# 四类索引生成 prompt

将花括号内容替换为真实范围和输出路径。支持 skill 的 Agent 可使用 `$file-index`；未安装时将本目录提供给 Agent，并要求读取 `SKILL.md`。以下请求只授权创建索引。所有布局统一使用标题分类与单行列表：`- [标题](<./文件.md>) [字段:: 值] #标签 一句话说明`，不写表格源码或子属性列表。已有文件用已核对的相对 Markdown 链接；所有文件和图片目标都用尖括号并对路径做一次 URL 编码，不能把含空格路径裸写进圆括号，也不能用引号包路径。需要按知识页面组织时，主项可写 `[[页面]]` 或 `[[页面|显示名]]`。`#标签` 与同名 `[[页面]]` 打开同一目标，含空格的标签用 `#[[多词标签]]`，也可在属性值或说明中使用。知识名称由宿主解析，不将它猜成相对路径；点击缺失知识目标会建页，生成索引时不提前创建页面。

## 多列表格视图

> 使用 $file-index，为 `{Vault 内目录}` 的现有 Markdown 文件生成 `{输出目录}/资料.index.md`，设置 view: table。先盘点实际文件，用标题表示有依据的分类层级，每个文件写一条单行 Markdown 链接，同行用 `[主题:: 值]`、`[作者:: 值]`、`[日期:: 值]` 表示属性，说明直接写在该行末尾。未知属性省略或留空，在分类说明中交代字段来源。使用相对链接，验证目标存在且仍在 Vault 内，不改写源文件。

## 分组列表

> 使用 $file-index，为 `{Vault 内目录}` 生成 `{输出目录}/导航.index.md`，使用默认列表布局。按我已有的类别目录或文件内容中明确的主题，用二至六级标题组织分类；每个文件只写一条单行列表，主链接在前，必要属性写成 `[字段:: 值]`，标签用 `#主题/子主题`，末尾可加一句说明。标签和标题分类分别保留，不靠列表缩进表达层级。缺乏分类依据的文件放入明确的未分类标题，并说明原因；不从标签臆测状态，不移动原文件。

## 泳道看板

> 使用 $file-index，检查 `{Vault 内项目目录}`，生成 `{输出目录}/项目看板.index.md`。设置 view: board、group_by: 状态、lane_by: 项目。标题表达已有分类，每个文件一行：主链接后跟 `[状态:: 值] [项目:: 值] [负责人:: 值]`，说明直接写在该行末尾。状态和负责人只采用文件或我提供的信息，未知省略或留空，不根据文件存在推断进度；配置字段至少在条目中出现，可留空。所有字段使用两个英文冒号，不写子属性列表，同一行不重复字段。验证相对链接，只生成只读索引，不更改项目文件。

## 书籍封面网格

> 使用 $file-index，为 `{Vault 内读书目录}` 的真实书籍笔记生成 `{输出目录}/书架.index.md`，设置 view: gallery、group_by: 阅读状态。用标题表示有依据的主题分类；每本书只写一条单行列表，书名链接在最前，后接 `[作者:: 值] [阅读状态:: 值]`、已有标签和 `[封面:: ![书籍封面](<./covers/book.png>)]`。所有文件和图片目标都用尖括号并对路径做一次 URL 编码，例如空格写成 `%20`；不要用引号包路径。作者、主题和阅读状态来自笔记，未知留空；仅引用确认属于该书的现有 Vault 内 PNG、JPEG、WebP、GIF 封面，缺图省略，不下载、不虚构书目、不修改笔记。不要写表格或多行属性，解码一次后检查所有链接和封面目标再交付。

## 在任一布局中使用知识页面

> 在上述索引中保留标题分类和单行条目，把我明确指定的知识页面作为 `[[页面|显示名]]` 主项；其余文件保留已核对的相对链接。主题用 `#主题`，含空格时用 `#[[多词主题]]`；关联概念可以在 `[关联:: [[页面]]]` 或行尾说明中记录。标签与同名 WikiLink 都应指向宿主中的同一页面，不从标签推断文件路径或状态。核对已存在的页面名称；如我明确要求保留尚不存在的概念，交付时说明点击会创建目标页面，但本次只生成索引。

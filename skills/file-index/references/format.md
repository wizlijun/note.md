# `.index.md` 格式 V1

文件名以 `.index.md` 结尾，例如 `阅读.index.md`。用标题表达分类层级，每个文件一条单行列表，属性写在该行内。没有 frontmatter 时默认分组列表，无需 `type: index`。四种布局共享同一份内容，`table` 仅表示显示布局，不需要表格标记。

## 内容结构

```markdown
# 文件目录

说明这一批文件的范围与字段来源。

## 工作

工作资料的分类说明。

### 查看器

- [需求清单](./需求清单.md) [状态:: 待处理] #主题/需求 整理文件导航需求
- [设计方案](./设计方案.md) [状态:: 进行中] [作者:: A B] #主题/设计

## 兴趣

### 个人阅读

- [蓝色之书](./蓝色之书.md) [作者:: 演示作者] [封面:: ![蓝色封面](./covers/blue-book.png)] #阅读
```

以上路径用于解释语法；可直接打开的演示在 `../assets/`。

### 标题与归属

- `#` 为页面标题，省略时使用文件名。`##` 至 `######` 为分类层级；条目属于它上方最近的分类标题。
- 标题跳级时挂在最近的更浅标题下，不补造空分类。例如 `## 工作` 后接 `#### 查看器`，仍属于“工作 / 查看器”；出现新的 `## 兴趣` 时，旧的下级分类全部结束。
- 普通段落和引用是当前标题的说明，不是上一文件的续行；可以出现在该分类的文件列表前后。空行不改变分类。
- 文件列表不靠缩进表达层级。增减空格或 tab 不改变条目归属，规范输出统一顶格写 `-`。列表符号也支持 `*`、`+`、`1.` 和 `1)`。
- 同名标题分别保留，不因文字相同而合并。空分类可保留标题与说明，搜索时只展示匹配条目及其祖先分类。

### 文件与行内属性

- 每个文件恰好一行，列表符号后的第一个内容必须是主链接：标准 Markdown 文件链接 `- [标题](./文件.md)`，或知识页面链接 `- [[页面]]`、`- [[页面|显示名]]`、`- #标签`。后面可按任意顺序写属性、标签和说明。
- 属性使用 `[字段:: 值]`，分隔符为两个英文冒号。例如 `[状态:: 进行中] [作者:: A B]`。字段名用普通文本，值可含空格、强调、行内代码、Markdown 链接、知识链接、标签或图片。
- 字段可省略或留空，顺序不用对齐。查看器按首次出现顺序取字段并集，缺少的字段补空；同一文件行内重复字段会回退 Markdown，避免猜测覆盖。
- `文件`、`标签`、`说明` 是查看器生成的保留字段，不能写成行内属性。主链接生成“文件”；标签生成“标签”；剩余普通尾文生成“说明”，尾文中的 Markdown 链接仍可打开。
- 按整行书写顺序遇到的第一张图片作为封面，也可出现在尾文中。推荐明确写为 `[封面:: ![封面](<./covers/book.png>)]`。
- 不写下一行的 `- 状态：进行中` 或其他子属性列表，不用表格、多行续文、逐项 YAML、代码围栏或 HTML 承载索引条目。

`[字段:: 值]` 借鉴 Obsidian 社区 Dataview 的行内字段写法，并非 Obsidian 核心或 Notion 原生语法。本格式只采用单行的方括号字段，字段值按可显示的 Markdown 内容读取；不运行 Dataview 查询、表达式或类型推断，也不支持无括号的 `字段:: 值`。设计依据见 [参考与取舍](design-notes.md)。

### 标签与知识链接

`#阅读` 与 `[[阅读]]` 具有相同的知识页面导航功能，都交给宿主解析并打开“阅读”。`#主题/设计` 与 `[[主题/设计]]` 也打开同一目标。标签显示保留 `#`，知识链接可用 `[[目标页面|显示名]]` 设置别名；别名只改变显示，不改变目标。

单词标签如 `#阅读`、`#主题/设计` 不含空格，可含字母、汉字、数字、下划线、连字符和 `/`，不能只有数字；含空格的标签写成 `#[[产品 设计]]`。标签字段比较时忽略大小写。转义文本、行内代码及普通 Markdown 链接或图片内部的标识保留为文本，不另行解释成知识链接。

```markdown
## 工作
- [[设计方案|方案]] [关联:: [[需求清单]]] #主题/设计 参考 [[设计方法]]
- [会议记录](./会议.md) [主题:: #[[产品 设计]]] #阅读
```

知识链接和标签都可出现在主项、属性值及说明中。行尾属性以外的标签还会汇入“标签”字段；属性值内的标签保留在对应属性内。

标签同时提供导航和标签字段，不推断状态、项目或标题分类；需要状态时明确写 `[状态:: 进行中]`。按“标签”分组时，使用该条目的整组标签组合，忽略大小写与标签顺序，不把一个文件拆成多条卡片。标题分类与标签各自保留，`#主题/设计` 不会自动创建“主题 / 设计”标题。在 Obsidian 中正文标签也属于整份笔记，本查看器将每行标签关联到对应索引条目，这是显示层的约定。

## 可选配置

```yaml
---
view: board
group_by: 状态
lane_by: 项目
---
```

- `view`：`list`、`table`、`board` 或 `gallery`，省略时为 `list`。
- `group_by`：确切字段名；省略时使用标题分类。没有分类的条目直接列出；看板中显示为“未分类”。
- `lane_by`：看板纵向泳道的确切字段名；省略时只有一个泳道。

普通 frontmatter 元数据可以共存；这里的配置作用于整份索引。用 YAML 字符串表达配置，不要写成数组。看板横向列使用 `group_by`，纵向泳道使用 `lane_by`；工具栏中的临时布局、分组与泳道选择不会回写文件。

## 链接与封面

标准 Markdown 链接和图片地址相对索引文件解析，也可用 `../` 指向 Vault 内其他目录。目标规范化后必须仍在同一 Vault 内；不使用网络 URL、脚本 URL、系统绝对路径或越界路径。生成器统一输出尖括号目的地，并对路径做恰好一次 URL 编码，例如 `[会议记录](<./会议%20记录.md>)`、`![封面](<./Life%20in%20Three%20Dimensions/cover.jpg>)`。尖括号提供 Markdown 目标边界，URL 编码避免不同渲染器对空格和标点的差异；引号仅表示可选标题，不用于包路径。生成后将目标解码一次，再按真实路径核对。

知识页面链接按逻辑名称交给宿主的全局页面索引解析，使用与内置笔记的 `#标签` / `[[页面]]` 相同的打开规则。名称不是相对路径，`主题/设计` 等名称由宿主统一处理文件名；插件不会把 `/` 直接拼成子目录。已有目标直接打开；目标不存在时，用户点击会由宿主按配置创建 Wiki 页面，受支持的日期名称使用 Daily Note 规则。加载和搜索索引不会创建页面。两种知识链接都参与宿主的反向链接，目标页面可反查 `.index.md` 中的来源条目；来源摘要只读，修改仍回到原索引。

本格式支持上述简单知识页面和别名，不实现 `[[页面#标题]]` 的标题定位、嵌套 WikiLinks、`![[嵌入]]` 或 Notion `@页面` 提及；不承诺完整 Obsidian 兼容。

封面仅支持 Vault 内 PNG、JPEG、WebP、GIF，不引用远程图片或 SVG。无图时省略封面属性即可；坏图显示占位及提示，不影响其他条目。查看器不下载图片、不改索引与原文件、不支持拖拽修改看板状态；点击缺失知识链接时的宿主建页行为如上。最低宿主版本为 `6.910.1`。

## 四种布局

- `list`：默认按标题分类层级展示，适合按主题导航；也可用 `group_by` 改按字段分组。
- `table`：将每行属性显示为多列表格，适合并排比较；写明 `view: table`。
- `board`：用 `group_by` 设置横向列，需要二维视图时加 `lane_by`，适合状态 × 项目。
- `gallery`：显示本地封面和元数据，适合书籍、画册、带封面的资料。

切换布局无需复制数据。看板横向分组数乘以纵向泳道数超过 400 时，会提示先搜索缩小范围或选择其他字段；原始数据仍完整保留。

## 校验与回退

容错处理列表缩进、标题跳级、空行、字段顺序和缺失字段，不猜测有歧义的属性。未知 `view`、不存在的配置字段、重复或保留字段、损坏的行内属性、没有行首主链接的列表条目，以及旧子属性列表或表格等不支持的结构会整体回退 Markdown，不静默丢行。生成后逐一检查真实链接；若 Agent 环境可以使用项目解析器，运行 `parseIndex(content, uri)` 确认返回有效文档。

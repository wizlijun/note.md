# `.index.md` 格式 V1

文件名以 `.index.md` 结尾，例如 `阅读.index.md`。内容使用标准 Markdown 标题、段落和 GFM 表格；没有 frontmatter 时默认表格布局，无需 `type: index`。

## 可选配置

```yaml
---
view: board
group_by: 状态
lane_by: 项目
---
```

| 字段 | 含义 | 省略时 |
| --- | --- | --- |
| `view` | `table`、`list`、`board` 或 `gallery` | `table` |
| `group_by` | 要分组的确切表头名，区分列名中的文字 | 按二级标题分组；无标题则“未分组” |
| `lane_by` | 看板纵向泳道的确切表头名 | 单泳道 |

普通 frontmatter 元数据可共存。用 YAML 字符串表达上述配置，不要将列名写成数组。看板横向列使用 `group_by`，纵向泳道使用 `lane_by`；两个字段应按实际浏览目的选择。工具栏中的临时布局和分组选择不会回写配置。

## 内容结构

```markdown
# 文件目录

说明这一批文件的范围与字段来源。

## 查看器

| 文件 | 状态 | 项目 |
| --- | --- | --- |
| [需求清单](./需求清单.md) | 待处理 | 查看器 |

## 宿主

| 文件 | 状态 | 项目 |
| --- | --- | --- |
| [设计方案](./设计方案.md) | 进行中 | 宿主 |
```

以上路径仅用于解释语法；实际可打开的演示在 `../assets/`。

- 一级标题为页面标题，省略时使用文件名。段落和引用作为说明展示。
- 二级标题划分分节；可使用一个或多个表格，各表的列名和顺序必须一致。
- 表头必须非空且唯一。至少有一张表格；只有表头和分隔行的空表格有效。
- 第一列每行恰好一个标准 Markdown 文件链接，例如 `[设计方案](./设计方案.md)`。列名可以是“文件”“书名”等，主链接外不放其他内容。
- 其余列自由定义，未知值保留空单元格，不编造数据。全部布局保留可读字段。
- 单元格可用普通文本、强调、行内代码、普通 Markdown 链接和图片。不要使用 HTML、列表、代码围栏、嵌套表格等结构承载索引数据；原始 HTML 不会执行。
- 每行按列顺序遇到的第一张图片用作封面，例如 `![演示书封面](./covers/blue-book.png)`。

## 链接与封面

链接和图片地址相对索引文件解析，也可用 `../` 指向 Vault 内其他目录。目标规范化后必须仍在同一 Vault 内；不使用网络 URL、脚本 URL、系统绝对路径或越界路径。文件名含空格时可用标准 Markdown 尖括号目的地，例如 `[会议记录](<./会议 记录.md>)`；生成后按真实路径核对。

封面仅支持 Vault 内 PNG、JPEG、WebP、GIF，不引用远程封面或 SVG。无图时留空即可；损坏或无法读取的图片显示占位及提示，不影响其他行。点击文件链接打开原文件；查看器不下载图片、不改原文件、不支持拖拽修改看板状态。

## 四种布局

| 布局 | 数据写法 | 适用场景 |
| --- | --- | --- |
| `table` | 一张多列表格，可省略配置 | 对比多个属性、批量浏览 |
| `list` | 同一表格；指定 `group_by` 或使用二级标题分节 | 按主题、类别导航 |
| `board` | 指定 `group_by`，需要二维视图时加 `lane_by` | 状态 × 项目、阶段 × 负责人 |
| `gallery` | 同一表格，封面列放本地图片 | 书籍、画册、带封面的资料 |

布局只是同一批表格数据的显示方式，切换布局无需复制内容或定义四份数据。

看板的横向分组数乘以纵向泳道数超过 400 时，会提示先搜索缩小范围或选择其他分组字段，避免生成难以浏览的巨大矩阵；原始数据仍完整保留。

## 校验与回退

未知 `view`、不存在的配置列、重复或不一致的表头、损坏表格、缺少主文件链接以及不支持的结构都会令查看器整体回退 Markdown，不静默跳过错误行。生成前核对模板，生成后检查每行与每条实际链接；如果 Agent 环境可以使用项目解析器，再运行 `parseIndex(content, uri)` 确认返回有效文档。

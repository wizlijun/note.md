# Mermaid 图表背景跟随渲染框主题

## 验收范围

用户最终明确要求“与对应渲染框的背景色一致”“根据 theme 切换”。本次保留 SVG 的实色画布，以当前渲染容器背景填充，复制 PNG 同样保留该背景。最初的透明画布/透明 PNG 方案已撤回，不作为本次验收结果。

Pele 原先固定使用浅色 `#ffffff`、深色 `#1e1e1e`，预览框另有基于系统 Canvas 的混合底色，两者均无法反映自定义纸张主题。现在预览框透出编辑器背景；响应式渲染接口传递实际 preview DOM，上溯解析透明层和已知不透明祖先的 RGB 背景，必要时合成半透明层。每次渲染重新取色，背景亮度决定无显式主题变量时的明暗默认值，正文颜色有足够对比度时用于文字及连线。

CORE 仅新增可选的响应式容器上下文及对子树 `data-theme` 的观察，覆盖编辑器局部主题切换；不观察样式或子节点变更，避免 SVG 更新触发自身重绘。旧 Mermaid 调用参数及默认配色保持原约定，复制图片流程未改。分享的独立渲染模块仅接收颜色与宽度，DOM 不跨模块接口传递。

## 生产浏览器验收

Chromium 140 加载本次 `dist` 的分享编辑器和 Pele 模块，核对 JS/CSS/渲染模块的 manifest SHA256 与 SRI。使用真实 CORE NodeViews 挂载现有 50 图例文档，不替换 NodeView 或主题通知链路。

- HTML 始终保持 `data-theme="light"`，只切换编辑器 host 的 `data-theme`：mint → parchment → evening → mint，验证局部主题通知自动重绘。
- 目标背景分别为 `rgb(232, 240, 234)`、`rgb(244, 238, 226)`、`rgb(30, 32, 36)`。每个状态检查 1200 和 390 像素视口，合计 400 个图表状态，SVG 背景变量、100% 画布填充、实际编辑器底色及可读文字颜色全部吻合，预览框本身透明。所有图表保留文字标签。
- 每种主题选取时序图、类图、饼图和象限图，共 12 次调用生产桌面适配器并传入真实 preview；背景均正确。
- 同 12 个图表触发实际 NodeView 复制按钮，捕获 PNG ClipboardItem 后解码检查像素，左上角 RGBA 精确等于主题 RGB 加 255 alpha；背景像素与图形像素均存在。人工查看浅色、深色截图及饼图 PNG，文字可读，无白底或黑块。
- 原 Markdown 提交内容保持不变；无页面异常、外部资源请求或 CSP 违规。

本地完整证据在 `tasks/mermaid-transparency-20261021/`：`browser-validation.json`、`verify-browser.mjs`、12 张 `nodeview-*.png`、12 张 `clipboard-*.png`、各测试及构建日志、`installed-core-dist.json` 和 `core-copy/context-verification.json`。该目录不纳入版本控制。

## 边界及交付

背景解析覆盖普通实色 RGB 及其透明叠层；没有已知不透明祖先，或背景为无法解析的颜色格式时，保留安全明暗默认值。渐变、图片背景及同一主题 ID 下直接修改 CSS 的自动重绘不在此次验收范围内。浏览器使用等价的局部主题 CSS 验证生产链路，未声称经过 macOS 原生安装包验收。

# 宿主体积与插件归属审计（2026-11-08）

审计对象为实际已签名的旧 `v6.1107.4` 和新 `v6.1108.4`。新版本仍为草稿，Sumi 0.1.3 仅在 R2 暂存，尚未更新市场索引。本报告不代表已完成插件迁移或新版本发布。

## 实测体积

| 项目 | 旧 6.1107.4 | 新 6.1108.4 | 增量 |
|---|---:|---:|---:|
| DMG | 13,505,710 B | 14,446,675 B | 940,965 B |
| 更新归档 | 13,550,406 B | 14,519,026 B | 968,620 B |
| App 全部普通文件 | 20,554,941 B | 22,393,444 B | 1,838,503 B |
| 主程序 Mach-O | 20,341,056 B | 22,134,144 B | 1,793,088 B |

新包新增独立 Sumi 目录与许可证 **42,571 B**，没有字体本体；另有签名资源清单增长。旧 App 的独立 Resources 只有图标199,574 B和两份主题CSS共6,933 B。大量前端资源、Rust业务和依赖已经嵌入主程序，因此“Resources没有大文件”不能证明宿主没有插件负担。

[实际归档逐文件与 Mach-O section 对比](2026-11-08-host-plugin-footprint/actual-bundle-comparison.json)从两个原始归档读取，归档大小/SHA均对上原发布验收记录。主程序增加1,793,088 B不等于能从DMG减少同样大小；DMG压缩、链接优化和共享依赖使组件成本不可直接相加。本次没有做删减构建，不伪造各Rust模块的压缩占比。

## 旧 13.5 MB 中的归属

| 内容 | 已核实归属 | 迁移判断 |
|---|---|---|
| Power Mode GIF、特效配置/接入 | 明确插件专属；13张GIF源文件173,472 B；插件停用仅禁用功能，不移除随宿主构建的资源 | 优先将素材放插件，通过受限资源接口供宿主编辑器读取；特效挂载/输入事件留薄接口。173,472 B不是已证明的DMG减量。 |
| Habitat 知识快照/历史/冲突保护 | 宿主host.knowledge按插件ID限定；部分业务已在插件backend | 将业务职责下沉，宿主保留与索引/Vault提交一致的通用事务接口；共享分词库不一定可移除。 |
| Memory管理、CDR | Memory UI使用宿主业务；同一实现也供CLI、搜索、Git同步；CDR更接近通用CAS存储桥 | 可提取后台服务，不能只移走UI调用实现而破坏其他消费者。 |
| 位置服务 | pos-log业务已在独立插件；宿主提供CoreLocation/TCC接口 | 保留通用系统位置桥；不把系统Framework当随包定位引擎。 |
| Health Sync、Meetings | 业务后端已是独立插件 | 不是此次宿主瘦身的主要迁移对象。 |
| Editor Kit、KaTeX、Graphviz/Mermaid、分享编辑器 | 宿主正文、公式、图表、分享或多个插件共同消费 | 不归为单个插件的专属素材；可单独研究重复嵌入/可选下载，需保留宿主离线能力。 |
| 主题字体服务、CSS编译、搜索SQLite、分词 | 宿主自身功能与多个消费者共享 | 不应因某插件也使用就整库迁出；本轮Sumi没有新增整份SQLite。 |

分享编辑器四份独立资源在旧主程序中已完整恢复、按位置去重共 **725,327 B 的 Brotli 数据**。这属于可研究按需分发的宿主分享功能，不是单插件专属资源，也不是直接可扣除的DMG压缩大小。旧前端另含KaTeX字体，不能将“已移除Sumi字体”说成“整个宿主没有字体”。详见[旧版静态资源审计](2026-11-08-host-plugin-footprint/host-baseline-resource-audit.md)。

## 新增 Sumi 的合理拆分

设置与导航UI已经在9,765 B的插件包中，字体已经独立按需下载；但CRDT、持久化、同步、下载器和原生编辑集成目前仍编译进宿主。小插件包不代表插件的全部成本小。

现有平台支持带签名可执行后端的插件，可优先迁移Sumi网络同步、字体下载/缓存等后台工作。更深入迁移CRDT、逐行时间、投影和持久化，需要定义输入确认、组字、远端变更、崩溃恢复及退出排空协议。当前原生输入是同步事务，不能直接换成每字阻塞跨进程调用而声称性能不变。

宿主应保留通用原生编辑surface、Tab/焦点/剪贴板/系统权限桥。现有市场不是dylib加载器；新增动态库插件机制并非完成这次瘦身的必要前提。完整依据见[插件迁移边界](2026-11-08-host-plugin-footprint/plugin-extraction-feasibility.md)。

建议顺序：先移明确专属素材，再拆Sumi后台，最后评估Memory/Habitat服务边界。每步用相同工具链实际重建，同时报告宿主包、插件包与安装后合计；不预先承诺回到某个包体积。本报告只完成审计，尚未实现以上进一步迁移。

## Linux AMD64 构建环境重规划与最终通过

两次失败均保留完整日志与容器状态：attempt 1 在 `syn` build-script 链接时 `collect2` internal compiler error/segmentation fault（exit 4）；attempt 2 中原 syn 链接已成功，转在 `getrandom` build-script 的 cc 进程 SIGSEGV。容器 `OOMKilled=false`，未见产品源码诊断；第二次未见磁盘耗尽。该证据不能独立证明 GCC/QEMU 崩溃的完整底层根因。

独立小 C/Rust 探针将问题缩小至仿真编译进程环境。首轮显式 cc/QEMU 路径 60 次成功不足以证明修复；第二轮 200 次中仍失败 6 次，否证“cc wrapper 已解决”。同轮普通 binfmt 也失败 1/200。没有据此修改产品源码、Cargo lock 或最终链接选项。

采用与 Docker 29.2.1/commit `6bc6209b88a7a834c91f77d848e025c79e0227a1` 对应的 Moby 默认 seccomp，仅追加允许 `personality(262144)` 的精确规则。独立只读 diff 确认其他顶层字段相同、无删除 syscall 规则、仅此一条新增，不使用 `unconfined`。`setarch -R` 仅作用于本任务构建进程及子进程；父/子 personality 为 `00040000`，全局 ASLR 前后仍为 `2`，探针最终 ELF 为 DYN；最终包另外完成下面的 PIE 与正常 ASLR 验收。

窄 profile + 进程级 no-ASLR 探针 C/LLD 200/200、Rust 默认 LLD 60/60 通过。attempt 3 保持同一冻结 host/CORE、原 GCC 12.2/LLD 23.1.1、原 release flags，优化 Rust 编译 30m43s 后成功。原包布局/ELF/真实 payload 门禁均过；独立 Arch runtime 的 parent personality `00000000`、全局 ASLR `2`，最终 ELF DYN/FLAGS_1 NOW PIE，ldd -r 与 CLI 通过。Omarchy 包随后在独立 Arch 容器完成首次安装验收；这仍不是桌面实机通过。

证据：`linux-amd64-attempt1-failure.json`、`linux-amd64-attempt2-failure.json`、两轮 `amd64-linker-probe*/exit-codes.txt`、`linux-amd64-environment-replan.json`、`amd64-aslr-probe/`。默认 profile SHA256 `01536f1d1df938ae611eba20d6349e0de7a99b6ecdee1549427a0b01b8301e28`；窄 profile `8bae1aeff39302a790399c1ab37b467ab3c4390ce1cccf44c755167a60ad8de4`。

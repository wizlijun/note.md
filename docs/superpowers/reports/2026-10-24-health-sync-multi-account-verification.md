# Health Sync 0.1.2 多账号与 API 历史导入验证

## 实现范围

Garmin、Oura 各可保存多个账号，只有一个当前账号供默认增量采集。第一个连接自动成为当前，后续新增不会切换；历史入口选择任意已连接账号和日期范围，不改变当前账号。断开仅删除所选凭据，保留账号名称和历史。

凭据继续使用 macOS Keychain，每账号独立授权 epoch；默认采集额外检查当前账号 epoch，显式历史任务只检查其所选账号。Oura 新授权按本次 authorization_id 确认完成，可取消等待，过期回调不能重新启用账号。失败或取消新增授权不改变原当前账号。

schema 3 按账号保存覆盖、附件与记录身份；同日同集合的不同账号成员不会互相替换。旧 schema 2 只按可核验旧身份迁移，无身份时停止覆盖并保留原档。Apple 重导入保留各厂商账号。查询可用 `--account` 过滤，摘要和覆盖明细区分账号。

历史任务使用独立账号/日期范围游标，完成后不回绕。普通采集首次默认最近 14 天，已有进度继续；原单账号游标只在已验证旧身份及原授权 generation 均匹配时继承，新游标优先，预览不迁移游标。GUI 不强行覆盖此范围，保留 CLI 的 since/until 续传语义。

## 边界

Garmin 官方导出 ZIP 的本地导入等待用户取得真实样本；按已有发布请求，本轮先发布多账号和 API 历史能力供真机测试，界面没有不可用 ZIP 按钮，README/changelog 明确尚未包含。后续需适配 JSON/FIT 和原文件保留、重复导入及账号归属，不能将保存附件称为完成结构化解析。

本轮未安装到用户设备，未操作真实健康 Vault；未完成原生 Keychain 弹窗、WebView 人工点击、Intel 真机或多账号真实 API 历史全量验收。此前真实 Apple 导出和中国区 Garmin 只读接口的验证分别见本目录对应报告，不能代替本轮这些实机项目。

# Rich Backspace 边界删除失效

用户确认 Rich 模式，未提供具体原文；本机安装版为 6.1104.2。以下为已稳定复现并修复的范围，不推断覆盖用户所有可能输入。

## 原因与修复

实际 File Editor 的 DOM keydown 可复现：`甲 乙` 在末尾按 Backspace，事件已被 preventDefault，正文仍为 `甲 乙`。标题和列表中同样出现。`前 **乙**`、斜体、删除线、高亮和行内代码的最后一个字也会失败。无此边界的普通中英文基线正常。

核心原文保真层把上述操作走成直接删除 Markdown 字符：留下行尾空白或空的格式包装。Markdown 再解析会吞掉空白或将空包装当成文字，与预期 ProseMirror 文档不同，于是返回 `semantic-mismatch`。宿主 FileController 拒绝事务，键盘默认动作又已取消，表现为退格没有反应。

内核提交 `dfda8e4` 在单次候选解析前选择既有 inline recipe，按实际删除范围编码新暴露的边界空白，并移除已空的格式包装。继续保留严格语义校验、既有实体拼写、容器前缀和未修改原文；不整篇重序列化。长段删除采用每正文的删除坐标边界和预计算空白边界，避免按每个空格重复遍历所有已删字符。

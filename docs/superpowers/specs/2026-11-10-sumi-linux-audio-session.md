# Linux 插件音频会话传递

## 问题与证据

Sumi 的 Linux 音效后端通过默认 PulseAudio 服务连接 PipeWire Pulse。宿主启动插件时调用 `env_clear()`，现有 Unix 白名单未保留 `XDG_RUNTIME_DIR`，导致插件无法定位当前用户的音频服务。

在实际安装的 v6.1110.6 中，宿主有该变量，Sumi 子进程没有。隔离运行 `pactl info`：仅继承现有白名单时连接被拒绝；只补回 `XDG_RUNTIME_DIR` 即连接成功。未修改用户音频设置或正文。

## 范围

- 仅 Linux 插件环境白名单新增 `XDG_RUNTIME_DIR`，值来自宿主已有环境。
- 保留 Windows 和其他 Unix 平台的既有白名单；不继承整个环境，不增加 token、密码或其他音频配置变量。
- 不修改音效超时、焦点、队列、资源、协议或用户持久化偏好。

## 验收

通过生产 `PluginProcess::spawn` 的真实子进程回归：独立测试进程携带临时运行目录和伪秘密变量，插件必须收到完整运行目录，但不能收到秘密变量或测试控制标记。测试在修复前失败，修复后通过；不改变测试运行器的全局环境，不连接音频服务、不播放声音。

运行宿主 `cargo check --locked --lib`。正式安装包的音频流与实际播放由发布验收另行验证，本源码回归不替代正式包验收。

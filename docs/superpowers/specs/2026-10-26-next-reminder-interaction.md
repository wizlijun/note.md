# NEXT 卡片与提醒交互

日期：2026-10-26。基于 [Task / Reminder 协议](2026-10-26-task-reminder-protocol.md)。状态：源码实现并通过下列验收，未发布或安装。

## 交互决策

任务状态与提醒控制各用一个入口。卡片保留“完成”和原来的七项安放菜单；Task 卡片增加铃铛文字入口，显示自动提醒、暂停至某时、提醒已关闭或已有关闭记录。Idea 没有稳定的 Task 提醒身份，不显示虚假的提醒开关。

点击铃铛打开快捷菜单：

- 自动提醒时：暂停 1 小时、暂停至明早 9 点、关闭提醒、更多…。
- 已暂停时：增加恢复自动提醒。
- 已关闭提醒时：恢复自动提醒、更多…。
- 已有独立关闭记录或读取异常时：只查看详情，不提供会覆盖既有证据的恢复动作。

“更多…”打开提醒详情，分别显示任务截止日期和提醒状态。用户可选择自动提醒或关闭提醒，也可填写自定义暂停截止时间。时间字段明确展示当前设备的 IANA 时区；写入时转换为带明确 offset 的秒精度时刻。过期时间、无效日期和 DST 歧义或不存在的本地时刻不能保存。

这是任务级的**暂停提醒**，不是某条 Delivery 的 snooze。暂停到期只恢复现有规则筛选，不保证在该时刻立即推送，不改 Task 的截止日期。尚未接入的重复规则、外部日历同步和投递回执不提供可操作控件。

安放“更多…”和点击标题后的编辑界面都有“管理提醒”入口。进入提醒详情时保留原表单及草稿，底层弹窗临时 inert 并暂停键盘处理；返回后继续编辑。提醒保存独立于任务元数据保存，取消底层编辑不会撤销已保存的提醒设置。

已结束泳道采用总称“已结束”；卡片按真实出口显示“已完成、已停止、已转移、已压缩”。已结束 Task 显示“不再提醒”，提醒详情只读。完成仍走原生命周期写入和成功礼花；重开不会清除独立静音偏好。

## 持久化与推送一致性

NEXT 与 Vault 推送器共同读取每个 Task 的独立文件：

```text
stat/task-reminders/<lowercase-task-uuid>.json
```

```json
{
  "version": 1,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "policy": "enabled",
  "updated_at": "2026-10-26T02:00:00Z",
  "paused_until": "2026-10-27T01:00:00Z"
}
```

- 缺文件表示没有额外抑制，仍按现有推送规则筛选；不是已经安排提醒。
- `policy=muted` 表示任务级关闭，不允许同时有 paused_until。
- `policy=enabled` 且 paused_until 在未来表示暂时抑制；到期自动失效。恢复时写 enabled 并省略 paused_until。
- version、身份、字段、日期和 JSON 重复键严格校验；未知或损坏记录禁止自动放行。UI 显示错误并禁止覆盖。
- Task 源文件、NEXT 账本和 `stat/closed-reminders.json` 不用于保存此偏好，也不由提醒开关修改。旧关闭记录是独立抑制，恢复不会删除它。
- 此偏好存储是协议的具体本地适配，不是完整交换快照。policy 对应协议任务级静音；paused_until 是额外的资格条件，不冒充 Reminder.trigger 或 Delivery 回执。

保存前重新读取来源并验证 Task UUID，再比较当前偏好与打开时的原始快照。保存后逐字回读验证；成功后刷新失败单独报告，不把已成功的写入误报为失败。本窗口复用 store.saving 串行写入，每个 Task 单独文件，避免覆盖其他卡片。

现有 host.vault.write 没有原子 CAS；写前比较与写后验证不能保证跨设备同一个 Task 并发安全，也不是操作日志。本轮不宣称实现了完整协议命令层的原子性。真实推送前仍须重读权威来源，文件暂时不可读则阻止发送。后续需要跨设备强一致时，应先补宿主原子写入接口。

Python `reminder_gate()` 在候选生成、发送前复核和已有 bot 消息检查中共用同一过滤判断。新静音/暂停与旧关闭记录、NEXT closed/unsupported 是叠加关系。已有精确关联的 bot 消息进入撤下计划；未关联消息和非 bot 消息不因这个开关被撤下。

暂停判断使用明确的当前时刻 `--now`（缺省 UTC 当前时间），与原有日期筛选参数 `--as-of` 分开。脚本仍只生成计划，没有网络 I/O；UI 不显示“已撤屏”，说明由下一次推送同步处理。

## 验收范围

- 数据层：按 UUID 隔离、旧记录兼容、同名任务、坏文件、旧快照、写失败和回读失败。
- 交互层：菜单键盘与全局 hover、暂停/关闭/恢复、保存失败保留、详情焦点与底层草稿、已结束出口准确显示。
- 链路：TS/Python 共用无私人数据 fixture；临发送再次读偏好，恢复不覆盖旧关闭或生命周期；暂停到期与非 bot 消息保护。
- 时间：UTC/offset 秒精度，日期合法性，夏令时一小时及半小时变化，跨年“明早 9 点”。
- 实机使用内存 Vault fixture，不写真实任务、偏好、账本或推送渠道。发布与安装另行执行。

验收结果：前端 413 项测试、Python 49 项测试、svelte-check 与生产构建通过。38 个 TS/Python 共享样例一致；实际 TS saveTaskReminder 与 UI 时间解析器生成的关闭、恢复、暂停数据也由 Python loader/filter 回读通过（含暂停结束的精确边界）。独立复核确认原时间秒数/offset保留、到期即时重新投影和当前源文本闭合匹配。

实机在独立内存 Vault 页验证了卡片提醒入口、快捷菜单、鼠标蓝底白字 hover、暂停保存反馈与日期显示。关闭/恢复、详细表单草稿、只读状态及错误处理通过渲染和数据测试；测试页在其余手工验收完成前被外部关闭，不将这些项目记作完整实机验收。未调用真实推送或撤屏接口。

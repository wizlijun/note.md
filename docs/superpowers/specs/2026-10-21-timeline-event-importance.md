# Timeline 按事件证据显示重要程度与反常标识

状态：待实现规格。本轮只交付本文，不实现、安装或发布 note.md 代码。

## 目标与边界

Timeline 生成流程结合卡片引用的原文判断重要程度。note.md 查看器读取结果，用颜色和文字区分重要、普通和待判断。鲁迅日记等消费者据此选材，事件数量随当天实际内容变化。

重要程度和反常程度是两个独立判断。普通事件也可能反常；重要事件不一定反常。来源字数和占用时间是辅助信号，不能直接等同于重要程度。

本规格涉及数据契约、查看器展示、兼容和验收。原文核对由生成流程负责；查看器不扫描原文、不推断身份、不自动打分，不改写源文件。

## 重要程度的判断

每件事件只过一个重要性阈值：是否改变后续安排、形成值得追踪的结果，或构成值得记住的生活经历。

| 值 | 显示 | 适用情况 |
| --- | --- | --- |
| `high` | 重要 | 至少符合一项阈值，且有可定位的原文证据 |
| `normal` | 普通 | 已核对原文，属于例行活动、琐碎步骤或无新结果的重复记录 |
| `unknown` | 待判断 | 原文不足、关系不明、尚未核对，或旧文档未标注 |

综合评估同时考虑以下信息，给出一句可复核的理由：

- 后果与结果：决定、承诺、期限、交付、健康、家庭、钱物或关系变化。
- 与本人关系：亲自参与或承担后果，间接相关，纯背景，或者不清楚。
- 事件规模：该事件相关原文的文字数，以及有证据支持的实际耗时。
- 非例行经历：出行、探访、重要会面等，即使文字很短也可重要。

不设每日名额、固定高等级占比或最低条数。不能按来源类型固定排序，不能因为会议长、聊天多、文档长就评为重要。短促的住院通知可能重要，长时间例行测试可能普通。与本人相关的判断只用明确来源，不把推断的说话人身份当事实。

`source_chars` 统计该事件实际引用且去重的原文文字数，不是整个共享文件的长度；它只表示材料规模。`duration_minutes` 只记录可证实的实际耗时；稀疏日志的首末跨度不等于持续投入时间，无法证实时为 `null`。两项未知值不得写成 `0`。

## 持久化格式

每个事件行追加稳定的本文件事件 ID。ID 不因调整行序、插入说明或改标题而重建。同一文件内唯一；跨日以文件路径和 ID 共同定位。

```markdown
---
type: Timeline
sources:
  - id: s01
    resource: ../ssot/example.md
event_metadata:
  e01:
    importance: high
    reason: 确认了交付日期，改变了后续安排。
    evidence:
      - source: s01
        locator: L12-L18
    signals:
      source_chars: 260
      duration_minutes: null
      owner_relation: direct
    anomaly:
      status: flagged
      reason: 原文说明此次交付比原计划提前。
      evidence:
        - source: s01
          locator: L16-L18
---

- 09:00–09:30 — 沟通：确认交付日期。 [来源](../ssot/example.md#L12) <!-- event:e01 -->
```

`event_metadata` 是按事件 ID 索引的映射。每个条目的必需字段：

| 字段 | 约束 |
| --- | --- |
| `importance` | 严格字符串枚举 `high`、`normal`、`unknown` |
| `reason` | 非空字符串，说明判断依据或无法判断的原因 |
| `evidence` | `{source, locator}` 数组；`high`、`normal` 至少一项；`unknown` 可为空 |
| `signals.source_chars` | 非负整数或 `null` |
| `signals.duration_minutes` | 有限非负数字或 `null` |
| `signals.owner_relation` | `direct`、`related`、`background`、`unknown` |

`anomaly` 是独立可选字段。省略表示尚未判断，不等于无反常。

| 字段 | 约束 |
| --- | --- |
| `status` | `flagged`（有依据的反常）、`none`（已核对未发现）、`unknown`（待判断） |
| `reason` | 非空字符串，说明反常依据或判断边界 |
| `evidence` | 与重要程度相同的证据格式；`flagged` 至少一项，其他状态可为空 |

反常需要明确依据，例如偏离已有计划、习惯或预期，发生罕见变化。不能仅因模型不熟悉某事就标反常。引用的基线与本次偏离均需有来源；没有基线时标 `unknown`。

所有事件 ID 匹配 `^[a-z][a-z0-9_-]*$`。`source` 必须回指当前 frontmatter 的 `sources[].id`。`locator` 为 `L正整数` 或 `L起始-L结束`，结束不得小于起始。数值不接受字符串、布尔值、NaN 或无穷。反常与重要程度的证据分别验证。

## 兼容与错误处理

旧文档未声明 `event_metadata` 时继续展示，未标注事件为 `unknown`；保留现有 `line-N` 内部回退 ID。带合法事件标记但没有元数据的条目也显示待判断。

一旦声明 `event_metadata`，所有事件行（含各级议题）必须有唯一标记及对应条目，所有映射条目也必须有事件行。重复 ID、孤立元数据、缺失映射、非法枚举、无效证据、空理由或非法数值使整份视图回退 Markdown，不可静默丢弃坏数据或显示部分日程。

事件标记必须在事件行末。剥离标记后才解析描述和链接，不在正文、来源按钮或可访问名称中显示注释。无元数据文档中的畸形事件标记同样应被拒绝；代码块内的示例不作为真实事件解析。

会议父卡片和每个子议题独立评估。父项重要不能传递给所有子项；子项重要也不强制父项重要。保留事件层级、时间和所有链接。

## 查看器展示

保留现有五类活动分类及其底色。重要程度通过独立色条和文字标签显示：重要用警告语义色，普通用信息语义色，待判断用中性色。用主题变量保证浅色和深色可读；不能只靠颜色识别。

卡片始终显示重要程度标签。`anomaly.status: flagged` 额外显示独立“反常”标识；`none` 不占用卡片空间；缺失或 `unknown` 不显示“正常”断言。紧凑和零时长卡片也需保证标签与点击区域可用。

详情展示每个事件自己的等级、判断理由、证据 ID 和行号。反常判断单独展示状态、理由和证据；缺失时说明尚未判断。可同时展示字数、耗时和本人关系，未知显示“未知”，不能补算为零。

分类图例与重要程度图例分开，避免把蓝色工作分类理解成普通等级。来源导航沿用现有机制。当前宿主如只能打开文件而不能定位行号，需明确保留该限制，不宣称已精确跳转。

## 下游日记选材

消费者默认保留 `high` 事件，可显式同时保留 `anomaly.status: flagged` 的事件。返回 `unknown` 事件作为待核对项，不能当成普通事件悄悄舍弃。

有子议题的会议父项用于结构展示，日记不把父项与同一内容的子项重复计数。重要父项存在独立事实时，生成端应将该事实单列为可回源子项。相同事件的多来源合并，同项目内不同重要事件分别保留。

鲁迅日记取消每日最多四件及全文一百二十字的硬上限；保留逐件简写和原文事实约束。自动选材只生成候选，写作仍需回源核实，不把判断理由扩写成未发生的事实。

## 验收要求

1. 解析：合法三档、独立反常组合、空未知信号、稳定 ID、链接剥离、嵌套议题均通过；插入说明后 ID 不变。
2. 校验：非法枚举、类型、数值、证据、ID、缺项、孤立项均使整份视图回退 Markdown；Python 工具与查看器共用等价样例。
3. 兼容：旧 Timeline 保持内容与链接，显示待判断；原文、Task、伴随大纲不被修改。
4. 界面：生产浏览器验收浅色、深色、390px 窄屏、短事件和重叠事件；标签不溢出，理由可见，分类与等级独立，键盘和辅助技术可读。
5. 父子：重要会议内普通、待判断议题保留各自等级；普通事件可反常；缺少反常字段不显示“无异常”。
6. 选材：用事件丰富、普通活动为主、短但重要、生活事件较多的日期对比旧新日记；重要事件不因条数或字数截断，待判断项可追踪，父子不重复。
7. 交付：完成定向测试、类型检查、生产构建及真实截图后才能宣称实现；另行授权部署。本文本身不证明插件已更新。

# HABITAT 概念建筑成长：可观测投入证据

## 范围与计划

- [x] 检查冻结快照的来源、引用、日期观察、项目意图和谱系。
- [x] 提供单一确定性派生函数，供全城、近期视图及详情复用。
- [x] 验证导入、重复、旧格式、冻结日期、版本重组与真实分布。

本轮仅前端派生，不修改提取器、快照、Git 历史、语义节点或关系。每栋建筑对应一个 keyword/concept/entity/project 节点；topic 聚合不再派生成概念建筑。楼层表示 Vault 中能回源的记录和投入，不代表事实正确、思想成熟、项目完成或人的能力。

## 接口

`deriveConceptGrowth(snapshot, { previous?, diff? })` 返回 `Map<nodeId, ConceptGrowthProfile>`。先对完整快照计算，再筛选近期可见节点；不用 attention.score、当前画布范围或邻居数量决定等级。同一快照的 stage/support 固定，切换对比对象不会改变楼层；previous/diff 只帮助判断本次版本对比中的真实重组。

Profile 包含 stage、level（0–5）、中文 label、state、support、reasons、limits。support 含去重来源组、含主动记录的来源组、已解析家族组数、导入组数、有可信日期的主动日/事件/跨度，以及项目依据。

## 来源与日期

可用来源中 verification=matched、非 metadata、非 knowledge 导入记录进入基础来源组。同 family 只计一组，无 family 时以 source ID 保守分组。来源组不称为独立证据；verified 仅表示家族解析状态。

高级建筑需要 role=attention、granularity=attention_sentence、authorship=human 的证据，表示经过明确用户/原生记录解析；旧提取器默认 human 的普通 context 不满足该条件。verification=imported 与 knowledge 来源只报告为背景，不能增加高层资格。

日期只取与节点实际 evidence 相连的 attentionObservation，须有合法日期、eventId、confidence≥.8、已知本人信号 agent_user/native_human 和可信 dateBasis。忽略未来、无效或未提供冻结观察日的日期。不取路径、mtime、墙上时钟或 attention 汇总数字补日期。观察日采用 meta.focus.asOf；旧快照可使用合法 generatedAt 日期。事件按 eventId、日按 YYYY-MM-DD 去重，跨度为首末日相差天数。多个同日事件不增加主动日或跨度。

这套日期是完整图中可观察的记录投入，可能比某词 attention 的局部概念语境计数更广：节点在一条实际原文中的引用，也可使用该原文为其他词保存的日期。不能将其解释为独立概念反思次数。

当前格式只保存有限窗口的日期观察。无日期的历史原文仍作为建筑基底，但不能证明长期跨度；日期淡出不表示遗忘。不会从用户临时选择的对比版本携带旧日期升级建筑。跨全部版本恢复稳定投入轨迹需要后续单独设计，不能在本轮界面比较中暗加状态。

## 六级规则

满足多个条件时取最高级；阈值是展示工程选择，不是心理学量表。

|级别|建筑|最低证据|
|---|---|---|
|0|茅草屋 hut|默认零散或导入背景|
|1|木屋 cottage|2 组非导入来源，或 1 组主动记录|
|2|住宅 house|3 组主动记录，或明确原生项目声明加 1 组主动记录|
|3|工作室 workshop|3 组主动记录、3 个主动日、跨度 7 天|
|4|楼宇 midrise|6 组主动记录、6 个主动日、跨度 14 天、8 个去重事件|
|5|摩天楼 tower|10 组主动记录、12 个主动日、跨度 21 天、16 个去重事件|

高塔另有明确项目路线：原生 `declared_project` 加 6 组主动记录、6 个主动日、跨度 14 天、12 个去重事件。`task_project_reference` 只表示任务提及，`imported_project_mention` 只表示导入提及，不享有项目声明路线。没有按项目名称或个人主题设置白名单。status=imported 的节点最多小屋，即使其他字段含糊也不将导入实体画成高楼。

## 活动与重组状态

- growth：冻结观察日前 7 天内有可定日主动记录。
- dormant：可用日期中的最后记录距冻结观察日超过 14 天。只是观察窗内没有新记录，不断言停止投入或遗忘。
- unassessed：没有可信日期，或距最后观察 8–14 天，不凭空判增长/休眠。
- rebuilding：仅在可比较同 Vault、scope、algorithm 的 before/after 与匹配 diff 中，存在该节点真实 primary membership 迁移，或新出现的 confirmed/user-confirmed merge/split/regroup lineage。算法迁移、改名、候选谱系、已有旧谱系均不画施工。

重组状态是版本间结构变化的表现，不能解释为此刻项目正在施工。

## 验证结果

11 项定向测试覆盖六级门槛、同日重复、来源族拷贝、导入/metadata、旧默认 human、真实项目声明与提及区别、未来/非法日期、冻结时钟、全图基底、节点排序、候选/确认重组、实际社区迁移、对比操作不改变等级，以及 topic 排除。

冻结 2026-10-02 的 14,273 来源快照实际分布（1,202 个概念节点）：茅草屋 78、小屋 540、住宅 529、工作坊 39、多层楼 14、高塔 2。两座高塔是 AI 与 Hemory，由一般持续记录条件进入，未因名称或导入项目身份升级。当前没有 confirmed lineage，因此不凭空出现施工状态。

仅本地审计包含真实节点细节；产品文档与测试不写私人原文路径。测试命令：`npx vitest run src/lib/concept-growth.test.ts`（在插件目录）。

## 建筑与街坊实现

关键词图每个节点对应一栋可拾取主体建筑及一个唯一地址，超过旧650栋预算的1,202词图也不聚合。大社区按最多12个地址分为物理街坊，所有街坊仍保留同一真实topicId；不新增语义社区。旧对象快照保持明确的聚合兼容。

等级复用Kenney离线GLB住宅、工作室、多层楼和两类摩天楼，加四款原创程序化茅草/原木建筑；门廊、门牌柱、围墙、植物、屋顶和台阶构成同一地址的附属物，不增加概念。模型按稳定id挑选同级变体；纵向比例修正限制在0.9–1.2倍，避免拉伸窗层。规划预留圆包络内包含所有附属物。

近期与近景显示逐栋概念标签，远景全城显示街坊；每个可見身份保留标记，文字碰撞折叠。选中概念的标签直接打开自己，不能再把它当整个社区的入口。概念标签显示建筑级别，活动/静置/重组以标记和详情解释；施工附属物仅由已核对版本重组驱动。

院路为不承载知识关系的步道；沿现有街坊边界寻找出口，并在密集街坊的楼间隙使用局部可见图找最短折线。每段检查预留建筑包络净空与凸地块边界，不穿建筑、不跨海。关系仍仅升级已有道路的宽度，不能把园路当新关系。

用户已暂停发布：全部工作、截图和验证在本地完成，不上传、不推送、不改版本。

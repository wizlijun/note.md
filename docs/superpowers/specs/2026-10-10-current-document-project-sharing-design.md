# 从当前文档创建分享项目：流程与生命周期重新设计

日期：2026-10-10。状态：待用户审阅；本轮为设计与诊断，尚未实现或发布修复。

本 spec 修订已发布 6.1010.2 的创建入口、项目身份、发布门禁和本机删除流程。继续沿用宿主内置功能、Sync/project_id 镜像、单 HTML 静态发布与现有轻量反馈接口，不增加服务或数据库。未修改的浏览器草稿、收件、人工审阅合同沿用原 spec。

## 1. 需求与已确认的决定

- 当前打开的 Markdown 可以直接创建为项目、分享为项目，无须先选择文件夹再选择入口。
- 默认以这篇文档所在文件夹为引用解析基准，原文档保持原位置。基准目录不等于自动分享整个目录。
- **用户已确认：每篇入口文档独立项目，同一目录可有多个项目和独立链接。** 同一入口重复操作恢复原项目，不重复创建或覆盖其他文档的项目。
- 创建但未发布的项目也要保存、再次打开和删除。
- 缺失引用必须说明实际未分享的内容，但不能使一篇可读取的文档永远无法分享。
- 删除项目是可执行的完整本机管理操作，与停止网页分享有明确区别。

## 2. 现场诊断，不以推测代替根因

只读检查真实应用状态，并以生产扫描函数、内存 DOM 和磁盘只读函数复现：

| 现象 | 证据与原因 |
| --- | --- |
| 无法发布 | 当前 `strategy.md` 引用的 5 张 `report-img/*.png` 在磁盘上不存在；scanProject 返回 5 条 missing，UI 将全部 missing 当作 blocking，发布按钮永久禁用，尚未进入快照或网络上传。分享服务地址和 API Key 已配置，未输出密钥。 |
| 无法删除 | UI 只有重绑、停止分享；Rust dispatcher 没有 delete。停止只清前端发布状态，Rust config.url 仍保留。 |
| 创建后不能可靠找回 | Rust 已保存项目绑定，但项目选择器只读成功准备发布后才写入的 projectShares 凭据表。现场项目尚无该表记录。 |
| 当前文档不成为入口 | initialize 恢复最近项目；当前文档只在手动选完根目录后用于猜测入口。 |
| 同目录不同文档互相覆盖 | open 按 sourceRoot 复用项目并改写 entry，与本次明确的入口文档身份冲突。 |
| Vault 根目录文档不支持 | source_root 拒绝 source == Vault，无法以这类文档的父目录为基准。 |
| 原目录丢失后无法管理 | binding 要求源目录存在，导致读取历史快照、冻结包、反馈和清理也依赖原件存在。 |

诊断见 `tasks/design/project-share-redesign-20261010/publish-diagnosis.md` 与 `lifecycle-diagnosis.md`。没有向生产服务发送发布或删除请求，未更改用户文档和应用数据。

## 3. 方案比较与选择

| 方案 | 结果 | 结论 |
| --- | --- | --- |
| 从当前文档创建项目，文件夹作引用基准 | 入口明确；同目录多项目独立；继续复用现有镜像和发布机制 | **采用** |
| 继续按文件夹创建唯一项目 | 实现改动较少，但 Downloads 等目录中的不同文档共享身份和链接 | 与用户确认不符 |
| 另建项目工作区，复制或搬运原件 | 引入新的编辑位置、迁移和同步生命周期 | 超出需求，不采用 |

最小模型仍是一个 project_id、一篇固定入口、一个源基准目录、一份批准文件集合、一套发布凭据。没有新的项目数据库、工作区系统或后台同步进程。

## 4. 创建与重新打开

### 4.1 从当前文档开始

既有“文件 → 分享项目…”打开分享窗口。窗口顶部展示捕获的当前文档名称和所在文件夹，提供：

- **创建项目**：必要时先保存当前文档，创建本机草稿；即刻加入项目列表，不联网。
- **分享为项目…**：执行同样的创建或恢复，再进入文件范围预览。仍需明确点击“发布分享”，不能在预览前自动上传。
- **选择其他文档…**：无当前 Markdown 时的补充入口；选择文件后自动以其父目录为基准，不再连续弹出目录和入口两个对话框。

捕获点击时的 tab ID，保存与创建始终针对这一个文档。富文本先 flush 再保存；未命名文档先“另存为”，取消不创建空项目；保存失败保持原状态并给出错误。其他 tab 的未保存文本不受影响。非 Markdown 当前页显示“选择 Markdown 文档”，不尝试转换。

打开窗口本身不自动新建记录。已有匹配入口时默认打开其项目，同时允许查看其他项目；返回“当前文档”后再创建或恢复。

### 4.2 身份与固定入口

- 后端从已保存文件的规范化路径得到 sourceRoot = parent、entry = filename。
- 新项目复用键为 **canonical(sourceRoot) + entry**，project_id 仍是随机 UUID；不同 entry 允许拥有相同 sourceRoot。创建前先按规范化入口文件路径匹配旧绑定；旧项目可能是 sourceRoot=/P、entry=docs/a.md，打开 /P/docs/a.md 时须复用旧 ID 和 /P 基准，不能按新父目录 /P/docs 另建副本。多个旧绑定命中同一实际入口时显式选择已有项目，不能静默选中或合并。
- 本轮入口固定。恢复项目使用 project_id，绝不调用会修改 entry 的旧 open；分享其他入口文档创建另一个项目。
- 同一入口显式重复创建时复用本机同一项目；同目录其他文件不会影响其 ID、URL、token、历史或反馈。
- 项目标题默认入口文档名，路径显示基准文件夹。暂不增加自定义名称、入口改名追踪或项目嵌套规则。
- 原件在 Vault 内外均支持。Vault 本身可以作为 sourceRoot；Vault 的上级仍不允许成为基准。Sync 子树、管理文件及保留目录不允许成为源。
- 当前文档是本项目的 Sync 镜像时，按本机 Sync record 定位已有项目和原入口，进入该项目；不从镜像再创建项目。只有其他设备镜像、无本机绑定时明确只读，不猜测源路径或接管。

后续更新保持固定入口和基准。目录移动仍通过显式重绑核验；同目录另一个不同入口项目不再阻止重绑，同一规范化入口仍拒绝重复绑定，包括根目录写法不同的旧绑定。入口文件改名不做自动追踪。

### 4.3 项目列表的唯一来源

宿主后端提供 projects，枚举本机 bindings 和对应配置；包括草稿、已发布、已停止、源不可用、删除中项目。单项损坏不能使整个列表不可用，应按 ID 展示需处理状态。

前端 projectShares 仅保存服务绑定、owner edit_token、协作 token 和 pending 原包，不再充当项目目录。凭据不写入 Vault 或 HTML。列表显示文档名、基准路径及状态；同目录文档容易区分。

已有草稿从 bindings 自动出现；旧项目保持原 ID、entry、目录、链接和快照，不按新规则重建。已有凭据但本机绑定缺失的记录作为“仅有分享记录”列出，仍可停止远端分享和移除残留记录，不捏造源绑定。

## 5. 分享范围与发布门禁

### 5.1 目录只提供引用基准

初次扫描从固定入口递归解析目录内真实存在的文档和资源，不读取或上传无引用的邻居文件。首次发布明确展示实际文件列表；复用现有勾选和私密文件排除规则。后续扫描发现的新文件默认不加入批准范围。

允许 Vault 根目录后，所有源读取入口统一拒绝 Sync 子树、`.notemd`、凭据、个人手记等保留内容；不能只在候选列表隐藏。read、snapshot、review/apply、Sync 绑定验证均使用同一源路径边界，软链按规范化目标校验。扫描候选目录时不因无关子目录不可读而阻断当前文档；需要读取的引用文件错误仍显式报告。

### 5.2 不完整引用与不可安全发布分开

| 情况 | 用户可见行为 | 发布门禁 |
| --- | --- | --- |
| 入口与批准文件均可读，缺少引用图片/附件 | “5 个资源不存在，将不包含在分享中”，列出引用来源和目标 | 警告，可发布已存在的内容 |
| 被引 Markdown 缺失、Wikilink 同名歧义 | 列出未包含的文档；修改链接后可重新扫描 | 警告，可发布；不擅自选择同名文件 |
| 相对引用越出基准目录、已主动排除文件、私密文件引用 | 显示“未包含”，不读入对应内容 | 警告，可发布批准内容 |
| 原文含本机绝对地址而即将原样公开 | 明确指出需修改的地址 | 阻断，避免公开本机路径 |
| 入口不可读/缺失、批准文件不可读或过大、安全校验失败、软链逃逸 | 显示具体文件和原因 | 阻断，不假装文件不存在 |
| 保存失败、源 hash 漂移、镜像冲突、总包超 25 MiB | 显示保存/扫描/镜像对照/减小范围等既有处理入口 | 阻断 |
| 服务未配置、鉴权失败、网络失败 | 配置入口或明确错误；未知结果保留原包重试 | 不显示成功 |

读取失败须提供稳定分类：NOT_FOUND、UNSAFE_PATH、UNREADABLE、TOO_LARGE 等，前端不能把任意异常都降级成 missing。入口缺失始终阻断。只对明确“被引目标不存在”降级；未知错误保守阻断并展示原因。

引用问题区同时显示“已包含 N 个文件”和“未包含 M 项引用”。真正阻断时在发布按钮旁显示原因。警告不禁用按钮，也不暗中上传其他位置的同名文件。已有 Viewer 的未共享链接/图片占位逻辑继续使用，不改变原件 Markdown、不保留失效的本机可点击链接。

### 5.3 发布闭环

沿用已确认的“保存批准文件 → 重新扫描 → 核验 hash/镜像 → 冻结快照和 HTML → 持久化身份/pending → POST /publish → 确认并记账”。只冻结实际读到并批准的文件；未包含引用不会进入 snapshot/镜像/包。

发布成功才显示阅读/协作链接；重发沿用这个项目的 URL。pending 时只能原包重试或停止待确认分享，不切换入口、重建 token 或清掉未知结果。同目录其他项目不受影响。

配置缺失时可直接打开宿主“分享”设置；返回后保留当前项目和勾选。错误保留“扫描/冻结/上传/确认”所属阶段及脱敏原因，不把所有失败都称为网络问题。沿用现有 HTTP 客户端和 Worker 合同，不新增发布协议。

## 6. 停止分享与删除项目

### 6.1 两个独立动作

- **停止分享…**：复用远端 DELETE，确认后同时清 Rust 配置及本机凭据记录的活动 URL/pending 状态；保留项目、镜像、快照、反馈和凭据，以后可重新发布。
- **删除项目…**：移除本机这个项目，并先撤回其可能存在的远端分享；原始文档及目录永不删除。

删除按钮放在可见的项目操作区，草稿和已停止项目也有此入口，不依赖入口/源目录仍可读取。确认文案列出入口、源目录、镜像目录，说明本机镜像、发布快照和已收反馈会移除，源文档保持原位。

这是“删除本机项目并撤回网页”的明确语义。沿用现有 Worker，不在本轮增加云端反馈物理擦除/定时 GC 接口；R2 既有历史收件原包仍保留，停止后新提交按原有分享状态拒绝。界面不宣称清空所有远端数据或收回已下载内容。

### 6.2 删除顺序与保护

1. 前端检查该项目镜像 tab：flush 后仍未保存则列出文件并停止，不自动丢弃或回写。原件 tab 和其他项目不自动保存或关闭。
2. 后端预检项目 ID、专属镜像边界和配置身份；核对该项目全部 Sync record 的镜像 hash，并检查未知/个人手记文件。存在漂移或非托管内容时阻止删除并给出路径，用户先另存或处理后重试。不能递归删除包含未知用户文件的目录。
3. 确认删除后、远端请求前，后端在排他边界内记录“删除中”，暂停此项目的新发布、应用反馈及镜像刷新；当前宿主仍有发布请求执行时先等待/拒绝删除，不与撤回交错。有已发布或 pending 身份时，再使用原服务及原凭据撤回；204/404 可继续。网络/鉴权/结果未知时保留本机项目、凭据和基线，允许重试或明确取消删除，不显示删除成功。未曾发布的草稿离线可删。
4. 远端确认后再次检查镜像 tab 缓冲区，在同一写入排他边界重新检查本机条件；只删除此 ID 的受管镜像目录、本机绑定、对应 Sync records 和精确匹配的镜像 metadata。关闭其干净镜像 tab；原件和其他项目的镜像保持不变。
5. 后端完成后移除此 ID 的发布身份、最近选择及 UI 项目项，刷新 Sync。删除是幂等的；中断后保留足以继续清理的 ID/凭据，不把半删除当完成。最后一步 Store 保存失败时，下次可继续移除仅有凭据记录。

原目录已经不存在不影响以上流程。镜像目录已经不存在可清理残留绑定和 records；镜像目录身份不明或安全路径校验失败则保留并报错。Vault/syncDir 已变时不得推测删除别处目录，须按受信绑定显式处理。删除中禁止该项目再写原件/镜像或发布。`sotvault-sync.json` 是整体 load-modify-save，所有修改者必须在共享锁内重新读取、校验绑定及写入，不能只给被删 ID 加锁，否则其他项目可能用旧 records 恢复它。删除持有该本机写入边界完成清理；冻结/回写和 Sync 刷新遵守相同边界。GUI 与独立 CLI runner 共用 app_data，故复用已有 fs2 对固定 sidecar 锁文件加跨进程排他锁，不能只用 Rust static Mutex，也不能锁被原子 rename 替换的 records 文件本体。临界区覆盖整表读取、路径/绑定/删除状态校验、文件写入及 records 保存；远端 HTTP 不持此锁。不建设通用事务框架。当前单实例主窗口的 busy 门禁串行化发布/停止/删除，删除标记在后端而非仅在组件；不为本轮新增多设备发布租约或云端事务，已结束但结果未知的远端请求和 KV 传播仍沿用既有非即时撤回边界。

删除本项目不得按 source_path 全量移除 records，因为同一原文件可能被其他项目或旧单篇 Sync 使用。project_id 不复用；删后再次创建同一入口得到新项目，不承诺旧协作草稿仍能提交或合入。

## 7. 最小代码与数据边界

继续使用一个 project_share 宿主命令入口。最少新增/调整：

| 操作 | 职责 |
| --- | --- |
| create(sourceFile) | 由已保存原文件推导父目录和固定入口，按二者复用或创建 UUID |
| projects | 列举本机项目及不可用/删除中状态，不依赖发布凭据或原件存在 |
| get(project_id) | 只恢复既有身份和配置，不改写入口 |
| stopped(project_id) | 清本机配置中的活动发布状态，与前端凭据记录对齐 |
| begin-delete / delete / cancel-delete(project_id) | 预检并保留删除状态、幂等清理或取消；delete 再校验，不依赖原件存在 |
| read 及内部源校验 | 区分缺失与读取/安全错误，统一保护 Vault/Sync 边界 |

把“受信绑定/镜像管理”与“源文件可读可写”校验分开。快照读取、冻结包恢复、取件、本地反馈与删除只要求前者；新内容扫描/冻结/回写才要求后者。现有 inbox/load_feedback/recover 含恢复写入副作用，源不可用时只读列举原包和现有决定，不执行回写或把未完成 intent 错改成已处理；源恢复后按原 hash 规则继续核对。没有 owner 凭据的已发布项目可以读本地，但不能静默删掉仍活动的链接。

存储沿用 app_data 的 bindings、share_db 和 `Vault/<syncDir>/<project_id>/.notemd`，不新增数据权威。必要删除中标记附着既有本机绑定，生命周期完成即移除。旧单篇分享不改协议、不改映射或入口。

## 8. 验收与完成标准

| 场景 | 必须证明的行为 |
| --- | --- |
| 当前文档 | 打开任意已保存 Markdown，可直接创建；无需目录选择；父目录和入口正确；关闭窗口/重启后草稿仍可见 |
| 未保存文档 | flush/保存后使用最终路径和正文；另存取消、失败不生成项目；不误用点击后切换的 tab |
| 同目录多入口 | a.md、b.md 获得不同 ID、镜像和 URL；重复 a.md 恢复原 ID；发布/停止/删除 a 不影响 b |
| 缺图真实复现 | 当前 strategy.md 的 5 个缺图显示未包含警告，可发布入口；公网正文可读、缺图有占位；不上传不存在的文件 |
| 引用分类 | 缺失文档/歧义/相对越界可见且不读错误目标；入口缺失、安全错误、权限失败仍阻断；未知异常不降级 |
| Vault 根与镜像 | Vault 根 Markdown可创建；引用正常文件可共享；所有源入口都拒绝 Sync/管理路径；镜像 tab 只定位既有项目 |
| 草稿与兼容 | 发布前就能选择/删除草稿；旧嵌套入口按实际文件命中且保留原基准/ID/URL/历史，多命中显式选择；只有凭据或单项损坏记录可见可处理 |
| 发布配置与重试 | 从真实宿主设置读配置；鉴权/离线有明确错误；未知结果同包同 URL 重试；确认后才给出成功链接 |
| 源消失 | 列表、管理、旧快照/反馈、原包重试和撤回/删除仍可执行；新发布及应用原件明确阻断 |

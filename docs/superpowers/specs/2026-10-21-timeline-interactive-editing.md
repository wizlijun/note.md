# Timeline 卡片交互编辑

用户确认：编辑开始/结束时间、重要程度，活动名称与事件描述均可编辑。此规格补充此前查看器只读边界；仅用户明确保存时写入当前 Timeline 文件，不修改引用来源。

## 交互

卡片详情及各级子议题提供“编辑”。表单含活动名称、事件描述、开始/结束时间及重要程度原生下拉（重要、普通、待判断），支持保存与取消。时间接受 HH:mm[:ss] 与日末 24:00，结束不得早于开始，父项修改后仍须包含所有子项。保存期间避免重复提交；编辑时阻止日期/卡片/设置切换，失败保留草稿。取消不写文件。沿用柔和明暗配色和紧凑卡片。

卡片显示原活动名称，分类规则继续决定分类，但不再用规则名称掩盖用户编辑的活动名称。活动名称与描述不能同时为空；名称禁止换行与冒号，描述允许单行纯文本。未修改的 Markdown 原样保留；显式修改文案时转义为普通文本，保留原来源链接及其目标。

## 文档与判断来源

时间和文案编辑不重算已证实耗时、来源字数或反常判断。ID、层级、来源及未涉及的正文/frontmatter 保留；保留 BOM 与换行风格。

重要程度改变时写入 `event_metadata[id].importance`，并设置 `importance_origin: manual` 和明确的手动设置理由。此可选字段只允许 `manual`；没有该字段继续执行原证据要求。手动判断可以没有证据，界面注明手动设置，保留已有证据作为原记录，不声称用户重新核对过原文。反常证据规则保持严格。

旧文件仅编辑时间或文案不升级格式。首次手动改变重要程度时，为所有真实事件（含子议题，不含代码示例）补稳定 ID 和 unknown 元数据，只有选中项写 manual。此后 ID 不随行序或标题改变。完整重解析成功后才发送保存请求。

该 manual 字段是契约扩展：旧查看器和外部生成/筛选工具若未支持，在手动等级无证据时可能拒绝文件。不得以本插件测试宣称外部工具已兼容；外部 Vault 工具不属于本次修改范围。

## 宿主保存

插件声明 `editor.write`；宿主在 `file_view.open.capabilities.edit` 明确告知当前文档是否可编辑。缺少能力的旧宿主仍可查看，详情提示更新宿主。

插件请求 `file_view.save {requestId, operationId, content}`。宿主校验插件 origin/frame、快照 requestId、单次 operationId、能力、文档身份、只读及外部冲突，并复用既有文档保存队列和 owner。响应 `file_view.save_result {requestId, operationId, ok, error?}`，然后同步新快照。插件保存前比较编辑起始快照，拒绝覆盖期间发生的外部修改；自己写入失败后的 dirty 快照可以重试。成功以宿主持久化结果为准，不以 postMessage 成功代替。

## 验收

- 源码保真：时间/标题/描述/重要程度各自编辑；CRLF/BOM、链接、嵌套、注释和未知字段；legacy 升级及稳定 ID；非法值拒绝且原文件不变。
- 安全保存：伪造消息、缺失能力、只读、过期快照、重复操作、并发变更及磁盘失败。
- 界面：父/子编辑、取消、失败重试、实际卡片更新、手动标识、明暗/390px/键盘。
- 完成定向测试、类型检查和构建，精确提交；本次实现不宣称已经发布或安装。

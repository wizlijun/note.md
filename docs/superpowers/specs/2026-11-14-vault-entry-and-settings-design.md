# Vault 创建入口与桌面设置设计

日期：2026-11-14  
状态：设计提案，待产品确认；本轮不实现、不发布。  
范围：macOS、Windows、Linux 桌面端。iOS 保持现有连接流程。

## 1. 目标与设计决定

新用户首次运行即获得 Vault 引导，无需寻找托盘图标，也可从主菜单进入 Vault 设置；此后在设置中查看位置、切换目录、初始化 Git 和管理已有同步。

- 参照托盘，仅在「文件」菜单保留一个状态化 Vault 入口：未配置显示「Vault：设置文件夹…」，已配置显示「Vault：~/…」。已配置时点击只查看设置，不直接打开目录选择器。
- 桌面设置增加「Vault」页，排在「通用」之后。所有 Vault 管理集中在此。
- Vault 是保存笔记与相关数据的本地文件夹。创建 Vault 不要求 Git、GitHub 账号或远程仓库。
- “修改目录”解释为切换当前 Vault。仅在设置底部折叠的「高级」区提供「更改 Vault 位置…」，明确影响并确认后才切换。物理搬迁和合并目录不在本期范围。
- Git 初始化、启用同步是两个独立动作；创建或打开 Vault 不自动提交或上传文件。
- 托盘入口保留并接入同一操作流程，不维护另一套选择/保存逻辑。

## 3. 主菜单与发现性

在「文件」菜单的「最近创建」之后、「关闭标签页」之前插入独立分组：

```text
文件
  新建… / 新建 Base / 新建 Canvas
  打开… / 打开分享链接…
  最近打开 >
  最近创建 >
  ─────────────────
  Vault：设置文件夹…              ← 未配置时
  （配置后同一项显示 Vault：~/Documents/My Vault）
  ─────────────────
  关闭标签页
  ……
```

菜单只有一个 Vault 项，始终可用，不新增快捷键或子菜单。未配置时点击进入首次设置引导；已配置时点击定位设置 Vault 页，路径失效时仍进入恢复/管理页，不退回新建引导。菜单显示缩写路径，过长时中间省略，完整路径可在设置中查看。

主菜单与托盘共用上述标签、状态和路由。托盘保留现有“未配置为选择文件夹、已配置显示路径”的简洁形式，但已配置时不再直接触发换目录。同步状态、立即同步、日志入口继续保留。主窗口隐藏时先显示主窗口；菜单事件只由一个操作宿主处理。Sumi/插件窗口中的该应用级入口聚焦主窗口，不触发其文件操作。

桌面已有“未设置 Vault”的功能空状态统一提供「设置 Vault…」，进入同一首次设置引导；至少覆盖搜索页。避免只提示“先配置”却不提供路径。首次运行主动展示可跳过的 Vault 引导（见 §3.1）；跳过后仍可直接编辑单文件。

### 3.1 首次运行引导

首次桌面 GUI 启动，在主窗口、设置与当前 Vault 状态读取完成后主动展示引导；不要用固定延时猜测状态。只在主窗口显示一次，CLI/后台启动不弹窗，也不标记引导已完成。

欢迎说明：

> 欢迎使用 note.md
> 先设置你的 Vault
> Vault 是保存笔记与相关数据的文件夹。文件保存在你选择的位置，无需 Git 或账号即可开始。
>
> **创建 Vault**　打开已有文件夹
> 稍后设置

“创建 Vault”为主按钮，复用 §4.1；“打开已有文件夹”复用 §4.2，不要求已有 note.md 元数据。取消系统选择器或创建表单返回引导，不将取消视为完成。验证失败在当前步骤显示，保留输入并可重试。

激活成功后显示简短完成页：Vault 名称、完整位置、“已准备就绪”。主按钮「开始使用」，次按钮「Vault 设置」。Git 只作为说明“需要版本管理时，可在 Vault 设置中初始化 Git”，不成为必选步骤、不自动初始化或同步。「开始使用」关闭引导并显示正常欢迎页及 Vault 概况；启动时有待打开文件则继续原打开请求，不创建额外空白文件。

「稍后设置」和 Escape 均明确跳过此次引导，回到正常界面。跳过后欢迎页保留醒目的「设置 Vault…」入口；后续启动不反复弹窗，缺 Vault 的功能仍提供设置入口。未完成也未明确跳过就退出应用，下次继续引导起始页。

状态存储在本机应用设置，例如 `vaultOnboardingV1 = completed | skipped`；缺值表示未处理，不写进 Vault，不跨设备同步。成功激活即可记 completed，避免关闭完成页前退出造成重复引导。已有可用 Vault 的升级用户直接记 completed，不再询问；已有路径失效时展示恢复提示而不是把旧用户当新用户重新创建。升级用户无 Vault 且状态缺失时也展示一次引导。

首次引导优先于其他应用内启动提示。`App.svelte` 现有 shell 命令安装提示须在引导本次完成或跳过后才有资格显示，并推迟到下次启动，避免接连弹窗；不提前标记 CLI 提示已处理。不改变操作系统权限弹窗的实际授权结果。恢复文件/深链只排队一次，完成或跳过后继续，不能丢失启动请求或重复打开文档。

### 3.2 主界面欢迎页：Vault 概况

源码核对：当前欢迎页是 `src/components/EmptyState.svelte`，显示 note.md 标识、大版本数字及新建/打开按钮，没有独立的“项目”列表。本设计在该欢迎内容中部的醒目位置新增 Vault 概况卡，位于品牌区域下方、新建/打开按钮上方；不另造项目系统。保留品牌与版本，大版本数字降低高度，让常见窗口尺寸首屏能看见 Vault 路径和操作。

有 Vault 的示意（数字仅为示例）：

```text
note.md                                      v6.…

当前 Vault                         [Vault 设置]
My Vault
~/Documents/My Vault      [复制] [显示]

1,248 篇文档       386.2 MiB 内容总尺寸
统计于 14:32                              [刷新]

[新建笔记]  [新建 Canvas]  [打开文件…]
```

- 名称取根目录名；路径展示当前实际根，当前用户主目录前缀统一缩写为 `~`，例如 `~/Documents/My Vault`，可选择复制。长路径折行，窄屏最多两行省略并提供完整提示/可访问名称；复制始终是完整路径。「显示」用当前系统文件管理器打开目录，「Vault 设置」进入统一管理页。
- 主指标仅“文档数”和“内容总尺寸”；详情说明可显示普通文件总数，不加入索引块数、Git 分支或同步健康仪表，避免欢迎页变成设置页。
- 无 Vault：同一区域显示「尚未设置 Vault」及一句用途说明，仅提供主按钮「设置 Vault…」，进入首次引导，再选择创建或使用已有文件夹。保留其下单文件新建/打开，不显示假的 `0 篇 / 0 B`。
- 路径不可访问：保留名称和路径，显示「无法访问此 Vault」，提供重新检查与 Vault 设置；统计显示不可用或标明“上次统计”，不能重置为零。
- 欢迎页卡片采用现有主题色、边框和排版，按钮沿既有样式；窄窗口指标与操作自然换行，不出现横向滚动。键盘可访问所有动作。
- 当前欢迎页容器双击会新建文件；新增卡片内的选字、复制、按钮点击/双击必须阻止触发该行为，只有原有空白背景可保留双击新建。

### 3.3 统计口径与刷新

展示的是当前 Vault 的文件概况，不是搜索索引的覆盖率。现有 `SearchStatsDto.files` 是索引文件数，`db_bytes` 是索引数据库尺寸，均不可直接当作本页文档数或总尺寸。

| 指标 | 确定口径 |
| --- | --- |
| 文档数 | 在下述内容文件集合中，按宿主及已启用插件现有文件类型识别能力判定为文档的普通文件数量。包含 Markdown、Canvas、Base 及已注册文档格式；图片、音视频等附件不计文档。复用既有类型识别规则，实施时冻结格式清单与测试，不能另写一套按搜索可索引性判断的规则。 |
| 内容总尺寸 | 同一内容文件集合内全部普通文件的逻辑字节数之和，包含文档、附件及其他内容文件；不等于物理磁盘占用。以 1024 进位并明确使用 KiB/MiB/GiB。 |
| 内容文件集合 | 当前 Vault 根下递归普通文件；排除任意层级 `.git`、`.notemd` 管理数据目录及平台元文件 `.DS_Store`、`Thumbs.db`。不因 gitignore、搜索排除配置或搜索大小上限漏计用户内容；其他隐藏内容文件仍按规则计入。 |

目录本身不计文件；符号链接不跟随、不累计目标；硬链接按可见路径计数及累计逻辑大小，此口径不宣称去重空间。已落入文件系统的同步副本按文件计入，不按内容哈希去重；未保存草稿不计。云占位文件只读可用元数据，不读取正文或主动下载；无法取得元数据列为未统计项。

统计由后端异步遍历文件元数据执行，不读取正文、不调用 LLM、不触发网络/提交、不阻塞主线程，也不依赖搜索索引构建完成。实现前检查现有文件类型注册能力能否无歧义区分“文档/附件”；若能力不足则补最小明确分类契约及用例，不能直接把全部文件改称文档。

- 首次无快照显示「正在统计…」，不先闪现 0。完成后同时更新两项指标和完成时间；真正空目录才显示 `0 篇 / 0 B`。
- 欢迎页显示时，先展示同根的内存快照，再异步刷新；本期不额外写磁盘统计缓存。页面可手动刷新，同一根并发请求合并。
- 欢迎页可见期间，文件变更触发防抖刷新，后台遍历最多一轮；频繁写入合并为待刷新，不无限排队。不保证逐字节实时，用完成时间表达快照性质。
- 欢迎页隐藏时不周期全库扫描；再次进入或应用回前台时按快照新鲜度刷新。插件文件类型变化使文档计数失效并重算。
- 切换 Vault 立即清除旧根指标，用根与代次绑定结果，取消或丢弃旧任务；A 的迟到统计不得显示到 B。
- 权限错误、目录消失、扫描中变动须区分：可跳过消失文件；不可读路径导致“统计不完整”，指标标“已统计”，附未统计项数量和重试。失败不显示成功时间，不以部分结果冒充全量。
- 大库扫描可取消，分批让出执行资源；只持有计数与受限诊断信息，不将全库文件路径/正文物化进前端。具体遍历并发与刷新阈值在实施时以隔离大库性能验证确定。

## 4. 首次设置与受保护的位置变更

### 4.1 首次创建 Vault

仅在尚未配置 Vault 的首次设置流程中提供创建能力；已有配置（含暂时不可访问的目录）不展示“再建一个 Vault”入口。打开小型对话框：标题「新建 Vault」，说明「Vault 是保存笔记与相关数据的文件夹。」

| 字段/动作 | 行为 |
| --- | --- |
| 名称 | 默认 `My Vault`，可改；仅允许单个合法目录名，拒绝空白、路径分隔符及当前平台非法名称。 |
| 保存位置 | 选择已有父目录，默认系统文档目录；无法获取时要求选择，不猜测路径。 |
| 最终路径 | 实时展示父目录与名称组合后的路径，用户主目录按 §8 缩写为 `~`。 |
| 创建 / 取消 | 创建按钮在输入有效时可用；取消无副作用。 |

创建独立子目录，目标已存在时不覆盖、不自动拼接编号，提示改名或返回首次引导选择「打开已有文件夹」。校验规范化路径、root_guard、写入权限；成功激活后关闭对话框，显示「Vault 已创建」，目录树定位新根。按既有初始化逻辑生成必要元数据和协作文件，不额外创建示例笔记或业务目录。

首次引导中的成功反馈按 §3.1；其他入口进入首次设置并创建完成后提供轻量反馈「可在设置 → Vault 中初始化 Git」，不强制进入 Git 向导。

### 4.2 首次选定目录 / 更改 Vault 位置

首次使用已有目录时使用系统目录选择器，标题「选择 Vault 文件夹」。已有 Vault 的更改入口只放在设置底部默认折叠的「高级」区；先说明通常无需更改，搬动过文件夹或明确改用其他目录时才使用，再通过目录选择器选择已有目标。选择器返回不立即切换，确认页并列显示原路径和目标路径，说明：「后续笔记与相关服务将使用新位置，旧 Vault 内容不会自动迁移或出现在新位置，原文件仍保留。」按钮为「取消」和「确认更改位置」，默认焦点在取消；只有明确确认才进入 §7 的切换流程。不要在此追加新建 Vault 向导。既有普通文件夹也可使用；非空目录明确提示会按需加入 note.md 管理文件，不覆盖已有内容。

当前目录重复选择视为无变更，不重启服务。选择旧 Vault 的父/子目录时提示目录重叠并阻止本次切换，以免把两个根的管理数据混用。符号链接先规范化，再作同目录、重叠和安全判断。

切换前等待正在保存的操作结束；有未保存编辑时使用现有保存/放弃/取消机制，取消则保留旧 Vault。普通文件标签保留绝对路径，不把旧文件映射到新根；依赖 Vault 的视图、设置草稿、搜索结果和订阅重新加载。无法安全切换的插件会话阻止切换并说明需先关闭的窗口，不强制丢弃草稿。

## 5. 设置 → Vault

页面按下面顺序组织，不将 Git 放在目录设置之前。

```text
Vault
  当前 Vault
    My Vault
    ~/Documents/My Vault
    [复制路径] [在文件管理器中显示]

  Git 版本管理（可选）
    尚未初始化
    [初始化 Git…]

  Git 同步
    尚未配置远程仓库
    配好远程仓库后可启用同步

  文件收集
    Sync 子目录       [Sync       ] [保存]

  高级（默认折叠）
    更改位置会改变后续笔记及服务使用的目录，不会迁移原文件。
    [更改 Vault 位置…]
    Git 大文件阈值    [现有值      ] [保存]
    既有协作文件提示（适用时）
```

- 未配置时：「尚未设置 Vault」，仅提供「设置 Vault…」进入首次引导。Git 与文件收集区显示简短依赖说明，不展示一整页不可用表单。
- 当前路径可复制、可换行或中间省略并查看完整值，不提供可误解为搬迁的可编辑文本框。
- 根不存在或不可写：显示实际路径与错误，优先提供「重新检查」，以及定位高级区的「文件夹已移动？」恢复入口；仍需路径对照确认，不静默创建替代目录。
- 将通用页现有 Vault 路径、Sync 子目录、大文件阈值及依附的协作提示移到此页；配置键、默认值和语义保持。通用页不重复保留编辑入口。
- Sync 子目录标注“文件收集目录”，与 Git 网络同步区分；路径修改沿用现有保存校验与语义，不承诺自动搬迁已收集文件。
- 搜索索引、搜索大文件阈值仍在搜索页；全局 Git 代理仍在原网络设置位置，可从同步区跳转。
- iOS 继续使用已有 VaultSettingsTab；桌面采用独立组件，避免复用 PAT/克隆表单造成能力混淆。

## 6. Git 初始化与同步

### 6.1 初始化

只有当前 Vault 是可写普通目录且尚无仓库时显示「初始化 Git…」。点击显示路径与作用：「在此 Vault 中创建本地 Git 仓库。此操作不会提交现有文件或上传到网络。」确认按钮「初始化」，取消无副作用。

初始化只创建本地仓库，默认分支 `main`；不执行 add/commit/push，不改全局 Git 配置，不生成或覆盖 .gitignore，不写虚构作者身份。完成后回读仓库根与分支，显示「Git 已初始化，尚无提交」；Vault 可继续使用。

仓库判定使用 Git 的真实根信息，不能仅测试 `.git` 目录：已有仓库不重建；有效 worktree 的 `.git` 文件识别为已配置。目标落在祖先仓库内但不是仓库根、裸仓库、损坏的 .git、Git 信任校验失败均显示具体原因，阻止初始化/同步，不自动删除 .git、创建嵌套仓库或修改 safe.directory。

缺少 Git 时显示「未检测到 Git」及「重新检查」；保留本地 Vault 功能，不自动安装工具。初始化失败后重新探测实际磁盘状态，避免失败后重复覆盖或把部分成功说成完整成功。

### 6.2 同步管理

显示真实分支、远端（URL 中凭据脱敏）、同步状态、最近成功时间、错误和查看日志入口。支持现有「启用/暂停同步」「立即同步」。操作成功、运行中和失败必须有可见反馈。

本期不新增远端仓库创建、克隆、账号登录或凭据管理。无远端时明确提示需先在 Git 中配置远端；提供可复制的当前目录路径，不把本地初始化表述为“云备份已开启”。

现有同步器默认使用 `origin/main`。本期只有满足该契约、已有提交且身份等前置检查通过时才允许启用；其他分支显示具体不支持原因，不擅自重命名分支或自动推送到 main。首次提交、Git 作者身份及远端配置本期仍由外部 Git 工具完成；设置文案明确列出缺少的步骤，初始化不等于已经产生版本历史。未来多远端/多分支或界面内首次提交另立规格。

首次启用当前 Vault 的同步时，说明将自动提交符合现有规则的文件并同步到所示远端，由用户明确开启。新创建或新打开的目录默认暂停；原有已配置 Vault 的正常启动行为保持。已有无远端的自动提交任务展示为“本地版本记录”，保留暂停能力，不谎报远程同步成功；本期不新增该模式的自动启用。同步授权与暂停状态保存在本机应用配置，按规范化 Vault 根绑定，不写入跨设备同步的 Vault 设置，也不使用全局布尔值让新根继承旧授权。首次升级仅迁移已配置旧根的实际启用状态；切换回已授权根可恢复其记录状态。暂停后不再启动新同步轮次；正在进行的网络动作显示“正在停止”，不能假装已经终止。

## 7. 共用操作与一致性契约

实现时抽出统一桌面 Vault 操作层，菜单、设置和托盘复用。以下为能力边界，命名可沿项目惯例调整：

| 能力 | 契约 |
| --- | --- |
| inspect | 返回当前根、可访问性、Git 仓库根/分支/远端与同步状态；只读，不触发初始化。 |
| create / activate | 所有校验先于切换，持久化成功后才发布新的当前根；串行执行，重复请求不重复创建或启动 worker。 |
| initGit | 显式请求才执行；绑定预期 Vault 根和代次，期间根变化则拒绝旧请求。 |
| sync controls | 绑定同一根及代次；返回实际操作结果，不吞掉错误。 |

切换顺序：验证候选 → 保护编辑状态 → 停止并等待旧 Vault worker/写入任务退出 → 持久化根配置 → 切换内存根并通知消费者 → 启动新根本地服务。Git 同步按明确授权状态启动，不能无条件启动。

须协调 settings.json 的 `vault_sync.repo_path` 与 shared 配置的 `sotvault`，保留无关字段；任一持久化步骤失败则恢复旧配置和可恢复的运行状态，不发布半成功根。回滚也失败时显示明确恢复错误并暂停相关写入，不声称仍在正常运行。

旧后台线程不能因共享 stop 标志被新启动重置而继续操作旧目录；需可等待的退出机制或等价的代次隔离，并等待在途 Git 操作结束。等待超时可取消本次切换并维持可诊断状态，不强杀 Git 或强行激活新根。

Vault 身份沿用 `sotvault/vault_id.rs::ensure`：已有 Vault 保留 `.notemd/vault-id`，新 Vault 生成自己的稳定 UUID，不因切换或 Git 初始化重置身份。

成功后统一刷新：托盘标签、sotvaultStore、vaultSettings、目录树、搜索/索引、最近记录、agents 服务及依赖 Vault 的插件状态。新根激活后索引失败属于“Vault 已设置，索引失败”，单独给重试入口，不把它报成创建失败。

创建目录后激活失败：保留并明确告知已创建的目录，重试可返回首次引导选择“打开已有文件夹”；不递归删除可能已有服务写入的目录。取消选择、校验拒绝不得改变原配置或启动新服务。

## 8. 文案、交互与无障碍

路径展示统一规则：欢迎页、设置、创建预览、引导完成页及应用内路径提示中，当前用户主目录本身显示 `~`，其子路径显示 `~/…`（Windows 使用对应路径分隔符）。按真实主目录及路径组件边界匹配，不硬编码 `/Users/用户名`，也不把同名前缀目录或其他用户目录缩写；主目录以外路径保持原样。缩写只影响显示，复制按钮、持久化、校验和文件操作均使用完整绝对路径；完整路径可通过提示查看。长路径省略在 `~` 缩写之后进行。


- 中文保持 Vault 专名，首次解释含义；菜单英文对应 Vault: Set Folder… / Vault: ~/…；位置变更为 Change Vault Location…，Git 初始化为 Initialize Git…；New Vault 仅用于首次创建步骤。
- 新增文案纳入既有本地化体系，覆盖项目支持语言；原生菜单与 Web 设置使用一致含义。
- 操作中禁用重复提交；错误保留在对应区域，可读、可重试；取消不展示错误。
- 键盘可完整完成流程，焦点进入对话框并在关闭后回到触发项；状态变化通过 live region 通知。
- 原生菜单沿用原生样式；如新增 Web 弹层菜单，必须用全局 `.menu-panel` / `.menu-row`，不自定义普通行 hover 背景。

## 9. 验收计划（实施阶段执行）

| 场景 | 验收结果 |
| --- | --- |
| 单入口与受保护变更 | 主菜单/托盘各只有一个 Vault 入口；已配置时点击只查看设置；欢迎页与设置主区无重复创建/切换按钮；高级区选目标后必须对照确认，取消保留旧根。 |
| 首次引导与跳过 | 首次主动出现；取消选择返回引导；跳过后不重复弹，欢迎页仍可设置；已有有效 Vault 不弹；无 CLI 弹窗叠加。 |
| 欢迎页与真实目录 | 文档/附件/管理目录混合 fixture 精确核计数与逻辑字节；主目录按组件边界缩写为 `~`，主目录外不缩写，复制仍为绝对路径；不拿索引大小代替；复制与双击不新建文件。 |
| 统计中断与切换 | 未知不显示零；不可读标不完整；A→B 迟到结果丢弃；大库不冻结 UI，隐藏页不持续全库扫描。 |
| 全新配置、无 Git、无托盘 | 从文件菜单单入口进入首次引导并创建 Vault；本地功能可用，无远程请求；设置中路径正确。 |
| 已有普通目录、已有仓库、worktree | 保留原内容；识别真实 Git 状态；无重复初始化或自动同步。 |
| 名称冲突、只读目录、危险目录、同目录、符号链接、重叠根 | 明确结果；失败/取消不改变旧配置，不覆盖已有文件。 |
| Git 初始化成功/失败/重复点击 | 仅当前指定目录受影响；无提交、无 push、无全局配置改写，失败后状态可重读。 |
| 祖先仓库、裸仓库、损坏 .git、缺 Git | 正确区分并阻止不适用操作，本地 Vault 能力不被误标为 Git 错误。 |
| 未保存文档/插件草稿/后台同步中切换 | 可取消；不丢编辑；旧 worker 停止后才激活新根；无旧结果污染新根。 |
| 任一配置写入失败、索引失败 | 不出现双根配置假成功；索引失败与设置成功分开报告。 |
| 远端缺失/分支不支持/身份缺失/网络错误 | 原因与动作清晰；不隐式改仓库；暂停与停止中的状态真实。 |
| 多窗口、隐藏主窗口、Linux 插件焦点 | 只打开一个正确的管理界面；文件保存/撤销路由不回归。 |
| 重启应用、跨入口修改 | 配置与授权状态持久化正确；菜单、设置、托盘及根消费者一致。 |
| 设置回归 | 移动后的 Sync 子目录/阈值/协作提示保持原行为；iOS 连接流程不变。 |

验证仅使用隔离临时目录、临时 Git 仓库及本地测试远端，不修改用户真实 Vault、不向真实远端推送。覆盖前端流程、后端失败注入和生命周期集成测试；三种桌面平台实际检查菜单可达性、焦点、长路径与明暗主题。设计评审不能替代上述产品验收。

## 10. 实施边界与待确认提案

推荐一次交付“首次引导 + 欢迎页 Vault 概况 + 菜单入口 + 桌面 Vault 页 + 创建/切换统一流程 + 本地 Git 初始化 + 已有同步状态/控制”。安全切换所需的生命周期和错误传播是本功能必要改动，不顺带重构其他同步协议。

本提案采用三个范围决定：目录修改仅切换、不搬迁；Git 为可选且不自动开启同步；远端/账号配置不在本期新增。若需要在设置中直接配置远端 URL、分支、SSH/PAT 或一键克隆，应在实现前扩展规格与凭据/首次推送流程。

# Vault 创建入口与桌面设置设计

日期：2026-11-14  
状态：设计提案，待产品确认；本轮不实现、不发布。  
范围：macOS、Windows、Linux 桌面端。iOS 保持现有连接流程。

## 1. 目标与设计决定

新用户无需寻找托盘图标，即可从主菜单创建或选定 Vault；此后在设置中查看位置、切换目录、初始化 Git 和管理已有同步。

- 在「文件」菜单新增直接可见的「新建 Vault…」「打开 Vault…」「Vault 设置…」，不藏入二级子菜单。
- 桌面设置增加「Vault」页，排在「通用」之后。所有 Vault 管理集中在此。
- Vault 是保存笔记与相关数据的本地文件夹。创建 Vault 不要求 Git、GitHub 账号或远程仓库。
- “修改目录”解释为切换当前 Vault。按钮写「更换 Vault…」，明确不会移动原文件。物理搬迁和合并目录不在本期范围。
- Git 初始化、启用同步是两个独立动作；创建或打开 Vault 不自动提交或上传文件。
- 托盘入口保留并接入同一操作流程，不维护另一套选择/保存逻辑。

## 3. 主菜单与发现性

在「文件」菜单的「最近创建」之后、「关闭标签页」之前插入独立分组：

```text
文件
  新建… / 新建 Base / 新建 Canvas
  打开… / 打开分享链接…
  最近打开 >
  最近创建 >
  ─────────────────
  新建 Vault…
  打开 Vault…
  Vault 设置…
  ─────────────────
  关闭标签页
  ……
```

三项始终显示，无 Vault 时也可用，不新增快捷键。已经配置 Vault 时仍可创建或打开另一个，完成后成为当前 Vault。主窗口隐藏时先显示主窗口，再执行动作；菜单事件只由一个操作宿主处理，避免多窗口重复弹窗。Sumi/插件窗口中的应用级入口也应聚焦主窗口，不触发该窗口的文件操作。

「Vault 设置…」直接定位设置 Vault 页。托盘原目录项改为「Vault 设置…」（可保留当前目录名作为上下文），落到同一页；同步状态、立即同步、日志入口继续保留。

桌面已有“未设置 Vault”的功能空状态统一提供「设置 Vault…」，打开本页；至少覆盖搜索页。避免只提示“先配置”却不提供路径。不新增强制开屏向导，普通单文件编辑仍可直接使用。

## 4. 创建与打开流程

### 4.1 新建 Vault

打开小型对话框：标题「新建 Vault」，说明「Vault 是保存笔记与相关数据的文件夹。」

| 字段/动作 | 行为 |
| --- | --- |
| 名称 | 默认 `My Vault`，可改；仅允许单个合法目录名，拒绝空白、路径分隔符及当前平台非法名称。 |
| 保存位置 | 选择已有父目录，默认系统文档目录；无法获取时要求选择，不猜测路径。 |
| 最终路径 | 实时展示父目录与名称组合后的完整路径。 |
| 创建 / 取消 | 创建按钮在输入有效时可用；取消无副作用。 |

创建独立子目录，目标已存在时不覆盖、不自动拼接编号，提示改名或使用「打开 Vault」。校验规范化路径、root_guard、写入权限；成功激活后关闭对话框，显示「Vault 已创建」，目录树定位新根。按既有初始化逻辑生成必要元数据和协作文件，不额外创建示例笔记或业务目录。

首次成功后提供轻量反馈「可在设置 → Vault 中启用 Git」，不强制进入 Git 向导。

### 4.2 打开 Vault / 更换 Vault

使用系统目录选择器，标题「选择 Vault 文件夹」，选择后显示路径及说明：「将此文件夹设为当前 Vault。原 Vault 的文件会保留，不会移动。」既有普通文件夹也可使用；非空目录明确提示会按需加入 note.md 管理文件，不覆盖已有内容。

当前目录重复选择视为无变更，不重启服务。选择旧 Vault 的父/子目录时提示目录重叠并阻止本次切换，以免把两个根的管理数据混用。符号链接先规范化，再作同目录、重叠和安全判断。

切换前等待正在保存的操作结束；有未保存编辑时使用现有保存/放弃/取消机制，取消则保留旧 Vault。普通文件标签保留绝对路径，不把旧文件映射到新根；依赖 Vault 的视图、设置草稿、搜索结果和订阅重新加载。无法安全切换的插件会话阻止切换并说明需先关闭的窗口，不强制丢弃草稿。

## 5. 设置 → Vault

页面按下面顺序组织，不将 Git 放在目录设置之前。

```text
Vault
  当前 Vault
    My Vault
    /Users/…/Documents/My Vault
    [在文件管理器中显示] [更换 Vault…]
    [新建 Vault…]

  Git 版本管理（可选）
    尚未初始化
    [初始化 Git…]

  Git 同步
    尚未配置远程仓库
    配好远程仓库后可启用同步

  文件收集
    Sync 子目录       [Sync       ] [保存]

  高级
    Git 大文件阈值    [现有值      ] [保存]
    既有协作文件提示（适用时）
```

- 未配置时：「尚未设置 Vault」，主按钮「新建 Vault…」、次按钮「打开 Vault…」。Git 与文件收集区显示简短依赖说明，不展示一整页不可用表单。
- 当前路径可复制、可换行或中间省略并查看完整值，不提供可误解为搬迁的可编辑文本框。
- 根不存在或不可写：显示实际路径与错误，提供「重新检查」「更换 Vault…」，不静默创建替代目录。
- 将通用页现有 Vault 路径、Sync 子目录、大文件阈值及依附的协作提示移到此页；配置键、默认值和语义保持。通用页不重复保留编辑入口。
- Sync 子目录标注“文件收集目录”，与 Git 网络同步区分；路径修改沿用现有保存校验与语义，不承诺自动搬迁已收集文件。
- 搜索索引、搜索大文件阈值仍在搜索页；全局 Git 代理仍在原网络设置位置，可从同步区跳转。
- iOS 继续使用已有 VaultSettingsTab；桌面采用独立组件，避免复用 PAT/克隆表单造成能力混淆。

## 6. Git 初始化与同步

### 6.1 初始化

只有当前 Vault 是可写普通目录且尚无仓库时显示「初始化 Git…」。点击显示路径与作用：「在此 Vault 中创建本地 Git 仓库。此操作不会提交现有文件或上传到网络。」确认按钮「初始化」，取消无副作用。

初始化只创建本地仓库，默认分支 `main`；不执行 add/commit/push，不改全局 Git 配置，不生成或覆盖 .gitignore，不写虚构作者身份。完成后回读仓库根与分支，显示「Git 已初始化，尚无提交」；Vault 可继续使用。

仓库判定使用 Git 的真实根信息，不能仅测试 `.git` 目录：已有仓库不重建；有效 worktree 的 `.git` 文件识别为已配置。目标落在祖先仓库内但不是仓库根、裸仓库、损坏的 .git、Git 信任校验失败均显示具体原因，阻止初始化/同步，不自动删除 .git、创建嵌套仓库或修改 safe.directory。

缺少 Git 时显示「未检测到 Git」及「重新检查」；保留本地 Vault 功能，不自动安装工具。初始化失败后重新探测实际磁盘状态，避免失败后重复覆盖或把部分成功说成完整成功。

### 6.2 同步管理

显示真实分支、远端（URL 中凭据脱敏）、同步状态、最近成功时间、错误和查看日志入口。支持现有「启用/暂停同步」「立即同步」。操作成功、运行中和失败必须有可见反馈。

本期不新增远端仓库创建、克隆、账号登录或凭据管理。无远端时明确提示需先在 Git 中配置远端；提供可复制的当前目录路径，不把本地初始化表述为“云备份已开启”。

现有同步器默认使用 `origin/main`。本期只有满足该契约、已有提交且身份等前置检查通过时才允许启用；其他分支显示具体不支持原因，不擅自重命名分支或自动推送到 main。首次提交、Git 作者身份及远端配置本期仍由外部 Git 工具完成；设置文案明确列出缺少的步骤，初始化不等于已经产生版本历史。未来多远端/多分支或界面内首次提交另立规格。

首次启用当前 Vault 的同步时，说明将自动提交符合现有规则的文件并同步到所示远端，由用户明确开启。新创建或新打开的目录默认暂停；原有已配置 Vault 的正常启动行为保持。已有无远端的自动提交任务展示为“本地版本记录”，保留暂停能力，不谎报远程同步成功；本期不新增该模式的自动启用。同步授权与暂停状态保存在本机应用配置，按规范化 Vault 根绑定，不写入跨设备同步的 Vault 设置，也不使用全局布尔值让新根继承旧授权。首次升级仅迁移已配置旧根的实际启用状态；切换回已授权根可恢复其记录状态。暂停后不再启动新同步轮次；正在进行的网络动作显示“正在停止”，不能假装已经终止。

## 7. 共用操作与一致性契约

实现时抽出统一桌面 Vault 操作层，菜单、设置和托盘复用。以下为能力边界，命名可沿项目惯例调整：

| 能力 | 契约 |
| --- | --- |
| inspect | 返回当前根、可访问性、Git 仓库根/分支/远端与同步状态；只读，不触发初始化。 |
| create / activate | 所有校验先于切换，持久化成功后才发布新的当前根；串行执行，重复请求不重复创建或启动 worker。 |
| initGit | 显式请求才执行；绑定预期 Vault 根和代次，期间根变化则拒绝旧请求。 |
| sync controls | 绑定同一根及代次；返回实际操作结果，不吞掉错误。 |

切换顺序：验证候选 → 保护编辑状态 → 停止并等待旧 Vault worker/写入任务退出 → 持久化根配置 → 切换内存根并通知消费者 → 启动新根本地服务。Git 同步按明确授权状态启动，不能无条件启动。

须协调 settings.json 的 `vault_sync.repo_path` 与 shared 配置的 `sotvault`，保留无关字段；任一持久化步骤失败则恢复旧配置和可恢复的运行状态，不发布半成功根。回滚也失败时显示明确恢复错误并暂停相关写入，不声称仍在正常运行。

旧后台线程不能因共享 stop 标志被新启动重置而继续操作旧目录；需可等待的退出机制或等价的代次隔离，并等待在途 Git 操作结束。等待超时可取消本次切换并维持可诊断状态，不强杀 Git 或强行激活新根。

Vault 身份沿用 `sotvault/vault_id.rs::ensure`：已有 Vault 保留 `.notemd/vault-id`，新 Vault 生成自己的稳定 UUID，不因切换或 Git 初始化重置身份。

成功后统一刷新：托盘标签、sotvaultStore、vaultSettings、目录树、搜索/索引、最近记录、agents 服务及依赖 Vault 的插件状态。新根激活后索引失败属于“Vault 已设置，索引失败”，单独给重试入口，不把它报成创建失败。

创建目录后激活失败：保留并明确告知已创建的目录，重试可使用“打开 Vault”；不递归删除可能已有服务写入的目录。取消选择、校验拒绝不得改变原配置或启动新服务。

## 8. 文案、交互与无障碍

- 中文保持 Vault 专名，首次解释含义；英文对应 New Vault… / Open Vault… / Vault Settings… / Change Vault… / Initialize Git…。
- 新增文案纳入既有本地化体系，覆盖项目支持语言；原生菜单与 Web 设置使用一致含义。
- 操作中禁用重复提交；错误保留在对应区域，可读、可重试；取消不展示错误。
- 键盘可完整完成流程，焦点进入对话框并在关闭后回到触发项；状态变化通过 live region 通知。
- 原生菜单沿用原生样式；如新增 Web 弹层菜单，必须用全局 `.menu-panel` / `.menu-row`，不自定义普通行 hover 背景。

## 9. 验收计划（实施阶段执行）

| 场景 | 验收结果 |
| --- | --- |
| 全新配置、无 Git、无托盘 | 从文件菜单创建 Vault；本地功能可用，无远程请求；设置中路径正确。 |
| 已有普通目录、已有仓库、worktree | 保留原内容；识别真实 Git 状态；无重复初始化或自动同步。 |
| 名称冲突、只读目录、危险目录、同目录、符号链接、重叠根 | 明确结果；失败/取消不改变旧配置，不覆盖已有文件。 |
| Git 初始化成功/失败/重复点击 | 仅当前指定目录受影响；无提交、无 push、无全局配置改写，失败后状态可重读。 |
| 祖先仓库、裸仓库、损坏 .git、缺 Git | 正确区分并阻止不适用操作，本地 Vault 能力不被误标为 Git 错误。 |
| 未保存文档/插件草稿/后台同步中切换 | 可取消；不丢编辑；旧 worker 停止后才激活新根；无旧结果污染新根。 |
| 任一配置写入失败、索引失败 | 不出现双根配置假成功；索引失败与设置成功分开报告。 |
| 远端缺失/分支不支持/身份缺失/网络错误 | 原因与动作清晰；不隐式改仓库；暂停与停止中的状态真实。 |
| 多窗口、隐藏主窗口、Linux 插件焦点 | 只打开一个正确的管理界面；文件保存/撤销路由不回归。 |
| 重启应用、跨入口修改 | 配置与授权状态持久化正确；菜单、设置、托盘及根消费者一致。 |
| 设置回归 | 移动后的 Sync 子目录/阈值/协作提示保持原行为；iOS 连接流程不变。 |

验证仅使用隔离临时目录、临时 Git 仓库及本地测试远端，不修改用户真实 Vault、不向真实远端推送。覆盖前端流程、后端失败注入和生命周期集成测试；三种桌面平台实际检查菜单可达性、焦点、长路径与明暗主题。设计评审不能替代上述产品验收。

## 10. 实施边界与待确认提案

推荐一次交付“菜单入口 + 桌面 Vault 页 + 创建/切换统一流程 + 本地 Git 初始化 + 已有同步状态/控制”。安全切换所需的生命周期和错误传播是本功能必要改动，不顺带重构其他同步协议。

本提案采用三个范围决定：目录修改仅切换、不搬迁；Git 为可选且不自动开启同步；远端/账号配置不在本期新增。若需要在设置中直接配置远端 URL、分支、SSH/PAT 或一键克隆，应在实现前扩展规格与凭据/首次推送流程。

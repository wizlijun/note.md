# 项目文档分享：极简设计

日期：2026-10-10。状态：待用户审阅；未实现。

沿用 Superpowers brainstorming 的架构设计流程。本次按极简原则重新 review，替代此前较重的版本；本轮只修订 Spec。

## 1. 目标与结论

从项目的一篇 Markdown 发起分享，把引用的文档和资源一起交给别人；对方在浏览器标注、编辑后自动回传，主人在本机审阅接受。

只增加这条流程：

```
原项目 → Vault/<syncDir>/<project_id>/ → 一个静态 HTML 分享包
                                            ↓ 浏览器编辑、标注并提交
原项目 ← 本机审阅 ← 现有 Worker + R2 收件箱
```

原项目是正文来源，Sync 目录是镜像及分享管理落点，线上是已发布静态副本。接受修改后更新原件，再刷新镜像、重新发布。继续要求配置 Vault；首版一个项目一个分享空间。

## 2. 极简 Review 的取舍

| 上版设计 | 首版收敛 |
| --- | --- |
| 稳定 documentId、双层链接映射与逆向转换 | 用项目相对路径定位，Markdown 字节保持不变，渲染时解析链接 |
| 独立静态文件路由、远端快照目录与 current 索引 | 继续一个 HTML 包，复用 `/publish`、KV、原 URL 和 edit_token |
| 每人 grant、角色、逐文档权限、epoch | 一个项目协作 token；持有者可编辑和标注全部已分享文档 |
| 跨根 `_external` 自动搬运 | 项目根内打包；越界时提示调整项目根或原文相对链接 |
| 线程、回复、自动重锚、公开讨论 | 一条标注是旧快照里的选文和评论，主人可查看 |
| 自动三方合并、多人状态和生命周期状态机 | 主人显式审阅；原件已变时人工对照合入；只有发布、重新发布、停止分享 |
| 预设多个 Repository/Resolver/Transport 组件 | 在现有 Sync、分享模块和 Worker 中补必要功能，不先建通用框架 |

保留不可缺的正确性：分享范围预览、镜像冲突检查、旧基线、本地草稿、收件鉴权与去重、原件回写确认、私有数据隔离。极简不等于覆盖原件或丢失反馈。

备选的完全静态手动返还不满足自动回传；实时云端协作增加服务与状态，均不采用。

## 3. 本地只有一个项目目录

syncDir 使用已有 Vault 配置，默认 `sync`。project_id 随机生成；项目显示名或源根移动不改变它。源根的设备路径和逐文件绑定沿用本机 Sync 记录；不向源项目另写管理目录。

```
Vault/<syncDir>/<project_id>/
  README.md
  docs/design.md
  assets/diagram.png
  .notemd/
    project.json                 # 分享集合、slug/URL、最后确认的 snapshotId
    snapshots/{snapshotId}/
      manifest.json              # 相对路径和 hash
      files/...                  # 本次批准的原样文件基线
      bundle.html                # 本次唯一上传产物
    inbox/{submissionId}.json     # 云端原包 + 本地处理状态/回写记录
```

owner 发布凭据、edit_token 和协作 token 留在应用本机凭据/分享记录中，不写入 bundle 或 Vault 可同步配置。project.json 只维护一份分享配置；原文、镜像、发布基线的用途分别明确。

既有 Sync 必须补的兼容点，不另做同步系统：

- 项目目标固定为 `<syncDir>/<project_id>/<相对路径>`，不加日期、不扁平化、不创建 `-2` 更新副本；项目 Markdown 和资源按原字节镜像，不套用单篇图片路径改写。路径穿越、软链越界、保留目录或大小写折叠碰撞必须拒绝，不能覆盖其他文件。
- 源单侧修改可刷新镜像；镜像自身变化须先处理。现有检查在源未变时会忽略镜像改动，项目发布前必须额外检查镜像 hash，不能把已有检查当成双边一致证明。
- 旧单篇映射缺省为 legacy，项目映射带 project_id；旧分享按 legacy 选目标，项目分享按项目选目标。保存源文件时枚举其全部已跟踪镜像，分别更新或报冲突，不能继续只取 `find_by_source` 首项。
- 新项目镜像 metadata 按完整镜像相对路径和设备标识命名，避免同名文件覆盖；兼容读旧 metadata，刷新时更新 checksum。个人手记 home 保持既有默认映射，不随新增项目副本变化。

首版只在已绑定原项目的设备维护分享；其他设备可读镜像。源根、Vault 或 syncDir 移动后显式重绑已有目录，未核验前暂停维护；不实现自动迁移、多人接管或文件改名追踪。

## 4. 引用一起分享，发布仍复用现有接口

1. 选择项目根和入口，解析根内 Markdown 链接、引用式链接、Wikilink、标题 fragment、图片和资源，递归去重并终止循环。代码中的伪链接不算引用。
2. 展示实际文件集合供确认。只上传批准的内容；引用标题仍意味着分享整篇。新引用或新文件不自动加入。缺失/同名歧义要明确解决，被排除的引用显示未共享。
3. 绝对本地路径、软链逃出根目录和越界引用在发布前报告；需要时调整根目录或原文相对链接后再发布。禁止把包含私有绝对引用的 Markdown 原样塞入公开包。排除凭据、管理目录、个人 `.note.md` 和生成的镜像本身。
4. 保存源文件，按批准清单刷新镜像并核验 hash，冻结为 snapshotId 对应的基线。源删除、未解决镜像改动或冻结期间内容变化时阻断/重试，不能以旧镜像冒充当前原件。
5. 把原样 Markdown、渲染页面、图片和必要资源一起嵌入一个 HTML；页面内导航按当前文档相对路径解析，源码不改写。资源可内嵌显示或下载，不执行附件脚本。原文与渲染结果都仅来自批准集合。
6. 使用现有 `POST /publish` 上传完整 HTML，沿用 slug/edit_token 更新原 URL。包内带 snapshotId，旧页面/草稿保持旧版本；刷新才取得新版。

整个 HTML 沿用现有 25 MiB 上限，包含脚本、原文、渲染内容和内嵌资源，超限明确拒绝，不截断、不暗中拆包。首版不另建大项目分片发布能力。

每次上传前先持久化对应基线，拟用 slug/edit_token/协作 token/snapshotId 在本机保存为待确认发布；响应未知时使用同一组身份重试同一包，不能重新生成 URL 或发布凭据。现有 publishHtml 仅在成功后记账，项目入口需补这个本机预存步骤。本机只在服务确认后记录发布成功；页面可能因现有 KV/CDN 缓存延迟更新，不承诺所有访客立即切换。保存源文件只更新镜像，发布仍由主人明确触发。

所有准备上传过的基线在本空间存续期间保留，涵盖响应丢失但实际成功的发布。无需远端旧版本存储：已打开页面有自身原文，本机有对应基线；首版不提供远端历史版本浏览。

## 5. 浏览器只提供阅读、草稿和提交

一个普通链接用于阅读；一个带项目协作 token 的链接允许编辑和标注全部已分享文档。全部协作者权限相同，没有真实身份认证或逐人撤权。

首版使用 Markdown 文本编辑和预览，复用现有渲染能力；不要求搬入完整桌面编辑器/CDR。草稿存 IndexedDB，键为 project_id/snapshotId/相对路径；确认持久化后才显示已保存，失败保留当前内容并可导出备份。

标注只保存 `snapshotId、相对路径、选文、位置、评论`。在对应旧快照中展示，不能唯一定位则显示选文；不自动迁移到新正文，不做线程回复，不自动向其他访客公开。

访客点击“提交修改”后自动回传，不逐键上传。提交时冻结包和 submissionId，重试不重建包；继续编辑产生新包和新 ID。反馈含编辑后的完整 Markdown 和标注；离线或提交失败保留草稿，结果未知沿用同一 submissionId 重试。已送达仅代表云端收件，不代表主人已收到或已接受。

协作 token 从 URL fragment 读取，请求头提交，不嵌在公开 HTML，也不能得到 owner 凭据。静态正文/评论须净化、JSON 内嵌须安全转义并设置合适 CSP，避免文档内容读取 token 或执行脚本。

## 6. Worker 只增加收件与主人取件

继续使用现有 Worker、SHARES KV 和 MEDIA R2；不新增服务、数据库、账号、DO、队列或常驻同步。既有阅读统计保持原状。

每项目一个随机协作 token，仅把 hash 作为已有分享 KV 记录的附加 metadata 保存，并绑定 project_id；token 不授予发布或读取收件箱的权限。重新发布保持 token；如需换 token 整个项目统一更换，不维护历史邀请。

| 操作 | 最小合同 |
| --- | --- |
| 访客 POST feedback | 按 slug 查分享 metadata，核对 project_id、当前 token 和过期时间；校验 schema/相对路径格式/大小，写入私有 R2 |
| 主人列出/下载 feedback | 使用既有 owner API 凭据，按 project_id 前缀分页取件；访客不可调用 |
| 发布/停止分享 | 扩展现有发布 metadata，复用已有发布/撤回认证；无新成员管理接口 |

反馈最小字段：schemaVersion、project_id、snapshotId、submissionId、文档相对路径/baseHash/afterMarkdown、标注；昵称只是自报信息。请求体上限 5 MiB；超限保留草稿并提示。收件接口只鉴权暂存，不认可客户端自报的基线和文件集合；本机必须用自己保存的快照核验，未知快照或未分享文件进入隔离，不能直接应用。

R2 对象键为 `feedback/{project_id}/{submissionId}.json`。服务器计算请求内容 hash 并记录首次 receivedAt；条件创建保证同 ID 同内容重试得到原回执、异内容返回冲突，不能先 HEAD 再无条件 PUT。确定写入后才显示已送达。

原包和去重键保留至整个空间明确清理，不逐包删除；本机处理状态不写回云端。主人打开分享或点击检查反馈时分页拉取并按 ID 去重，cursor 仅用于当前扫描，不依赖后台轮询。

token 已换、分享已停或过期时可拒绝重试；丢响应者保留“结果未知”和草稿，由主人取件核对，不承诺跨全部生命周期的回执查询。KV 缓存会使 token 更换/停止分享存在传播延迟，在途提交也可能完成，首版不承诺即时撤权。

## 7. 本机审阅：先不做自动三方合并

先用本地快照校验 project_id、snapshotId、相对路径和 baseHash；只允许映射到已绑定源文件，不接受新增/删除文件或客户端指定的本机绝对路径。

| 当前情况 | 主人可执行的操作 |
| --- | --- |
| 原件仍等于发布基线 | 查看差异，明确接受后把访客 Markdown 写回原件 |
| 原件已经变化 | 并列展示基线、当前原件、访客版本；主人选择或编辑最终文本，再确认写入，不静默覆盖 |
| 只有标注 | 查看对应快照、选文和评论，保留在反馈记录中 |
| 原件只读/缺失、绑定缺失或镜像存在未处理改动 | 保留反馈，先处理权限、重绑或镜像冲突；不以写镜像代替原件 |

审阅前先处理应用内原件的未保存编辑；回写后刷新已打开的原件 tab，避免旧缓冲区覆盖结果。回写前重新检查原件 hash，若又变化则返回审阅。按文件接受；提交中的某一文件已接受，不阻碍其余文件继续审阅。

每个 inbox 文件兼作该提交的处理记录：写原件前持久化原 hash、拟写结果 hash/文本和待应用标记，写后再标记已接受。崩溃恢复比对这些 hash；无法确定则人工核对，不重复覆盖。这里只做文件级恢复，不建设多文件事务框架，也不宣称对任意外部 writer 有原子 CAS。

接受后调用 Sync 刷新相关镜像；刷新失败显示待重试，不能再次应用源修改或用旧镜像发布。再次发布后访客才看到已接受的正文。

## 8. 生命周期与边界

本机入口只需要发布、重新发布、检查反馈、审阅、停止分享。停止分享复用已有撤回，原项目、镜像、快照和反馈保留；离线/结果未知显示待确认。

KV 和公共缓存决定停止分享/更新的传播时间，不能承诺立即使所有缓存副本消失；已下载内容无法收回。收件也按同一分享记录核验是否存在/过期。停止后的在途反馈仍供主人审阅。

首版不做定时清理或自动垃圾回收。彻底清理属于明确的整空间操作：先停止分享、取回反馈并保存本地归档，再清理该项目云端收件和镜像管理目录；不删除原项目或其他镜像。project_id 不复用，清理后旧草稿不再有投递/合并基线保证。清理与在途请求不具备跨存储事务，不承诺一次请求即永久清空所有边缘残留。

## 9. 必须通过的验收

| 范围 | 核心验证 |
| --- | --- |
| Sync 兼容 | 两个子目录同名文件不碰撞；旧单篇/项目镜像共存且源保存均刷新；个人手记 home 不变 |
| 引用/隐私 | 循环、相对路径、Wikilink、fragment、图片正确；越界/绝对引用明确处理；未批准内容、私有元数据和 token 不进入 HTML |
| 发布 | 超限明确拒绝；失败/未知保留基线；源或镜像变化会阻断；重新发布沿用 URL，旧草稿基线不变 |
| 浏览器 | 中文输入、撤销、草稿重开恢复；持久化失败不报成功；选文评论可查看旧快照；脚本/附件不能执行文档注入 |
| 自动回传 | 主人离线仍可收件；错误 token/owner 越权拒绝；条件创建并发/重试不重复，异内容冲突；分页取件无遗漏 |
| 审阅回写 | 原件未改可接受；已改有可操作的人工合入；路径伪造/未知基线隔离；重复/崩溃/原件再次变化不静默覆盖 |
| 完整流程 | 两篇互引文档和图片一起发布；对方编辑/标注提交；主人取件合入原件、镜像刷新、重新发布；停止分享不删原件 |

本次 review 结论：首版收敛为“项目镜像 + 静态分享包 + 反馈收件”。上述均为未来功能验收；本轮仅文档审查，不能以旧测试宣称新功能已通过。

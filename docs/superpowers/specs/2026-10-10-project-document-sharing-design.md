# 项目文档、引用集合与远端协作设计

日期：2026-10-10。

状态：待用户审阅的 Spec 草案；未批准、未实现。

流程：Superpowers 6.3.0 / brainstorming / architectural。本文只定义设计与验收；用户批准后再通过 writing-plans 编写实施计划。

## 1. 需求与推荐决策

从项目的一篇文档发起分享，连同其引用文档和附件交给他人；接收者可以在浏览器阅读、标注和编辑。项目可以位于 Vault 外，继续使用原目录、Git、IDE 和 Agent 工作流。

推荐新增独立于 Vault 的 ProjectBinding / ShareSpace 层：项目目录是文件定位范围，ShareSpace 是经过确认的文档集合、授权和协作范围。现有单文档 Sync 保留；项目分享不能通过逐文件调用现有 Sync 拼装。

默认产品假设：引用递归发现、发布前预览；引用文档按整篇授权；远端编辑直接保存共享版本，本机明确接收后合回源文件。首版支持提交式协作，不承诺多人同段逐字实时合并。需要同时输入体验时接入既有规格选定的 Yjs。

### 1.1 成功标准

- owner 能从任意可访问的项目目录选择入口 Markdown，不要求配置 Vault 或迁移原文件。
- 接收者只需浏览器，即可在授权范围内沿引用阅读、查看附件、标注和编辑。
- 接收者的正文修改形成持久共享版本，可由 owner 接收到原项目文件；电脑离线不阻塞云端保存。
- 新增链接不会自动公开新文件；并发修改不会静默覆盖另一方内容。
- 原项目继续作为 Git、IDE 和 Agent 的普通 Markdown 目录，不依赖专有云端格式才能读取。

### 1.2 首版范围与非目标

首版包含：项目绑定、单个或多个入口的引用集合、发布预览、多文档浏览、受控附件、受邀访客、阅读/标注/编辑权限、独立讨论、提交式编辑、本机差异接收、三方合并和恢复。分阶段实现不改变完整交付标准。

首版不包含：整个项目或 Vault 自动公开、同段逐字实时输入、完整离线浏览器编辑、任意文档嵌入、跨文档块引用、摘录级权限、远端文件增删改名、跨共享空间自动合并、目录级原子文件系统同步及公开 Profile SDK。

### 1.3 本草案采用的产品默认值

以下是供用户审阅的设计选择，不表示用户已确认：接收端优先浏览器；递归引用按整篇分享；本机源修改由 owner 执行“同步共享空间”提交；远端修改默认显式接收；首版不提供自动接收开关；编辑采用提交式协作。若用户要求同段实时输入，需要修改范围并增加独立 CRDT ADR，不能在实施时自行替换默认行为。

### 2.1 方案比较与选择

| 方案 | 优点 | 代价与限制 | 结论 |
| --- | --- | --- | --- |
| 独立项目绑定 + 有边界的共享空间 | 保留项目位置；身份和授权清楚；支持浏览器协作与回写；可复用现有编辑内核和云端部署 | 需新增引用集合、远端存储和项目同步适配器 | 采用 |
| 将引用文件逐个 Sync 到 Vault 后分别 Share | 单文档能力复用较多，适合临时只读链接集合 | 目录层级和相对引用丢失；缺少统一授权、共享版本与正文回写 | 不满足完整需求 |
| 首版建设整个目录的 CRDT 同步系统 | 可覆盖实时共同编辑和更广的目录同步 | 将引用分享扩大为文件系统协作；身份、外部 writer、离线状态与迁移成本更高 | 延后，按真实体验需求接入 |

## 3. 领域边界与数据流

```text
原项目目录（Vault 内外均可）
  ↕ Project Sync：基线、版本、显式接收、冲突处理
ShareSpace（已授权文档、附件、共享版本、批注、历史）
  ↕ Worker API：认证、提交、订阅
接收者浏览器（阅读 / 标注 / 编辑）

原项目目录 → 可选 Vault 镜像（沿用现有个人收集与检索）
```

不让 Vault 镜像成为新协作的必经中间写入点。若保留项目镜像，应在独立项目命名空间保留相对目录，且只作派生表示；不可再增加一套独立正文权威。

| 对象 | 最小职责 |
| --- | --- |
| ProjectBinding | 稳定 projectId、documentId 与本机根目录/相对路径映射；根目录可重新绑定 |
| ShareSpace | spaceId、owner、入口文档、生命周期；一个空间是一条共同维护的版本线 |
| Manifest | 有版本的文档/附件成员清单、引用边、首次发布的精确 revision 集合 |
| SharedDocument | documentId、当前 revision、块身份、规范 Markdown 和历史 |
| Grant | 空间角色及文档权限上限；不因出现链接而产生授权 |
| AnnotationThread | 作者、回复、解决状态、版本绑定的锚点 |
| SyncBaseline | 本机源内容及 hash、对应共享 revision、同步结果与待处理状态 |

路径和内容 hash 都不是文档 ID：重命名保留 ID，相同内容的不同文件也保留不同 ID。应用外移动只有在唯一可验证时重绑，歧义时请用户定位，不凭 hash 猜测。

项目描述信息建议集中在项目 `.notemd/project.json`，不向正文批量注入 frontmatter；项目只读或用户不愿写配置时，由应用管理的本机项目状态目录保存描述，用户也可明确选择 Vault 关联目录，不能要求先配置 Vault。只保留一个已选定的描述来源，不同时维护两份可写账本。设备绝对根路径留在本机 binding，凭据留在本机凭据存储，不上传到访客可读 manifest。

同一文档如需与同一批人持续协作，复用同一 ShareSpace。创建独立空间意味着独立共享版本线；首版不把其他空间的修改自动串到当前空间，也不为每个访客复制一份正文。

### 3.1 组件接口与依赖

| 组件 | 输入 → 输出 | 依赖与禁止事项 |
| --- | --- | --- |
| ProjectBinding | 已选根目录、文件定位 → 稳定身份与本机路径 | 本机文件系统；不决定远端授权 |
| ReferenceResolver | 源文档快照、项目范围 → 引用边、附件、歧义/缺失诊断 | Markdown AST 和纯路径解析；不写文件、不联网、不创建缺失文档 |
| SharePublisher | 经 owner 确认的集合、精确快照 → 已提交 manifest 版本 | 云端 API；不能发布预览以外的新成员 |
| CollaborationService | 认证主体、操作、版本前置条件 → revision 或明确拒绝 | CDR Core、服务端 Authorizer、Repository；不采信载荷自报身份 |
| ProjectSync | 共同基线、本机快照、共享 revision → 差异、合并或冲突 | 本机写入与恢复日志；不直接写共享 HTML 或 Vault 镜像 |
| BrowserEditor | 授权快照、媒体解析器、操作传输 → 编辑操作与界面状态 | Editor Kit v2 的环境适配；不调用 Tauri/Vault API |

首版沿用 CDR 的版本与操作概念，不在本 Spec 冻结外部公开 SDK。所有远端变更命令必须携带幂等 requestId，正文变更同时携带版本前置条件；响应只在持久化结果确定后声明成功。

### 3.2 用户流程

1. owner 在原项目文档上选择“共享文档及引用…”，首次选择或确认项目根目录。
2. 应用先落盘入口的未保存修改，再收集引用；预览显示清单、解析问题、整篇分享说明及权限，owner 可排除文档。
3. owner 确认清单后创建空间并获得链接/邀请；应用显示实际发布的文档、附件数量与版本。
4. 接收者兑换邀请，按权限沿链接阅读、选择文字讨论或编辑；编辑提交成功后显示“已保存到共享空间”。
5. owner 在本机看到待接收文档和差异，逐文档接收；本机有修改时先合并，冲突时保留两侧。
6. owner 可再次同步原项目修改、确认加入新的引用成员，或撤销访客访问；这些动作分别留痕。

## 4. 引用发现与发布范围

从一个或多个入口出发，在用户选定的项目根内递归解析本地文档引用，收集附件，按文件身份去重并终止循环。目录只定义可发现边界，不等于全部发布。

必须用专门的 Markdown AST 提取与纯路径解析器；覆盖普通链接、引用式链接、Wikilink、标题 fragment、图片及附件。代码块和行内代码中的伪链接不能算依赖。不能使用会创建缺失文件的点击处理器，也不能用仅索引部分 `.note.md` / wiki/daily 的反链索引。

现有 RichEditor 与 Outline 的 Wikilink 解析不同。首版相对/显式路径按源目录定位；裸标题或两种语义冲突必须展示候选并记录明确解析结果，不能在服务器上重新猜文件。

发布预览逐项显示：入口、发现的引用、引用来源、文档数量、附件、未解析链接及实际权限。发布前检查快照 hash 未变；变更则重新计算差异。上传完所有对象后才切换空间 manifest，不能让接收者读到缺页的一半发布物。

边界规则：

- 项目外引用、系统绝对路径与软链越界列为待处理；用户明确加入指定文件后才发布，不顺带扫描外部整个目录。
- 外部 HTTP 链接保持外链，不递归抓取网站。
- 默认排除凭据、控制目录和未明确允许的隐藏文件；排除项即使被引用也不能自动进入。
- 引用一个标题或段落默认会分享该文档全文，必须在预览说明；摘录分享是不同能力，不在首版内。
- 排除某文档时，显示“未共享引用”，不输出本机绝对路径、被排除文档摘要或其名称等额外元信息。
- 深度/数量达到护栏时明确提示集合未完整，不静默截断后显示分享完成。
- 新增引用只产生待加入成员，不自动扩权；删除引用也不自动销毁已有文档和讨论，成员移除由 owner 决定。
- 首版不宣称支持完整 `![[...]]` 文档嵌入或 `((id))` 跨文档块导航；需另行解析并验证。

原 Markdown 保留项目内相对链接；共享网页通过已确认引用边转换为 `/s/{spaceId}/d/{documentId}#fragment`，资源通过受控 assetId 地址提供。URL 重写只在渲染/传输适配层，不能把网页路由回写到项目。

源文档中的绝对本机引用在上传前转换为逻辑文档/附件引用，逆向映射只留在本机；不能上传原始绝对路径后仅在 HTML 隐藏。共同基线保存原始源表示与传输表示的对应关系。项目外明确加入的文件分配独立逻辑路径，不用真实 `../` 路径突破项目边界。

## 5. 阅读、标注与编辑权限

空间提供 viewer / commenter / editor，分别具有 read、read+comment、read+comment+edit；owner 负责成员、权限和同步决定。每篇文档另有 read/comment/edit 上限，最终能力取角色与文档上限的交集；无 read 时正文、附件、讨论、历史和元信息均不可见。默认引用材料只读，入口权限由 owner 明确选择；首次分享显示清楚，可选择整个集合允许编辑。首版不做块级 ACL。

匿名链接仅用于 owner 明确选择的只读访问。标注和编辑使用受邀身份；首版每位邀请对象使用独立的一次性、有限期邀请，兑换后创建服务端 guest actor 和会话。作者身份绑定该会话，昵称不构成身份；持有邀请即有兑换能力，首版不宣称已验证其邮箱或真实姓名。owner 可以撤销 guest grant。所有读取、写入、订阅、历史和附件请求都在服务端校验空间及成员权限；不能向浏览器发作者 API key 或旧 edit_token。

新空间附件必须经授权读取，不能直接沿用现有公开 `/f/` 路径。撤销时拒绝后续请求并终止对应活动会话；受保护内容不进入公共缓存。已下载内容无法收回，产品只承诺撤销服务访问。

## 6. 标注模型

批注独立于正文存储，锚点包含 documentId、blockId、目标 revision、选中文本与前后文，可附范围位置。支持回复、解决、重开及作者留痕；commenter 不需要正文写权限。

编辑后用块身份与上下文重新定位；只能返回 resolved / ambiguous / orphaned。不能唯一定位时保留原文快照并提示待定位，不能把评论静默挂到相似文字。已有 CriticMarkup 可以作为导入/导出表示，不能充当多人讨论数据库。现有个人 `.note.md` 不随分享自动公开。

## 7. 共享编辑与本地回写

必须区分两件事：远端“已保存”表示共享 revision 已提交；“已同步到项目”表示本机源文件写入完成。主人电脑离线时，浏览器编辑和讨论仍正常工作，项目同步显示待接收。

首版复用 CDR Core 的 OperationBatch / blockRevision 和幂等 requestId，服务端提交后再 ack。不同块可独立提交；同块基线过期明确冲突并保留草稿，不最后写入者覆盖。这可以实现多人先后编辑与提交式并发，不等于同段实时协同。

需要为普通项目文档新增 Profile 和 Repository Adapter；Host Repository v2 已是通用的本机存储边界，但当前限定 Vault，不能原样复用该绑定或 Memory Profile，也不能要求 Memory 的 projection/批准语义成为项目编辑前提。Editor Kit 的读资源、身份、提交与订阅改为注入适配器，浏览器不依赖 Tauri 或 Vault API。

Project Sync 保存共同基线 B、本机源 L、共享版本 C：

| 状态 | 行为 |
| --- | --- |
| 仅 L 改变 | 形成相对共同基线的本地修改，按共享 head 前置条件提交；head 变了则重新合并 |
| 仅 C 改变 | 显示待接收差异；首版由 owner 接收后写回原项目路径 |
| L、C 都改变 | 尝试三方合并；同处冲突保留两侧并展示，不能静默覆盖 |
| 源文件缺失/改名不明 | 停止对该文件回写并要求重绑，不自动在旧路径重建 |

三方合并基于保留本地链接语义的规范内容，不基于 HTML 或镜像里重写后的图片 URL。任意现有 Markdown 的往返保真必须先做 spike：不支持的结构明确只读或冲突，不允许保存一次就批量改写无关语法。外部编辑先识别 drift 再形成受控导入。

本机写入前重验源 hash，使用恢复 journal、临时文件和备份；写后推进基线。云端成功、本机失败应保留可重试状态，同一 requestId 不重复应用。文件系统对不合作的外部 writer 不天然提供通用原子 CAS，不能把一次 hash 检查与 rename 宣称为完全解决竞争；首版显式接收、协调已打开编辑器并检测后续 drift，具体支持边界需在实现 ADR 冻结。

多文件普通正文可逐文档推进同步；路径改名与引用改写需要单独的可恢复事务。首版不允许访客远端重命名、删除项目文件或创建任意路径，避免伪装成已实现目录级原子同步。

已有源→Vault save-push 仍可从最终落盘源文件派生更新；云端更新不得直接写 Vault 镜像并期待现有 Sync 反向传播。

### 7.1 错误处理与用户可见结果

| 情况 | 必须行为 |
| --- | --- |
| 入口未成功落盘、文件读取失败 | 阻断发布并定位失败项，不能分享旧磁盘版本冒充当前内容 |
| 引用歧义或缺失 | owner 明确选择候选或接受“未共享引用”后才允许发布；不猜测或偷偷补建文件 |
| 上传部分失败、响应丢失 | 旧 manifest 继续可读；使用相同 requestId 查询/重试，不产生重复空间或成员 |
| 同块版本过期 | 返回冲突，保留访客草稿，展示当前共享版本；不能自动全文覆盖 |
| 浏览器提交时离线 | 显示未保存并保留当前会话草稿；恢复连接后重验权限和版本再提交，不承诺离线重开恢复 |
| 本机回写失败或进程退出 | 共享版本保留，源文件保持可恢复，重开可查询 journal 并重试；不能提前推进同步基线 |
| 访问过期或被撤销 | 停止读取/提交/订阅；保留未提交草稿供用户复制，不泄露之后的远端内容 |

重试结果未知时不能同时显示成功与失败；必须查询已有回执或保持“结果待确认”，确认前不启动依赖该结果的下一次同步。

## 8. 云端落点

沿用现有 Cloudflare 部署体系，新增协作 API 与存储命名空间，保留旧 `/publish` 静态分享。

- Worker：认证、邀请兑换、页面/API 入口、受控资源读取。
- 一个 ShareSpace 对应一个 SQLite-backed Durable Object：首版统一成员、manifest、共享 head、批注、提交回执与通知，避免跨对象授权事务。
- R2：私有附件及大快照；先上传不可变对象，再事务提交其引用。未引用对象可后续回收，不将 R2 与 DO 宣称为同一原子事务。
- KV：旧 HTML 分享和非权威缓存；不存协作 head、决定性权限或评论权威。

依据：Cloudflare KV 是最终一致且不适合原子读改写；Durable Objects 提供强一致协调与事务存储。此选择是结合现有部署的架构建议，不代表仓库已经实现。

无需首版同时引入 D1、独立消息队列或按文档分片；在真实空间规模成为瓶颈后再拆。

## 9. 实施切片与验收

1. **项目分享集合**：ProjectBinding、纯引用解析、manifest 预览、稳定 ID、多页阅读与私有附件。验证 Vault 外、无 Vault、循环引用、同名文件、越界、排除与 fragment。
2. **完整协作首版**：身份/权限、独立批注、CDR 提交式编辑、本机接收/三方合并/恢复。必须跑中文 IME、Markdown 保真、同块并发、离线待接收、源漂移、失败重试、撤销后活动连接与附件访问等验收，才称为满足本次完整需求。
3. **按体验要求接入实时协作**：若要求同段同时输入、光标与离线合并，使用既定 Yjs Binding，并独立 ADR 定义 CRDT 持久状态、CDR revision 与 Markdown 导出关系。权限与历史仍走服务端受控通道；不能把块 CAS 冒充 CRDT。

第一切片只交付阅读，不等于完整任务完成；第二切片包含本次要求的标注和编辑。第三切片是否属于首发取决于“编辑”是否要求逐字实时协同，不影响前两层边界。

### 9.1 完整首版验收矩阵

| 闸门 | 可验证结果 |
| --- | --- |

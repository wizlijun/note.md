# 项目文档分享：Local-first、静态镜像与轻量收件

日期：2026-10-10。状态：待用户审阅的修订 Spec；未实现。

流程：Superpowers 6.3.0 / brainstorming / architectural。用户要求本地优先、减少服务和数据库，并明确需要自动回传、可接受一个轻量收件接口。本版替代之前的云端 ShareSpace / Durable Object 方案；审阅通过后再编写实施计划。

## 1. 需求、约束与成功标准

从任意项目目录的一篇或多篇 Markdown 发起分享，将引用文档与附件一起交给他人；接收者可通过浏览器阅读、标注和编辑。项目可以在 Vault 外，原目录继续用于 Git、IDE 和 Agent。

约束：本机维护正文和 ShareSpace；线上只发布本机生成的静态镜像。自动回传复用现有 Worker，把不可变修改包放入 R2 收件箱；不新增云端协作数据库、成员数据库或常驻服务。

成功标准：

- 无 Vault 的项目也能分享，引用可跳转，未选择的内容不上传。
- 访客在浏览器本地编辑和标注，确认提交后自动回传，无需手动转发文件。
- owner 电脑离线时，静态阅读与收件仍可用；owner 上线后可拉取、审阅和合并。
- 收件成功不改变线上正文；owner 本机合并并重新发布后，其他读者看到新快照。
- 重复提交不重复应用，同处冲突不静默覆盖，不把他人的修改丢失在重新发布中。

“编辑”在本版指编辑个人草稿并提交修改包。不是共享云端 head，也不是多人实时输入；这一变化必须在产品说明和界面中可见。

## 2. 方案比较与首版范围

| 方案 | 维护成本与行为 | 决策 |
| --- | --- | --- |
| 本地权威 + 静态镜像 + 现有 Worker/R2 收件箱 | 自动回传；本机审阅合并；无新增协作数据库 | 采用，符合用户澄清 |
| 完全静态 + 修改包手动返还 | 没有收件 API，但需要邮件/微信返还 | 仅作故障时导出备份，不作主流程 |
| 云端正文/成员库 + 实时会话 | 能直接共同修改云端正文，但增加状态与运维 | 不采用 |

首版包含：项目绑定、引用闭包、发布预览、静态多文档阅读、浏览器本地草稿、独立标注、能力链接、自动回传、本机收件/审阅/合并、重新发布及撤回。

非目标：实时共同编辑、访客互看未合并草稿、云端自动合并、账户/邮箱认证、逐人立即撤权、任意文件增删改名、跨空间自动合并、摘录级读取权限、全目录同步、公开 SDK、Yjs、DO/D1/消息队列。既有阅读统计 DO 不作为新功能依赖，本轮不重构它。

默认行为：入口权限由 owner 选择，引用材料只读；所有获知阅读链接者可读同一快照；编辑/标注分别由收件能力约束。访客显式点击“提交修改”自动回传，输入过程只保存浏览器本地草稿。本机默认审阅后合并；发布由 owner 明确触发。

## 3. 现有代码与新增边界

当前单篇 Vault 外分享：配置 Vault/分享服务 → 保存源文件 → 建立或更新 Vault 镜像 → 从源文件 tab 烘焙 HTML → POST /publish → KV 静态页面 → 本机记录 slug/edit_token。再次分享更新原链接；保存源文件只维护 Vault 镜像，不自动刷新网页。

| 已有能力 | 依据与限制 |
| --- | --- |
| 外部文件归位与原件编辑 | `src/lib/share/index.ts:73`；要求 Vault，新增项目入口需解除这一前置条件 |
| 单文件镜像 | `src-tauri/src/sotvault/mod.rs:503`；扁平化日期 basename，不遍历普通文档引用，无反向正文回写 |
| 静态 HTML 发布 | `src/lib/share/publish.ts:49`；Worker 的 `/publish`，HTML 上限 25 MiB，默认 TTL 7 天 |
| 图片处理 | `src/lib/plugins/share-baker.ts` 与 `host-render-html.ts`；内嵌图片不等于项目引用打包 |
| 本机分享记录 | `src/lib/share/records.ts`；按绝对路径记链接，不是稳定项目身份 |
| CDR / Editor Kit v2 | 有块 ID、版本、操作和草稿接口；浏览器资源读取与项目 Repository 仍需适配 |

本轮不修改既有单篇 Share/Sync 行为。新增项目分享复用渲染、发布认证和编辑内核，新增引用打包、静态快照、轻量收件与本机合并。当前上传端只接收 HTML/媒体，不能声称已有项目快照/修改包 API。

## 4. 权威、存储与组件

```
本机项目源文件 + ShareSpace
    │ 打包、明确发布
    ▼
线上静态快照 ──读取──► 访客浏览器本地草稿
                            │ 确认提交，自动回传
                            ▼
                      现有 Worker 收件接口
                            │ 不可变文件
                            ▼
                         R2 私有收件箱
                            │ 本机拉取
                            ▼
本机审阅、合并回源文件 ──重新发布──► 新静态快照
```

| 数据 | 权威与落点 |
| --- | --- |
| Markdown 正文 | 原项目文件；不迁移到 Vault，也不以 HTML 反推正文 |
| ProjectBinding | 项目 `.notemd/project.json`：projectId、documentId、相对路径与绑定信息 |
| ShareSpace / 发布基线 / 合并决定 | 本地 `.notemd/share-spaces/{spaceId}/` 的文件，无须 SQLite 服务 |
| 访客未提交修改 | 浏览器本地 IndexedDB；按 origin/spaceId/snapshotId/草稿 ID 隔离 |
| 静态镜像 | 现有 R2 的专用前缀；由本机生成，云端只存储和分发字节 |
| 已回传修改包 | 同一 R2 的私有 inbox 前缀；是投递缓冲，不是正文或讨论权威 |
| 读者账户、在线共同正文、共享 cursor | 不建立 |

项目只读或不愿写 `.notemd` 时，显式将整个项目描述与 ShareSpace 放到应用本机状态目录；只保留一个选定来源，不另造第二份可写账本。设备绝对根路径与发布凭据留在本机，不进入快照。项目整体复制需显式选择重绑原身份或复制为新项目，不能以内容 hash 自动决定。

建议本地布局：

```
.notemd/
  project.json
  share-spaces/{spaceId}/
    space.json
    snapshots/{snapshotId}/
      public/                 # 唯一允许上传的文件集合
      local-base/             # 原始基线与路径逆向映射，绝不上传
    inbox/{grantId}/{submissionId}.json # 已验证的收件原包
    decisions/{grantId}/{submissionId}.json
    journal/                  # 发布、合并和恢复记录
```

space.json 记录入口/已批准文档和附件、权限上限、目标 URL、当前发布快照、收件 epoch、过期时间和最后确认回执。它维护分享生命周期，不维护另一份当前正文。合并后的正文回到原项目文件，下一次快照从这些文件重新生成。

组件边界：ReferenceResolver 只读解析；SnapshotBuilder 生成静态产物；Publisher 上传和切换镜像；InboxTransport 只投递/拉取文件；LocalReview 在本机执行幂等审阅与合并。Editor Kit 注入本地资源解析和草稿适配器，不依赖 Tauri/Vault API；不建设通用同步平台。

## 5. 引用集合与静态发布

从入口递归发现本地引用、按稳定 documentId 去重并终止循环。覆盖普通/引用式 Markdown 链接、Wikilink、标题 fragment、图片与附件；代码中的伪链接不算引用。使用纯解析器，不能调用会创建缺失文件的点击处理器或仅覆盖部分文件的反链索引。

RichEditor 与 Outline 的 Wikilink 语义已有差异：显式相对路径按源目录定位，裸标题或同名歧义需展示候选并记录选择。跨项目根、绝对路径与软链越界须单独确认；外链不递归抓取；控制目录、凭据与未允许的隐藏文件不自动加入。

预览显示实际文档/附件、引用来源、未解决项与权限。引用某个标题默认分享整篇，需明确说明。被排除引用显示“未共享引用”，不额外输出私有路径或摘要。新增引用不自动扩大范围；移除引用也不自动删除本地讨论历史。

快照包含 schemaVersion、spaceId、snapshotId、允许文档/资源、内容 hash、链接映射、文档能力上限和必要的已合并公开批注。网页链接解析到静态快照内的 documentId；原项目保持普通相对链接。本机绝对路径在上传前转换为逻辑引用，逆向映射只留 local-base；个人 `.note.md` 默认不公开。

云端对象示意：

```
mirror/{spaceId}/index.json              # 本机生成的静态发布索引
mirror/{spaceId}/{snapshotId}/manifest.json
mirror/{spaceId}/{snapshotId}/index.html
mirror/{spaceId}/{snapshotId}/docs/...
mirror/{spaceId}/{snapshotId}/assets/...
inbox/{spaceId}/{grantId}/{submissionId}.json  # 非公开
```

先上传完整且不可变的快照，核对 manifest 和必要对象，再条件更新静态 index.json。索引指向完整旧版或完整新版；访客页面固定 snapshotId，不因 owner 重新发布而替换其草稿基线。已有读者明确刷新后才切换快照。

index.json 是本地 space.json 的发布投影，含当前 snapshotId、inboxEpoch、过期时间与收件开关，不是云端自行维护的空间数据库。更新按对象 ETag 前置条件执行；另一发布者已更新时拒绝覆盖，先回读处理。旧 KV HTML 页面可以继续作为旧分享入口，但新空间的状态/收件判定不依赖 KV 缓存。

本地 SnapshotBuilder 和新静态上传路径需明确大小护栏，达到上限不能静默丢文档；不能直接假定现有 25 MiB 单 HTML 发布接口可容纳任意项目。

## 6. 自动回传：一个轻量收件接口

部署仍只有现有 Worker。新增投递与 owner 拉取能力，复用现有 R2 binding 的隔离前缀；不增加 DO、D1、账号服务、队列、WebSocket 或定时同步服务。

| 接口职责 | 合同 |
| --- | --- |
| 访客 POST 提交修改包 | 校验能力、基线、文档范围与大小，写入一个不可变 R2 对象，返回确定的持久化回执 |
| owner 列出/下载收件 | 使用本机发布凭据及空间维护凭证，按空间前缀分页读取；访客不可调用 |
| owner 本地归档收件 | 本机持久化原包及审阅决定，按决定隐藏已处理项；云端原包保留至整个空间彻底清理 |
| 发布与能力签发 | 复用现有 owner 认证；能力仅用于投递，签发不写成员数据库 |

收件能力是 Worker 签名的有限期 bearer token，绑定 spaceId、grantId、inboxEpoch、允许动作/文档与大小上限。签名 secret 留在 Worker，owner 发布凭据不发送给访客。每个邀请可签发独立 grantId，但不宣称验证了真实姓名/邮箱，也不宣称具有账户级个人身份。

读者通过 URL fragment 获得投递能力，页面读取后只在提交请求头中发送；不放在静态对象内容或普通查询日志中。只有阅读链接者可以阅读同一快照；只读链接不包含投递能力。服务端必须独立校验 commenter 不能提交正文替换、editor 仅能提交允许文档，不能靠隐藏按钮实现限制。

对尚未存在的新投递，读取 R2 的静态发布索引与目标基线 manifest，验证仍开放、未过期、epoch 一致、snapshot 存在、目标属于分享集合，并求交 token 能力与文档上限。此检查不使用 CDN/KV 缓存。正文替换的首版是有基线的 after Markdown，不是远端执行文件操作；附件增删和任意文件路径写入均不接受。

修改包最小字段：schemaVersion、submissionId、spaceId、baseSnapshotId、修改文档的 documentId/baseHash/afterMarkdown，以及独立 annotation 变化。grantId 和 receivedAt 由服务器根据能力和服务器时间写入可信信封；昵称及客户端时间仅作自报展示。默认请求体上限 5 MiB，超限保留草稿并提示，不能截断后成功。

包内容 hash 由收件接口计算；服务端信封的首次 receivedAt 不参与请求内容 hash。包以固定 space/grant/submission 对象键条件创建：同 ID 同内容 hash 重试返回同一回执；同 ID 异内容返回冲突；禁止先 HEAD 再无条件 PUT 冒充原子去重。只在 R2 写入确定后回复“已送达”；响应未知时保留相同 ID 重试。云端不执行合并、不改正文、不维护 accepted/rejected 字段，也不向其他访客提供收件列表。

已有提交的回执确认与新投递分开：先校验签名、space/grant/submission 绑定和请求内容 hash，若不可变原包已存在，只返回该邀请自己的原始投递回执；这种确认不因能力过期、epoch 变化或镜像撤回而失效，也不向访客返回包正文。只有不存在时才执行当前开放状态/过期/epoch 校验并尝试新写入。全服务签名 secret 更换导致旧签名无法验证属于凭据失效，浏览器保留草稿并提示导出，不能伪造“未送达”。

不可变原包同时占据去重键并保存原始回执，首版不提供逐包云端删除或压缩；本机归档不会释放云端去重键，也不写云端审阅状态。所有云端原包保留至 owner 显式彻底清理整个空间，避免归档与重试并发时重新创建同一提交。客户端确认和本机收件均按复合身份处理。彻底清理会明确结束云端回执确认承诺，spaceId 永久退役，不在旧 ID 上重新创建空间。

本机打开空间或执行“检查反馈”时分页拉取，先验证并保存原包，再推进本地已下载标记。列表 cursor 仅用于一轮分页，不作为永久水位；后续重新扫描并按 spaceId/grantId/submissionId 复合身份去重，避免遗漏乱序到达文件或不同邀请间 ID 冲突。首版不需要后台常驻进程。

## 7. 浏览器草稿、标注与本机合并

浏览器保存的是个人草稿。按稳定基线将选择、正文和批注保存到 IndexedDB；只有本地持久化确认后显示“草稿已保存”，清除网站数据/隐私模式不保证保留，始终提供导出备份。

状态必须区分：草稿已保存 → 提交中 → 已送达 owner → 等待本机审阅。没有查询审阅状态的访客 API；“已送达”不得变成“已合并”。owner 重新发布后页面可提示有新快照，访客选择刷新或保留旧草稿；不悄悄重设基线。

快照正文、批注和修改包都是待呈现的数据，不能作为页面脚本执行；静态渲染需净化不可信 HTML、转义讨论内容并设置合适 CSP，避免分享正文获取 URL fragment 中的投递能力。外部内容不能调用 owner 发布或收件读取接口。

标注是独立记录，包含 thread/annotation ID、documentId、baseSnapshotId、块 ID（若可用）、选中文本及前后文、回复与状态；不把个人批注写进正文。唯一定位成功才挂回新内容，否则保留原选文并标 ambiguous/orphaned。访客只看到当前公开快照的批注及自己的草稿，不看到其他人的未合并讨论。

owner 拉取后在本机审阅：

| 对象/状态 | 本机行为 |
| --- | --- |
| 正文，源文件等于包的基线 | 展示差异，接受后写回原路径 |
| 正文，源文件已变化 | 用该包基线 B、本机当前 L、访客 after V 三方合并；同处冲突保留两侧 |
| 标注/回复 | 验证目标与能力，接受后保存本地批注记录；不授予作者批准其他包的权限 |
| 重复包 | 读取持久决定，不重复应用、不重复创建批注 |
| 基线缺失、包被篡改或目标不属于快照 | 隔离并提示；不能把自报基线或任意本机路径作为可信目标 |
| 源文件移动/缺失 | 明确重绑；不在旧位置自动新建或写入其他同名文件 |

先验证基线 hash、schema 与允许操作，再生成候选；接受时重验本机内容。合并只作用于可信 ProjectBinding 映射的文档，包内不携带可执行路径。上传前转换的逻辑链接须受控还原；未编辑 Markdown 保持原有语义和尽可能精确的字节，不能用网页 HTML 回灌。

本机保存原包、差异、决定、结果 hash 与恢复 journal；原文件写入和决定形成可恢复提交。崩溃后根据 journal/结果 hash 分辨已写入或尚未应用，不能在已改正文后丢失去重记录。任意外部 writer 不天然具有文件系统原子 CAS；协调应用内已打开编辑器并检测 drift，不能宣称 hash 检查加 rename 已解决所有外部竞争。

已合并批注是否公开由 owner 在发布预览选择，默认只发布 owner 明确选择的讨论。已有源→Vault 镜像仍可从合并后的源文件派生更新，不作为反向协作通道。

## 8. ShareSpace 生命周期：本机维护

ShareSpace 保存在第 4 节的本地目录，由 note.md 的“项目分享”入口维护。Worker 只有发布投影和文件收件，不运行云端空间状态机。

| 本机状态 | 含义与动作 |
| --- | --- |
| draft | 尚未发布；仅在本机修改范围和设置 |
| published | 最后一次远端回读确认索引指向指定快照，显示确认时间；不能据此宣称远端永远在线 |
| withdrawn | 撤回远端索引/镜像并核验；新投递不再通过 |
| archived | 本机停止维护，保留快照、收件和决定；若远端仍开放，先完成撤回再进入 |

发布/撤回请求处于 pending 或 outcome-unknown 时单独显示待执行/结果待确认，不能提前进入已发布/已撤回。主人离线仍可编辑本地，但撤回必须联网完成才对线上生效。

停止收件可由 owner 发布 inboxEnabled=false 或更新 inboxEpoch；全空间旧能力失效，新能力重新签发。首版不维护逐人撤销列表，不承诺撤销单个访客后其他人的旧 token 继续有效。发布新正文不必改变 epoch，允许对旧快照的合法提交在本机三方合并。

收件接口验证过期时间；超期拒绝新投递。只读静态镜像的撤回/过期需 Worker 静态路由直接核验索引元数据，并避免受控入口和资源的公共缓存，不能仅靠前端隐藏、KV TTL 或 CDN 缓存到期保证撤回。正文响应仍是预生成字节，没有服务器编辑或个性化计算。已经下载的页面、浏览器草稿无法收回。

撤回与在途请求之间没有跨对象事务：已通过检查的请求可能在撤回后完成投递；本机标记为在途反馈，仍经 owner 审阅。撤回不能删除已送达包。不得承诺线性一致的全空间撤权。

删除本地绑定不删除远端或原文件；界面明确展示尚未撤回的远端链接。彻底删除分享须先核验撤回、归档未处理收件，再显式清理云端前缀；不删除项目源文件。全部云端收件原包保留至整个空间彻底清理，本机归档不触发云端删除；首版不引入定时垃圾回收服务。所有成功发布过的快照 manifest、合并所需的规范基线和本机 local-base 在首版保留至整个空间彻底清理；不能因为它不再是当前快照、尚未收到反馈，就删除仍可能被访客草稿引用的基线。未成功发布的孤立上传对象可以显式清理。彻底清理前显示尚未提交的草稿将失去原基线/投递能力，终止空间并永久退役其 ID；已经拉到本机的原包和决定默认保留归档。

## 9. 错误处理与交付切片

| 情况 | 必须结果 |
| --- | --- |
| 源未落盘、引用歧义、范围快照变动 | 阻断或重新预览，不能发布旧内容冒充当前 |
| 部分上传失败/索引更新失败 | 旧完整快照继续可读；重试相同 snapshot，仅未成功发布的孤立对象可后续清理 |
| 投递失败/离线/响应未知 | 草稿保留，状态准确，使用同一提交 ID 重试；可导出备份 |
| token 过期/epoch 变化 | 拒绝新投递，已有投递仍可确认原回执；草稿保留，需要时提示获取新能力 |
| owner 离线 | 页面和收件继续；不显示本机已收到或已合并 |
| 合并冲突/回写失败/进程退出 | 两侧内容保留，基线与去重记录可恢复，不能虚假“已应用” |

实施按三个纵向切片推进：

1. 本机 ProjectBinding/ShareSpace、引用预览、静态快照与重新发布。
2. 浏览器草稿和标注、签名收件能力、Worker/R2 不可变投递、本机收件。
3. 本机审阅/三方合并/恢复、公开批注选择、撤回与完整验收。

三片完成后才满足本次完整需求。此处仅定义设计切片，不是已批准实施计划。

## 10. 验收矩阵与自审

| 闸门 | 可验证结果 |
| --- | --- |
| G1 本地权威 | 无 Vault、项目只读兜底、项目移动重绑通过；只有原文件是当前正文权威，静态镜像与收件不自动改正文 |
| G2 引用集合 | 普通/引用式链接、Wikilink、fragment、附件正确；循环/同名/越界/排除/代码伪链接不导致错发或泄漏 |
| G3 发布 | 完整上传后切索引，失败仍读旧版；访客草稿固定基线；无绝对本机路径或 local-base 上传 |
| G4 能力边界 | 无 token 不能投递；commenter 不改正文；token/manifest 的文档限制生效；访客不能列/读 inbox、签发 token 或发布镜像 |
| G5 自动回传 | owner 离线仍可持久收件；同 ID 同内容去重、异内容拒绝、并发条件创建与网络重试通过；丢响应后撤回/过期仍可确认已有回执；本机归档与重试并发不删除云端去重键、原回执不变；分页扫描无丢件 |
| G6 浏览器本地编辑 | IndexedDB 失败不显示已保存；中文/日文 IME、跨块编辑、undo、重开恢复、旧草稿遇新快照、导出备份通过 |
| G7 标注 | 原文变动后锚点正确或明确失联；作者能力与自报昵称分开；其他访客看不到未合并批注 |
| G8 合并 | 同/异基线、双边同处/异处变化符合三方规则；不信任自报路径/基线；应用后崩溃、重复包和外部 drift 可恢复 |
| G9 生命周期 | 本机驱动发布/撤回；离线撤回显示待执行；旧 epoch/过期拒收；在途竞态不被误称绝对撤权；所有云端收件原包及成功发布过的基线保留至整空间清理，旧快照草稿仍可合法提交 |
| G10 维护成本 | 复用现有 Worker/R2；新增功能不依赖 DO/D1、账号库、队列、WebSocket 或常驻/定时任务 |

自动化覆盖纯引用解析、能力检查、条件创建、包校验、合并和恢复。真实浏览器验收草稿持久化、IME、选区、断网提交与新版快照切换；本机端到端核验原项目回写。既有单文件 Share/Sync 回归保持通过。

场景：方案引用调研，调研反向引用方案，另有图片；得到两篇文档和图片。A、B 从相同快照分别提交：在线静态正文不变，owner 依次审阅，两包异处修改可合并，同处修改明确冲突，重新发布后双方看到新快照。owner 全程离线时两包仍能回传，之后分页拉取不会漏件。

本版自审项：无云端正文/成员状态机；静态索引明确为发布投影；自动回传不等于自动合并；纯静态页面与一个轻量收件接口符合用户澄清。新功能尚未实现，所有 G1–G10 均为未来验收门禁，不能以既有测试代替。

技术依据（2026-10-10 查阅）：[R2 一致性与 CDN 缓存边界](https://developers.cloudflare.com/r2/reference/consistency/)、[R2 Workers 条件写入与分页 API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)。线上只需在既有部署内增加静态快照路径、发布维护和轻量收件代码，不新增服务或数据库产品。

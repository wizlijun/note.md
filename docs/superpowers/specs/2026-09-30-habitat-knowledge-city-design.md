# HABITAT · 心城：Vault 概念形成、结构与培育引擎

日期：2026-09-30。状态：本文保留早期产品设计与合成数据演示记录。后续已实现 HABITAT 源码开发版、真实 Vault 只读全量提取、2.5D Canvas 与专用 Git 历史接口；尚未发布，未实现完整 3D、规划编辑或真实调用车流。当前实现与验收以 [Vault 知识结构提取与演变历史 §11](2026-09-30-vault-knowledge-structure-extraction-design.md#11-源码实现与真实全量验收2026-09-30) 为准：先提取知识结构，再投影成城市；完整 JSONL 经标准 Zstandard 无损压缩为单个当前快照，Git 保存历史。本轮未向真实 Vault 写入结构或提交。

## 1. 核心体验

打开 Vault，看见一座属于自己的城市。用户知道 note.md 在哪里，记得上周那批新想法落在哪片空地，也能看见原本不相关的兴趣和工作之间，什么时候多出了一条路。

一句话：**给思考一个稳定地址，让组织、联系与投入逐渐可见。**

这里“与人脑对齐”是交互设计目标：用空间记忆、熟悉的生活用途、渐进形成、可追溯的演变减少理解负担，并非已获验证的神经科学模型。需要通过找回概念、理解关系和确认归属的用户任务验证。

它回答四个问题：我把注意力放在哪里；什么正在形成；什么已经有结构；哪里值得再做一点。养成感来自真实思考产生的变化，不设签到、金币、全城总等级或必须升级的终点。

## 2. 城市总图：用途和成熟度是两个轴

城市是一整块连续、可扩展的土地，采用可旋转的低多边形正交三维视角。区域边界像城市规划中的土地用途，有渐变和混合边缘，不是强制文件夹。

| 区域 | 容纳什么 | 视觉与生长方式 |
| --- | --- | --- |
| CBD · 事业区 | 赚钱、经营、产品、业务 | 宽街、稳定地标、预留用地的项目园区；hemory / note.md 按用户指定安置在此 |
| 公园 · 兴趣地 | 休闲、审美、好奇、非功利投入 | 大草地、稀疏帐篷、树荫、小亭；帐篷可以成为长期居所 |
| 生长地 · 未定街区 | 尚不能归类的材料、问题、观察 | 最大的连续预留地；材料堆、小棚、聚落、街巷逐渐形成 |
| 前沿 · 探索边界 | 用户主动追问的未知、尝试中的方向 | 勘察营地、朝外延伸的小径、待探访路标；只标已提出的问题，不凭空制造“你应该探索”的空缺 |

CBD 不吞并所有成熟概念。成熟的兴趣可以是公园里的工作室；非商业项目可以是探索区研究所。首版只需要上述四区，未来允许用户改名和调整用途，先不预制一整套人生分类。

一个概念有一个主地址，可关联多个用途。其他区域通过入口和交通相连，不复制另一份概念，避免同一内容被计数两次。

## 3. 视觉语义：每种变化都有解释

| 城市对象 | 意义 | 不意味着什么 |
| --- | --- | --- |
| 材料台 / 小棚 | 尚未归属的一个来源组或收集包 | 垃圾、低质量 |
| 一栋小屋 | 一个可命名、可回源的概念或问题 | 一篇文件、固定数量的字 |
| 一个街区 | 围绕共同问题组织的概念群 | 已经有项目承诺 |
| 一座规划园区 | 用户明确投入目标与行动的项目 | 资料多就自动升级 |
| 园区里的楼栋 | 项目的子问题、能力或工作流 | 每个标签各造一栋楼 |
| 层数 / 体量 | 有上限的组织丰富度，例如已确认子主题 | 智力、真理、收入、重要性总分 |
| 整齐庭院与公共空间 | 已命名、整理、建立边界的结构 | 观点正确、已经完成 |
| 灯光 / 局部车流 | 可验证的近期编辑、引用、应用 | 页面打开一次就获得经验值 |
| 安静建筑 | 最近没有观测到相关活动 | 失败、遗忘、应当拆掉 |

概览不尝试一文一屋：大量材料聚合为有计数的材料地块，缩放后再展开。几何细节、窗户和树是美术，不逐个暗示事实；对象详情明确显示真实来源组、概念和子主题数量。

概念详情始终包含：名字；用户或系统给出的归属；为何形成；原文依据及有效范围；待解问题；最近一次可验证变化。推测、用户确认和引文核对分别表达，不把“核对过引文”称为事实为真。

## 4. 生长不是单向升级树

主干是：收集材料 → 发现聚落 → 命名街区 → 持续培育。**规划为项目是一条由用户选择的分支**，可以从单个想法发起，也可以永远不发起。

1. **落地。** 新材料进入生长地的稳定收集地块。明确属于既有项目的材料，可以直接进入对应园区的入口材料台。同步或批量导入按来源组聚合，不瞬间盖出几万座房屋。
2. **结邻。** 词面或语义接近的材料被建议放在附近。一个小聚落的说明应是“这几份材料都在问个人记忆如何检索”，并附依据。相似度只能形成邻近候选，不能直接宣称有实体关系。
3. **命名。** 用户认可共同问题后，赋予稳定名称和主地址。只有一条有价值的想法也可以被用户立即命名；不设必须攒够文章的门槛。
4. **成街。** 用户概括、修订边界、补充反例、在新语境中使用，增加庭院、分出楼栋和内部秩序。新增重复材料不增加独立概念；自动摘要改善说明，不凭空增加成熟度。
5. **立项。** 用户指定目标、范围和一个下一步，查看改建预览后确认。原街区可原地改建为园区；只有用户希望搬迁，才迁入 CBD 或其他用途区，保留原址入口。
6. **分叉 / 归并 / 休眠。** 一个街区可以分成两个问题；两个街区可以共享一个新园区；长期不活跃只是安静。完成项目保留地标与成果，支持以后重新启用。

系统可以自动更新材料计数和候选聚落，不自动重命名已确认对象、不自动拆楼、不自动立项。命名、合并、拆分、改用途、规划等语义修改均可撤销，并保留演变记录。

## 5. 交通网络：为什么有路、路多宽、车多少

交通必须能点击回源，且有三个独立维度：

- **关系类型决定路径表达。** 明确引用、用户确认的关联、某次成果同时使用两地知识，可以成为实际道路；依赖用方向，争议用议题标记，不能统统解释为相互支持。纯相似度只影响邻近，建议联系用细虚线勘察路线。
- **长期联系决定道路等级。** 对同一对概念，按不同来源组及实际使用事件去重，分为朴素小径、支路、主干道。第一版使用固定分档，不随全库最大值重新归一化；分档参数属于待校准的设计参数，不作为科学分数。升级应跨过阈值后稳定观察，再局部拓宽，避免抖动。
- **近期使用决定车流。** 近期发生的跨概念引用、关联编辑或明确应用事件，形成车流。车流只表示当前时间窗口，不改变历史路宽。只有来源修改时间时，不能假装知道跨概念使用；显示“活动未接入”，车辆不生成。

保留用户提出的“联系越少，路越简陋”的直觉：少联系画窄土路或不连续铺装，多联系变为宽路。将真正破损、路障留给可确认的断链或撤回关系。单次但重要的联系依然可以是一条小径，路宽不做价值排名。

道路级别和车流默认正相关，因为反复使用会积累联系，但允许“很宽、很安静”的历史通道。演示的车辆是合成活动快照，不声称来自真实 Vault，也不靠循环装饰动画伪造繁荣。

概览只显示被选中对象的主要联系和少量跨区主干道；其余按方向聚合，放大后展开。路由沿已保留的交通走廊布线，交叉不等于有关联；没有关系的地面道路装饰不使用数据道路的样式。

## 6. 培育的五个动作

| 用户动作 | 知识变化 | 城市反馈 |
| --- | --- | --- |
| 给它名字 | 承认这是一个值得保留的概念 / 问题 | 路牌和稳定地址出现 |
| 整理一下 | 写一句概括、分清子主题、补条件与反例 | 凌乱聚落形成院落与街巷 |
| 用到别处 | 在具体决策、笔记或成果中引用 | 两处出现可追溯的小路与近期车辆 |
| 规划成项目 | 明确目标、范围、下一步 | 显示总图，确认后改建为有预留用地的园区 |
| 先放着 | 暂缓、保留、允许未定 | 保留位置，减少提醒；不会倒塌或扣分 |

“今天照料什么”按用户的未完成意图给最多三个建议，例如“这片街区有共同问题，是否命名”“这两处最近被一起用于设计，可建立联系”。不能用孤立、低活跃、少资料本身推断需要干预；用户可以永久关闭此类提示。

矛盾材料保留为同一议题的不同院落，打开时并列陈述者、条件和证据。更多争论可以丰富结构，不自动提高可信程度。

## 7. 具体城市的一天

**note.md / hemory。** 两个园区拥有各自总图与稳定地标。note.md 的编辑、插件和知识组织是不同楼栋；hemory 的采集、记忆和检索是另一组楼栋。二者因实际共同设计与引用形成跨园区主干道。新资料先入门口材料台，不按文件数让主楼无限长高。

**未知的材料。** 几次会议片段、阅读和想法进入生长地。“对话如何成为可用记忆”逐渐形成小聚落，用户命名后长成街区。用户可长期研究，也可提出一个检索实验，原地改建为园区；CBD 的两座地标保持原位。

**摄影兴趣。** 公园里的一顶帐篷几个月不动，仍然有名字和地址。用户把构图原则用于 note.md 城市视图，一条有出处的小径连到项目园区；摄影不因此被自动商业化。

**探索前沿。** 用户提出“如果只保留少量记忆，会发生什么”，形成探索营地。后续结果可能融入 hemory，也可能保留独立；未知空间表示尚未形成结构的余地，不预判缺失知识。

## 8. 空间与时间：保护用户已经记住的城市

区域、主干走廊、项目地块在初次总图后冻结。新概念优先进入邻近空地，满了向区域边缘扩展，不全局重排。每个正式概念使用独立 cityObjectId；文件路径、块位置和内容 hash 是可变化的来源版本。

用户固定的位置高于自动布局。未确认的候选可以在预留范围微调，正式街区不能无提示搬家。合并与拆分保存前后 ID 的继承关系，改名不改 ID。重新规划是显式操作，先展示差异；撤销恢复语义和布局。

时间回看使用同一城市坐标，显示当时建筑和关系。首版可从首次安装起记录演变，不能仅凭现有文件 mtime 编造过去的城市历史。若当时资料已被删除或撤权，历史视图同样不得泄露它。

## 9. 最小引擎契约

采用“语义状态 → 城市规则 → 稳定布局 → 可见场景”的单向投影；三维只是一个视图，将来俯视地图和可访问列表共享同一状态。

```text
Host index 元数据快照 / 原文核对 / 明确用户操作
  → 来源组与身份登记
  → 候选概念、带证据的关系、用户确认的概念与项目
  → 城市状态归约器（增量、可解释、可撤销）
  → 用途区域 + 固定地块 + 局部交通路由
  → LOD 场景包
  → 三维城市 / 二维俯视 / 列表 / 来源详情
```

建议新增的最小数据结构（提案，不是已有 API）：

```ts
type CityObject = {
  id: string;                   // 持久化身份，不用 contentHash 代替
  label: string;
  form: 'material' | 'cluster' | 'concept' | 'project';
  provenance: 'suggested' | 'user-confirmed';
  zoneId: string;               // 用途与 form 独立
  memberIds: string[];
  evidenceIds: string[];
  intent?: { goal: string; scope: string; nextStep: string };
  parcelId: string;
};
type CityRelation = {
  id: string; from: string; to: string;
  kind: 'reference' | 'applied-together' | 'depends-on' | 'disputes' | 'user-link' | 'suggested';
  evidenceIds: string[];
  lifecycle: 'active' | 'withdrawn' | 'source-missing';
};
type CityEvent = {
  id: string; at: string; objectIds: string[];
  kind: 'named' | 'organized' | 'applied' | 'planned' | 'merged' | 'split' | 'parked';
  actor: 'user' | 'system'; evidenceIds: string[];
};
```

cityObjectId、地块、来源映射、布局 epoch、用户覆盖和事件 revision 必须持久化。AI proposal 绑定输入快照和 baseRevision，用户确认时先检查过期；源改变导致待核对，不静默覆盖新编辑。确认后的概念保留名称与位置，已经失效的来源或引文撤下。

用户的命名、规划与固定地址是其知识资产，建议保存在 Vault 的 `.notemd/habitat/`（需生产实现明确版本、原子写入和跨设备冲突处理）；派生网格、GPU 缓存、候选布局缓存留在 plugin data_dir。首版单写者，检测 revision 冲突后重新预览，不做静默 last-write-wins。删除源或撤权必须清理正文缓存、快照显示及历史引用，不能用演变记录复活旧正文。

### 当前仓库可复用与缺口

- `host.index.*` 已提供元数据分页/冻结快照及按需来源读取；沿用宿主索引和权限，避免第二套全库扫描。实现见 `src-tauri/src/plugin_runtime/index_api.rs`、`plugin-protocol/src/index.rs`。
- STRATA 的 Worker atlas、稀疏候选邻接、来源核对、独立窗口及离线三维管线可参考。其当前节点身份依赖内容版本，稳定坐标只对同 ID 生效；城市须另建身份登记，不直接承诺原文变化后旧节点仍在。实现见 `plugins-src/strata/src/lib/atlas.ts`、`plugins-src/strata/backend/src/task.rs`。
- 现有关系来自受限抽取或词面候选，wiki 目标路径与节点 ID 还需城市适配层解析；不能把 lexical 邻接直接升级为道路。Knowledge Browser 的关系角色、方向、参与者与证据呈现可借鉴，不能把多元关系随意拆成全连接。
- 当前底座没有完整城市用途、项目意图、概念生命周期、跨来源稳定身份和跨概念应用事件。首次接入应坦诚展示候选覆盖；没有活动事件时关闭车流，不按文件数量编造交通。
- 不在本轮改动宿主、索引或现有 STRATA。生产上建议先实现独立 HABITAT 视图插件，只有经过验证的共用部分再抽取共享模块，避免复制两套来源安全与身份规则。

### 场景生成和渲染

首版生产渲染可沿用仓库随包离线构建的 Three.js。正交相机配有限俯仰、旋转和缩放；低模几何、实例化建筑 / 树 / 车辆、有限阴影，不使用物理交通模拟。算法在 Worker 中生成 parcel、building instance 和 road polyline，渲染层只消费场景包，不自己决定项目状态。

全景画区域和聚合体；中景画街区与主要楼栋；近景展示概念、道路证据与来源入口。按视口和 LOD 限制实例与标签；大量未知材料显示聚合地块。颜色+形状+文字共同编码；支持键盘列表、减少动态、二维降级。所有弹层沿用项目 `.menu-panel` / `.menu-row` 全局样式。

相机和日期变化不触发重新聚类。闲置时停止渲染循环；可观测活动的交通动画只在可见窗口内有界播放，减少动态时显示静态车辆。布局只在来源变化或用户规划时增量更新；暂停 / 重开不能丢失地址。

## 10. 分期和验收

**P0，本轮：** 本规格与合成数据三维交互演示。演示展现稳定 CBD、公园帐篷、开阔生长地、探索营地；切换三个发展状态，观察原地改建和道路变化；可旋转与选择对象。演示没有真实语义推断、文件修改、生产路由算法或历史回放。

**P1，可用城市：** 真实 index 元数据 → 材料地块与候选聚落 → 用户命名 / 放置 / 规划 → 重开后保留 → 点击来源。规划从首版起支持改建预览和本次操作撤销。先完成身份、归属和大 Vault 聚合，不启动自动 AI 全库提炼。无事件记录时不画车流。

**P2，可信生长：** 明确选择来源范围后提炼概念和关系；增量证据校验；跨项目关系解析；记录实际应用事件，开启交通；完整演变回看。

**P3，规模与认知验收：** 使用真实日期分布和真实量级索引，测试巨型聚类、未定材料远多于成熟项目、单点重要概念和跨域热点。以下是验收要求而非已实现承诺：

1. 相同快照重复载入地址不变；文件改名或改正文时可追踪身份，无法确认时请求归属而不悄悄合并。日期切换不搬地块。
2. 重复导入、镜像和同源 AI 摘要不增加独立证据体量。兴趣无活动时不降级；单想法可立项；巨量材料不能自动变项目。
3. 每条实路可回源；建议路有独立样式；长期强关系但近期零事件为宽路零车；断源关系可解释，撤权正文不可回看。
4. 规划需明确意图且可预览 / 撤销；合并拆分保留 lineage；保存冲突和中断不会部分迁移园区。

# 项目分享阅读页设计

日期：2026-10-10。状态：原设计已实现并发布6.1010.4；本次按用户明确纠正更新响应式布局要求。

## 1. 目标与已确认需求

项目分享继续使用本地 Sync 镜像、不可变发布快照、单 HTML 静态页面与现有 Worker 收件接口。不增加服务、数据库或线上正文权威。本轮只改变阅读呈现、文档导航及必要的发布元数据。

用户已确认：

- 正文沿用发布时应用当前选中的正文主题/皮肤，与单篇分享同源；实际当前选择为 Effie，但代码不得硬编码 Effie。
- 删除整块「note.md 项目分享」标题栏、固定说明、常驻状态信息及重复文件标题。保留 Markdown 本身的标题。
- 左侧文件栏默认收起，支持文件夹逐层展开，参考现有 Folder View 风格；文件按修改时间从新到旧排列。
- 分享时可设置分享标题，默认使用选中分享的入口文件名去掉 `.md`。frame 标题在分享标题后追加当前模式「只读 / 可编辑」。
- 已发布正文完整渲染图表；协作者修改后的草稿图表显示代码和提示，主人合入并重新发布后完整渲染。优先保持静态包极简。

成功标准是最终公开 HTML 中实际可读的正文、图表和公式，以及可用的文件导航和现有协作流程；宿主内可显示或 HTML 含 `<svg>` 都不足以证明完成。

## 2. 现状与方案选择

当前项目页在 `src/lib/project-share/bundle.ts` 内嵌裸 Marked，在 `browser.ts` 重新解析 Markdown。它没有当前主题、KaTeX、高亮与图表渲染链，而且 sanitizer 会整棵删除 SVG/MathML，并剥除 class/style。仅换 CSS 无法修复。

既有单篇分享通过 `computeActiveThemeId` 选模板，`share-baker.ts` 组合正文样式，`host-render-html.ts` 生成正文、公式和代码，`diagram-render.ts` 生成 Mermaid/DOT/Graphviz SVG。直接套用整个单篇分享页面会带入不需要的页头/页脚，并丢失项目导航和反馈；直接调用它的磁盘图片读取也会绕过项目批准范围。

选择：宿主从冻结快照预渲染所有已分享正文，打包当前模板与必要资源；浏览器负责展示、导航、本地草稿和反馈。相比在浏览器打包完整 Mermaid/Graphviz/WASM，引擎体积和 CSP 更小；相比再造一套静态 Markdown 渲染器，语义与应用保持一致。草稿完整图表即时预览不在本轮范围，用户已明确接受。

## 3. 阅读外壳与 Folder View 风格

### 3.1 直接正文

正文不设固定阅读宽度，随视口及侧栏剩余宽度自适应；分享页覆盖正文根节点的 width/max-width，当前主题的字体、颜色和正文内部样式保持生效。窄屏保持正常页边距，宽表格、公式、图表局部横向滚动，不撑宽整页。

不显示产品品牌、项目标题、路径、版本、snapshot ID、发布时间或解释性顶栏；分享标题只用于 frame/浏览器标题。单一展开/收起图标固定在侧栏右侧边缘，收起时回到视口左侧；按钮始终可见并提供动态 aria-label、title 和 aria-expanded。删除正文顶部工具栏容器，不为任何菜单预留高度；可编辑模式的协作按钮及按需操作状态放在页面底部轻量浮层，保持选文后直接标注，不藏进文件树。桌面侧栏展开占用实际宽度，手机仍为覆盖抽屉；跨窄屏断点同步遮罩状态。

### 3.2 默认折叠的文件树

直接参照 `src/components/FolderView.svelte` 和 `FolderTreeNode.svelte`：13px 紧凑行、14px 层级缩进、细线文件/文件夹图标、旋转展开箭头、浅灰悬停与明确选中态；深色使用相应灰度。它是持久导航，不能套用弹层菜单的蓝色 hover。

只派生 snapshot 中批准的 Markdown 路径及其祖先目录；不列未分享文件、空目录、宿主绝对路径或 Sync 管理目录。树不需要新的数据库或目录扫描。

- 每次进入页面文件栏默认收起，正文不预留空侧栏。
- 首次展开时仅展开当前文档的祖先目录，其他文件夹收起。点击文件夹行切换展开，点击文件行切换正文。
- 文件夹优先，与现有 Folder View 一致；同层文件按源文件修改时间降序；同层文件夹按已分享后代文件的最大修改时间降序。时间相同按名称、相对路径稳定排序；未知时间排在同类已知时间之后。
- 使用发布时冻结的源文件时间，不使用镜像复制时间、快照写入时间或草稿编辑时间。阅读初始文档仍是入口或有效深链接，不因排序切换到最新文件。
- 页面内保留目录展开状态；切文档时揭示当前项的祖先。桌面切换不强制关闭侧栏；手机采用覆盖抽屉，选文档后关闭、恢复合理焦点。Esc 关闭抽屉并回到触发按钮。
- 用按钮与嵌套列表实现可访问导航；展开按钮有 `aria-expanded`，当前文件有 `aria-current`，键盘可操作并有可见焦点。无需引入完整 ARIA tree 键盘框架。

不复制 Folder View 的上级目录、Finder、重命名、置顶、视图模式或排序菜单；本轮排序规则固定。

## 4. 分享标题与模式

在现有宿主分享界面增加一个「分享标题」文本框，初值为入口文件 basename 去掉末尾 Markdown 扩展名（至少 `.md`，兼容宿主已支持的 `.markdown/.mdown/.mkd/.mdx`，大小写不敏感）。用户输入 trim 后为空时恢复该默认值；没有可用名称时用「未命名文档」。不从 H1 猜标题，不把目录名当分享标题。

标题保存在已有 `ProjectIdentity` 的可选 `shareTitle` 字段；新发布时捕获输入，成功后作为下次默认值。尚未发布时关闭对话框无需另建标题草稿存储。已有项目无该字段时按入口生成默认值。修改标题后通过现有「更新分享」发布到原 URL，不创建新项目。

发布前把本次标题同时冻结到 HTML payload 与 pending 元数据（`pending.shareTitle`）。发布待确认期间显示冻结标题并禁止改成本次重试输入；重试仍发送原包。标题变化不改 Markdown/hash，也不影响反馈身份。

当前 Worker 直接返回 HTML，没有额外 iframe。这里将用户所说 frame 标题落实为页面 `<title>` / `document.title`，浏览器及遵循页面标题的容器均可使用；不增加正文可见标题。初始 HTML 标题为「分享标题 · 只读」，初始化读取 URL fragment 或浏览器缓存的协作 token 后更新为「分享标题 · 可编辑」。切文件或切换编辑/预览不改变分享标题和权限模式。

模式依据当前有效协作 token 是否存在，与协作按钮权限一致；「可编辑」表示可维护自己的草稿并提交审阅，不表示直接改主人原件。沿用当前 token 缓存合同：同浏览器以前打开过协作链接时，普通 URL 也可能拥有可编辑权限；不能只看当前 hash 就标只读。不新增权限角色、模式查询参数或 token 验证接口。初始化恢复完成前禁用写操作；本地存储故障仍可内存编辑/导出，但提交禁用，并提示原因。

所有标题输出采用 HTML/JSON 转义或 `textContent/document.title`，不能形成标签、脚本或属性注入。旧包保持原行为，新的旧项目更新发布后使用上述默认标题。

## 5. 冻结元数据与渲染管线

### 5.1 兼容的数据变化

TS/Rust `ProjectFile` 增加可选 `modifiedAt`，取源文件 mtime 的 Unix 毫秒整数。缺失、无法读取或无效时间视为未知；只影响排序，不阻断已核验内容的发布。Rust 反序列化兼容无该字段的旧 manifest，继续使用 `schemaVersion: 1`。snapshot 的路径、源 Markdown、hash 仍是唯一反馈基线。

读取 mtime 使用与冻结内容同一来源，并保留既有 source/hash/镜像锁与最终一致性核验。不得从新写入的镜像或 snapshot 副本 stat 推断原文件时间。新渲染数据是 bundle 内的派生呈现数据，不写回源文件，也不另存在线正文。

### 5.2 发布流程

1. 保留现有保存、扫描、用户批准范围与源 hash 核验，后端冻结 snapshot 和源修改时间。
2. 宿主按「使用当前主题」选择发布当时的 activeThemeId 或内置 default，并冻结实际编译主题 CSS；加载失败明确报错，不能静默换成另一模板。
3. 对 snapshot Markdown 复用共享正文渲染：GFM、软换行、KaTeX、代码高亮、CriticMarkup/高亮、frontmatter 折叠。只抽取正文与样式所需入口，不复用单篇页头、页脚、beacon 或 PDF A4 外壳。
4. 项目引用解析仅消费已批准 snapshot 路径和资源字节；再复用宿主图表渲染生成静态 SVG，最终清洗并冻结每篇 HTML。不能调用默认任意磁盘 `inlineImages` reader。
5. 组合单份样式、必要字体、资源表、派生正文 HTML、原 Markdown 和现有浏览器协作脚本；完整 UTF-8 HTML 必须不超过 25MiB。
6. 将完整包写入现有 snapshot bundle，持久 pending/凭据后才发 HTTP。失败重试复用原 HTML、主题、标题、时间和期限；已有线上版本不因烘焙失败被替换。

浏览器正常阅读和「发布原文」使用预渲染正文，不重新用裸 Marked 覆盖图表。新发布捕获新主题，pending 重试不受之后的主题设置影响。

## 6. 内容、资源和清洗

### 6.1 正文与图表

已发布正文必须覆盖现有共享链支持的普通 Markdown、表格、任务列表、代码高亮、行内/块公式、Mermaid、DOT/Graphviz、图片与链接。保留 `.moraya-editor` 和冻结 `data-theme` 合同，模板仅影响正文。

采用内联 SVG，保留实际图表所需的 viewBox、defs/marker、路径、文本、受限样式及 Mermaid foreignObject 内安全标签；删除脚本、事件、嵌入活动内容、外部 SVG 资源和危险 URL。图内链接也必须经过项目路径/安全外链解析，不能因 SVG 另开资源读取通道。生成 SVG 的 ID 与引用使用文档/图表命名空间避免冲突。渲染前即限制图表声明的外部图片、链接与资源，不能先让宿主渲染器访问网络/磁盘再依赖最终清洗；图表只消费批准快照资源，未知资源以可见占位或错误处理。

区分原始 HTML 和受控生成结构：原始 Markdown HTML 先受限清洗，不允许冒充生成器的 class/style/id；再保留生成公式、高亮和图表必需的受控结构，并做最终清洗。KaTeX 所需 HTML/MathML、样式和无障碍结构不能整棵删除；不支持但安全的文本节点解包保留文字，活动内容删除。

有效图表必须实测正确。单个语法错误图表保留代码和可见错误，其他正文仍可读；宿主发布结果明确报告该图表错误，不得宣称全部正确渲染，也不能无提示空白或旧图冒充新图。

### 6.2 链接、图片与字体

复用项目现有相对路径/Wikilink/附件下载/未共享占位语义，保留引用范围；标题锚点使用统一算法并处理重名。远程 HTTP(S) 图片和安全外链沿用现有行为；本地资源只能来自批准快照，绝对路径、越界和未分享资源不发布。

资源集中存一份，预渲染 HTML 记录受控资源引用，浏览器挂载正文时绑定对应 data URL；不为同一图片在每篇 HTML 重复塞 base64。不能泄露本机路径，也不能为模板或图表自动读取未批准本地文件。

KaTeX CSS 与必需 woff2 字体从现有依赖内嵌为 data URL，避免相对 `fonts/` 请求失败；CSP 增加 `font-src data:`。当前模板 CSS 的远程 `@import`、`file://`、asset/blob 和未经批准的资源依赖不能原样发布。模板字体家族保留，但本机专有字体/外部 CJK 字体不自动打包或联网下载，访客使用其已有字体及模板 fallback；宿主明确提示存在字体替代。主题字号、间距、颜色、装饰及布局仍复用原样式。已批准的 CSS 图片资源可内联；不能解析的依赖报告具体降级，不静默读磁盘。

维持 nonce 脚本、JSON 转义、`default-src 'none'`、仅 feedback origin 的 connect、`base-uri/form-action 'none'`。不为预渲染引入外部脚本、CDN 图表引擎、浏览器 WASM 或宽泛 eval 权限。检查 CSS/HTML 的嵌入闭合边界。

## 7. 草稿、标注与自动回传

只读隐藏无权使用的协作控件。可编辑时保留精简编辑、标注、提交入口；署名、备份和原文/草稿切换按需展开。源 Markdown textarea、本地草稿、导出完整修改包及主人审阅合并机制保留。

已发布原文/草稿两种视图明确区分：草稿文字继续使用轻量 Markdown 预览和相同正文 CSS；不承诺与宿主完全相同的草稿富渲染。草稿中的 Mermaid/DOT/Graphviz 块显示真实代码和「草稿图表将在主人合入并重新发布后显示」提示，不展示旧基线图。草稿公式保留源表达，不冒充完整数学排版。保存、导出和提交始终使用完整真实 Markdown。用户已选择极简草稿图表范围，无需新增图表浏览器引擎。

保留 IndexedDB 按 `project_id:snapshotId` 隔离、文件 path 草稿、项目 token 缓存、初始化写操作禁用、事务完成后才显示保存成功。草稿与基线不同的时候，标注明确要求先切回发布原文；切回不丢草稿。只接受完全位于当前正文内的选文，维持 `{path,quote,comment}`，不以 DOM 文字长度伪造 Markdown offset。公式/图表内部不承诺精确源位置标注。

现有回传语义不变：点击提交后自动 POST 现有收件接口；不是每次输入自动发送。保留 5MiB 反馈门禁、发送前持久 pending、未知结果同 submissionId/同 body 重试、已送达待主人审阅状态。页面改版不直接修改原件，也不迁移旧 snapshot 的标注。

## 11. 分享文件下载

文件栏底部固定「下载全部」，只读和可编辑均可用。浏览器使用既有 fflate 依赖同步生成 ZIP，不新增依赖、接口或云端存储；ZIP 包含当前已发布快照全部 Markdown 和附件，保留相对目录、UTF-8 文件名和原始字节。它不读取本机原文件夹，不包含未分享文件或访客草稿。ZIP 文件名使用安全化分享标题。

文档行右键显示全局 `.menu-panel` / `.menu-row` 样式的「下载文件」，保存该行对应发布原文，文件名与扩展名不变；右键不切换当前正文。菜单支持 Escape、外部点击和键盘上下文菜单，保持合理焦点。使用 Blob 和浏览器原生下载机制选择保存位置。ZIP 验证嵌套中文路径、Markdown UTF-8、二进制附件、空文档、只读可用及修改草稿后下载仍为已发布原文；共享包继续受25MiB门禁约束。

## 12. 分享主题选择（用户追加）

分享设置增加「使用当前主题」复选项，默认选中。选中时沿用发布当时应用选中的正文主题；取消时使用应用内置默认正文主题，不能硬编码当前用户的Effie。每项目记住选择，旧记录缺字段视为选中；pending发布冻结选择和最终CSS，失败重试不重新读取设置。标题、宽度、图表/公式与反馈合同不变。

## 13. 两阶段发布与保留发布ZIP（用户追加，替代第11节仅客户端打包方案）

### 13.1 最小方案与状态

用户已确认ZIP范围仅本项目勾选批准的全部文档和附件；不扩张到整个物理文件夹。首次发布先冻结入口快照S1，使用本次选择且已冻结的主题编译CSS烘焙入口页，持久原包/凭据后发布，立即显示可复制链接；其余引用显示同步中，下载全部待完整包就绪。随后后台按持久批准paths/hash冻结完整快照S2并烘焙。S1/S2各自保留本地历史，早期反馈仍按S1合入，不伪造同一snapshotId下的不同基线。

同一发布轮次publicationId贯穿两阶段。既有完整分享更新时，入口请求只登记新轮次并保留旧完整页面/ZIP，直到完整包就绪再切换，避免退化为单篇。主题选择和实际compiledCss在轮次开始即冻结，S2不受后来用户主题设置变化影响。源文件变化导致hash校验失败时保留已生效入口/旧完整页面和待处理范围，明确报错。

完整ZIP包含原路径原字节文档/附件，以及内部目录 `.__notemd-{S2}/manifest.json` 与 `reader.html`。清单记录项目ID、快照ID、入口、原文件path/hash/bytes和发布页位置。将已烘焙完整HTML放入同一个压缩发布包，避免再次上传完整HTML；线上不重新渲染Markdown或图表。下载全部直接返回当前完整ZIP，包内保留该内部发布信息，方便保存发布镜像；单文件下载继续从当前页面快照取原字节。

### 13.2 存储、并发与生命周期

沿用已有Worker及MEDIA R2，不加服务、数据库、队列或DO。每slug一个R2 state.json保存轮次、当前指针、绝对到期时间和撤回标记；用R2 ETag条件写实现CAS，不能用最终一致KV的get/put冒充原子切换。版本HTML/ZIP写不可变键；完整包校验通过后最后CAS切换active指针。GET、ZIP下载和feedback均以此状态检查有效期/撤回，不依赖缓存KV旧值。新式项目页面使用no-store，保证完整发布后刷新可见；旧单篇/KV项目保持兼容。

撤回先CAS标记不可访问；晚到的旧轮次完整上传不能复活撤回或覆盖新轮次。撤回成功、旧版本被替换后清理不再使用的HTML/ZIP。ZIP通过校验后、首个对象写入前，先用CAS登记本轮完整快照及其两个对象键；撤回和更新将精确已知旧键持久排入清理队列，失败不掩盖已成功的回执，并由后续请求重试。入口请求结果未知时，宿主撤回还携带已冻结S1身份，服务端将可能已写的入口/旧KV迁移对象精确登记；不能用前缀盲扫删除其他并发请求尚未提交的对象。失败重试保留对象信息和凭据，不能提前遗忘。ZIP在当前分享有效期间保留，过期后入口/下载/反馈均拒绝访问，垃圾清理由现有删除流程触发且允许幂等重试；不承诺到期时刻精确物理删除，不增加定时服务。

### 13.3 接口、重试与边界

新增owner鉴权 `POST /project/{slug}/entry`，JSON含publicationId、previousPublicationId、snapshotId、project_id、edit_token、feedback_token_hash、html、entry、title、expires_in_seconds；返回slug/url/expires_at/snapshotId/stage。`POST /project/{slug}/archive`上传ZIP，headers包含X-Edit-Token、X-Publication-Id、X-Snapshot-Id；`GET /project/{slug}/download`返回attachment ZIP，完整包未就绪明确报告。previousPublicationId为客户端已确认的前一轮次，首次为null，服务端CAS核对后推进，防止迟到旧入口重新占用分享。原DELETE /{slug}识别新状态并撤回；包含本次及前一轮次身份；entry阶段另带entrySnapshotId（S1）和可选legacySnapshotId（本机旧基线辅助），服务端也从旧KV用相同解析器取得真实旧快照ID、无法解析时使用legacy。首请求结果未知时也能建立撤回墓碑，回执返回实际已撤回轮次供下次发布使用。

pending分entry/full-preparing/full。每个网络阶段前都持久凭据和原包信息。full阶段由不可变snapshot-get和bundle-get以固定1980时间戳、条目顺序、压缩级别确定性重建相同ZIP，无新增Rust大包命令或share_db base64。未知结果同轮次同字节重试；重复请求不降级、不刷新TTL。同轮完整异包拒绝。旧pending无新字段继续既有/publish原包链路。

门禁保持HTML25MiB、源快照25MiB；ZIP输入32MiB、实际解压总量50MiB加manifest256KiB、最多512个源文件、路径1024UTF-8字节。有界流式解压验证实际输出，不信任ZIP声明大小；禁止路径越界、重复路径、未知条目、错误清单/入口/快照、活动HTML之外未经批准资源。压缩/解包失败保持现有active，只有完成后才报告完整分享。

验证必须证明：入口先于完整烘焙/上传可读、已有ready更新不降级、同轮重试不延长期限/不改字节、两个基线反馈可审阅、完整ZIP与原文件逐字节一致、撤回/新轮次与迟到full竞态不复活、过期和ZIP下载权限一致、旧KV/pending兼容、主题跨两阶段冻结。

# Agency 0.2.0：从维度计数到协作复盘

用户要判断与 AI 协作是否有用，并找到下一次能改变的做法。主视图改为具体目标进展、明确协作负担、可证能力扩展；效能/乐观/想象降为片段详情中的辅助说明。

## 产品与证据契约

- **目标进展**：说明目标和最后可见的进展，保留已确认、AI 自述、未收尾、停止、未知的区别。不用助手称完成计算成功率。
- **协作负担**：只记录明确误解、重复解释、返工、越界或缺交付，引用用户反馈。探索、合理澄清或主动改需求不自动算负担；不猜测耗时和情绪。
- **能力扩展**：需要用户明确的前后变化自述，或可复用技能/流程/产物的请求和结果证据。产物创建不等于用户学会，AI 自述创建不等于独立验证。普通委托和单次任务不推断扩展。
- **小尝试**：每批至多一条，必须包含具体行动、观察标准及触发它的用户证据。可为空；不创建待办、不保证因果收益。

主卡列出具体发现和对应目标，可选中详情核对编号原话。没有证据显示未知。人工排除同时作用于三个主卡与建议。没有可用样本时不展示零分、虚构成果或心理评价。

## 实现与兼容

保持数据 schema `notemd.agency/v1`，新增 `rule_version=2` 区分业务规则。旧批次缺字段按规则 1 读取；新批次的每个片段带 practical 对象，其 progress/friction/expansion/experiment 可以为空。非空发现必须绑定有效原话索引；负担、扩展和建议至少含用户证据。完整 JSON 经原生校验后发布。

复用要求来源、provider 和规则版本一致；旧报告不能复用为新分析。旧批次与人工校正保留。模板只允许从插件内保存的精确官方旧版本迁移，自定义内容不覆盖；先检查全部受管文件，避免遇到自定义时半途迁移。

沿用 `agency-observe-v1` provider 无工具任务入口，调用 JSON 携带完整规则。provider 版本无需为本次业务规则再次变更。新版不启动定时任务；用户生成或本次验收调用真实模型才分析。

## 验收

1. 旧报告读取不损失结果和人工校正，界面明确补充分析需重新生成。
2. 同源 rule1 → rule2 必须重新分析；rule2 同源复用。
3. 无引用/引用越界/把助手当用户的负担与扩展拒绝发布；第二条实验或无证据顶层建议拒绝。
4. 最新来源扫描、跨日警告、慢请求竞态继续生效。
5. 真实会话试跑，抽查具体发现及未知，避免把普通授权奖励为能力扩展。

## 真实样本校准后的补充

单次报告、JSON、账本和候选文件不因能够保存或复查就等同复用能力。要求明确沉淀为可再次使用的方法/技能/模板，或有跨任务再次使用证据；如果解释本身承认证据不足，应为空。片段混合已验收和新增未完成要求时，不能整卡标用户验收。

原话校验失败最多自动修正一次：把原候选与精确片段/引用序号/行号作为待检查数据，交回同一无工具provider；最终仍逐条验证。来源漂移、存储和其他错误不走修正，不放宽逐字匹配。

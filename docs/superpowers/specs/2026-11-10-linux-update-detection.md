# Linux 宿主版本检查修复

## 已证实的问题

本机notemd 6.1109.4-1为本地安装的foreign package，Omarchy官方包库和AUR都没有notemd更新条目。Linux package-manager渠道在updater状态机入口直接返回，启动和手动检查都未请求版本信息；菜单仍打开更新弹窗，其兜底分支将idle误报为“已是最新”。设置页仅提示omarchy update，也不能升级此本地包。

## 行为与边界

- 包管理渠道恢复启动检查、手动检查、可保存的开关、关闭指定版本提示、新版本通知及更新详情。
- 根据原生宿主triple查询GitHub公开稳定releases，选择实际存在、版本与tag一致、同架构的Linux安装包。不能使用Mac-only的/latest或缺少Linux的latest.json；忽略草稿、预发布、其他架构和仅插件/addon资产。
- 确认存在更新后提供该具体版本的官方release下载页，用户选择发行版包并交由系统包管理器安装。此次修复不实现无提示安装、不用Tauri updater替换包管理的可执行文件，不请求sudo或自动重启。
- Linux缓存按原生triple隔离，避免旧direct/Mac缓存或另一架构导致误报。只有成功且仍有效的缓存可报告检查结果；失败不能在下次启动被20小时TTL当作“已是最新”。手动检查始终请求新数据。
- 仅显式uptodate状态显示“已是最新”；未知/尚未检查/错误要如实显示。检查无更新时清除旧可用版本、下载目标和说明。
- 保留Mac/Windows原有签名安装路径；不向latest.json添加Linux自替换目标。

## 验证与交付

1. 红绿测试覆盖菜单idle误报、Linux启动/手动检测、独立缓存/偏好、网络错误、匹配架构/真实资产/分页、下载页打开且不触发安装IPC；保留direct回归。
2. 对实际公开6.1110.2元数据验证6.1109.4→6.1110.2，ARM保持自己的旧稳定版本；组件和隔离真实UI验证。
3. 精确提交，构建并发布新的宿主修复版本（不改已发布6.1110.2字节或tag；Sumi0.1.11无需重发）。旧版客户端检查逻辑无法由服务器修复，首次升级须通过已验证的安装包引导；不能声称已修好仍在运行的旧二进制。

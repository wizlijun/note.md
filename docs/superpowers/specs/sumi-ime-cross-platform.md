# Sumi 打字机输入法体验规范（跨平台）

- 文档版本：1.0
- 日期：2026-11-10
- 适用对象：note.md 的 Sumi 打字机，以及在其他平台复现相同体验的编辑器。
- 状态：用户需求整理；本规范规定目标行为，不代表所有平台已经实现。
- 优先级：本文以用户最后确认的要求为准。**非聚焦模式保持正文输入行原位，仅候选区固定底部。** 此条替代早期“正文输入行也固定底部、候选展开将正文上推”的要求。

## 1. 目标与范围

让输入法候选看起来像正文的一部分：沿用正文排版、没有独立窗口装饰、尽量不吸引额外注意力。输入、选词、连续书写与保存保持可靠。

定制仅在 Sumi 正文编辑器拥有输入焦点时生效。其他应用，以及 Sumi 的搜索框、设置输入框等，继续使用各自正常的输入法界面。不能为了正文体验强制修改整个操作系统的候选主题。

本规范不限定 Fcitx、GTK、D-Bus 或任何单一平台框架。实现者负责验证目标平台是否能够获取候选、选择候选、控制预编辑样式，以及按输入上下文抑制系统候选窗。

## 2. 术语与坐标

| 术语 | 定义 |
| --- | --- |
| 聚焦模式 | Sumi 的专注书写模式；与操作系统的键盘焦点不是同一概念。本文“专注模式”与“聚焦模式”同义。 |
| 非聚焦模式 | Sumi 的普通编辑模式，用户在自己选定的光标位置输入。 |
| 当前输入显示行 | 光标所在的视觉行，包括自动换行后的行；不等同于整个段落。 |
| 预编辑／组字串 | 输入法尚未正式提交的文字，例如选词中的拼音。 |
| 候选区 | 临时展示候选项的界面，不属于文档正文。 |
| 正文视区 | 宿主实际分配给正文编辑的可见区域，扣除工具栏和必要安全留白。 |
| 底部 | 正文视区的底边；独立全屏窗口中对应可用书写区域底部，不是整个桌面或其他窗口的底边。 |
| 行距 | 正文实际渲染的相邻显示行基线距离，包含字体度量和附加行距。 |

所有定位使用一致的逻辑坐标，并正确转换为平台的实际显示像素。窗口缩放、系统缩放和全屏切换不能重复叠乘字号或偏移。

## 3. 共同视觉要求

### 3.1 与正文一致

- 候选继承当前正文实际使用的字体及回退字体、字号、字重、文字颜色、行高和行间距。
- 候选按横向排列，空间不足时向下一显示行换行；第一项对齐正文可输入区域的左边界，不跟随拼音串的横坐标。
- 候选区覆盖正文可用排版宽度；不得另设窄小的浮动卡片，也不必拉伸候选文字填满宽度。
- 不显示独立背景色块、边框、阴影、圆角容器、气泡或箭头。视觉底色与正文完全一致。
- 当前候选使用细下划线标记即可。不要使用蓝色填充、强对比选中块、闪烁或额外放大。
- 如保留数字选词提示，使用普通文字，弱化到不干扰阅读的程度；提示必须与真实选词快捷键一致。

### 3.2 预编辑文字

- 正文中的组字串不显示蓝色选中背景或其他实心高亮底色，最多保留细下划线。
- 组字串沿用正文排版，不出现第二套字体或独立输入框。
- 仅调整输入法预编辑的展示；普通正文选区仍保留必要的选择反馈。

### 3.3 不使用 emoji 图标

- 候选界面、状态提示和翻页操作不使用 emoji 图标；使用简洁文字或必要的普通符号。
- 关闭输入法自动推荐或插入的 emoji 候选、表情快捷短语，避免其彩色字形干扰版面。
- 普通中文、标点和文字候选继续正常使用。
- 此要求不删除、替换或损坏文档中用户主动输入或粘贴的 emoji；也不把已有文档内容当作界面图标过滤。
- 优先在目标输入上下文或应用范围内关闭自动表情；若平台只支持全局设置，必须明确说明影响范围，不能把全局修改伪装为应用局部行为。

## 4. 两种模式的布局

| 项目 | 聚焦模式 | 非聚焦模式 |
| --- | --- | --- |
| 正文输入位置 | 沿用编辑器已有的专注定位规则；定位完成后稳定 | 保持用户光标与输入行的位置 |
| 候选起始位置 | 当前输入显示行的完整下一行 | 正文视区最底部的一行 |
| 多行展开 | 从下一行向下展开 | 底边固定，新增行向上展开 |
| 最大高度 | 最多四个候选显示行 | 最多四个候选显示行 |
| 正文布局影响 | 通过展示层留白避免与正文重叠，不修改文档 | 候选不得改变正文布局、视区高度或滚动位置 |

### 4.1 聚焦模式

1. 开始组字且有候选时，在当前输入显示行下一行展示候选，第一项从正文左边界开始。
2. 候选最多占四行；不得为了显示更多候选扩大整个窗口或连续推动整个页面。
3. 候选所占区域应成为临时的展示留白，不能与原正文字符叠画。留白仅用于呈现，不向文档插入空格、换行或占位字符。
4. 当前输入行的居中或其他专注定位沿用宿主已有行为；候选布局不得引入重复居中、来回滚动或窗口大小反馈循环。
5. 空间不足时，优先减少同时展示的候选行并允许翻页；不得越出正文视区或突破四行限制。正常编辑所需的光标可见性由编辑器统一处理。

### 4.2 非聚焦模式——最终要求

1. 用户在点击、方向键或其他正常编辑操作选定的位置继续输入；不能把输入行移动到底部。
2. 单行候选固定在正文视区底部，多行候选从底部向上展开，最多四行。
3. 候选出现、消失、翻页、选中项变化和行数变化时，不得：
   - 移动正文光标或改变选区；
   - 改变正文滚动偏移；
   - 修改正文上下边距或压缩正文视区；
   - 把正文整体上推或重新锚定到底部。
4. 候选使用不参与正文排版的展示层。与底部正文发生覆盖时，候选应清晰可读；底层插入光标不得穿透候选绘制，也不得通过移动真实输入位置来解决覆盖。
5. 正常输入换行、光标越出视区、用户主动滚动等导致的自然滚动仍由编辑器处理。“保持位置”约束候选带来的额外移动，不禁止正常编辑滚动。

### 4.3 窄窗口与较长候选

- 四行是上限，不要求每次必须显示四行。
- 使用真实字体度量决定换行，不用固定字符数估算宽度。
- 候选超出当前可显示容量时，提供分页或等效的候选导航；所有候选仍可到达。
- 超长单项可按字形边界省略展示，但选中后提交完整原词；不能截断代理对、组合字符或其他完整字形。
- 展示顺序、数字提示和选中项必须对应输入法真实候选。视觉换行、省略或表情处理不能造成索引错位。

## 5. 输入行为与数据完整性

- 输入法继续负责组字、选词和提交，编辑器继续负责正文、选区、撤销与保存。候选展示层不另造一套输入法状态。
- 保留平台正常的键盘选词、翻页、确认和取消行为；支持点击候选选词。点击候选不能把插入位置移到被覆盖的正文。
- 一次选词只提交一次完整文本。例如输入拼音 `nihao` 并选择“你好”，正文得到“你好”，不能混入原始拼音、重复提交或遗漏字符。
- 候选列表、候选编号、临时留白和界面标记不得进入正文、持久化数据或撤销历史。
- 富文本或 Markdown 投影变化不得打断尚未完成的组字，不得在提交回调中触发重入，导致拼音再次写入正文。
- 保存失败时保留正确草稿与可恢复状态，不得因为禁用编辑、切换焦点或重置输入上下文而追加原始拼音。
- 不对用户实际正文做 emoji 过滤或候选展示用的截断处理。

## 6. 稳定性、滚动和全屏

- 固定文档、光标、字号和视区时，重复定位必须得到稳定的正文像素位置，不允许在相邻像素间来回跳动。
- 正确处理浮点滚动值与平台整数像素坐标。恢复坐标时应匹配平台实际的取整规则，不能仅扩大容差掩盖振荡。
- 动画进行期间可以更新目标，但不能因每帧布局回调反复重置动画起点和时长；动画结束后必须稳定。
- 覆盖长文、奇偶行高与窗口高度、小数字号、多种显示缩放以及全屏进入／退出。
- Sumi 正文不显示破坏连续背景的滚动条、轨道、边框或阴影；正常滚动、阅读和导航能力仍保留。
- 该要求针对正文容器，不要求移除普通窗口标题栏、窗口管理装饰或其他应用的滚动条。
- 光标呼吸或闪烁只更新必要区域，避免持续重绘整个页面或窗口。具体性能预算由目标平台制定并实测记录。

## 7. 输入上下文与故障回退

- 只接管当前正文的精确输入上下文，不按进程名或应用名笼统接管所有输入框。
- 内嵌候选可用时，不同时显示另一套系统候选窗；预编辑样式调整也限定在该上下文。
- 正文失焦、隐藏、切换文档、关闭窗口或销毁后，清除旧候选并撤销接管；不得把旧候选显示到新文档。
- 候选选择和翻页应校验所属上下文及数据版本，拒绝过期操作。
- 输入法进程重启、连接断开或平台桥接不可用时，恢复正常系统候选能力，不能让用户无法选词。
- 重新连接后只恢复仍然有效且获得焦点的正文上下文，不复用过期候选。
- 平台缺少接管能力时，保留原生输入法并说明未满足的体验条目；不能仅隐藏系统候选窗来冒充实现完成。

## 8. 跨平台实现边界

跨平台统一的是本规范中的行为、视觉与验收结果。原生文本组件、候选获取机制、绘制方式、进程通信和打包方式可以不同。

推荐按职责划分：

1. 平台输入法适配：识别输入上下文，获取候选、当前选中项与分页状态，执行选词／翻页，并处理接管与回退。
2. 编辑器适配：提供当前显示行、正文可用范围、实际排版度量及模式；继续拥有正文与保存事务。
3. 候选呈现：根据模式布局、绘制、命中测试与可访问的文字标识，仅保存临时展示状态。

不要求复制 Linux 的 D-Bus 协议，也不要求 fork 每个平台的输入法。先验证公开或现有原生接口能否满足需求；若需要输入法扩展、修改或额外安装包，应把它列为正式交付依赖。

词典迁移与候选界面属于独立事项：若要复用原个人词典，应确认目标平台的词典格式、导入方式与去重规则。不能把某个平台的二进制词典直接当作通用文件，也不能用“已导入词典”证明候选界面已生效。

## 9. 验收清单

测试应使用隔离文档；除了布局测试，必须有真实输入法和实际原生组件验收。

| 场景 | 必须满足的结果 |
| --- | --- |
| 聚焦：输入 `nihao` | 候选位于当前显示行下一行，左对齐、满可用排版宽度；组字无蓝底 |
| 聚焦：一至四行候选 | 向下展开，无正文叠画，无文档占位字符，不超过四行 |
| 非聚焦：在长文中部输入 | 光标行保持原位，仅候选出现在底部 |
| 非聚焦：0→1→4→0 行、翻页 | 相同编辑状态下正文滚动、视区高度和选区不因候选变化而改变 |
| 点击和键盘选词 | 选择同一真实候选；恰好提交一次完整文字 |
| 当前候选与预编辑 | 细下划线或同等克制的标记，无蓝色填充和抢眼动画 |
| emoji | 无自动表情候选或 emoji 界面图标；已有正文 emoji 不被改写 |
| 窄视区／超长候选 | 不越界、不超过四行；截断仅影响展示，分页仍可到达完整候选 |
| 长文静止与连续输入 | 相同布局反复定位无 1px 往返，正常编辑换行仍有效 |
| 小数字号／奇偶高度／缩放 | 记录滚动值、正文像素位置和实际分配尺寸；静止阶段无漂移 |
| 全屏往返 | 候选排版跟随实际字号与视区，无尺寸反馈循环、滚动条边框或额外背景块 |
| 普通滚动阅读 | 不显示正文滚动条，但滚动和键盘导航仍可用 |
| 失焦／其他输入框／其他应用 | 清除 Sumi 候选，其他输入上下文恢复正常界面 |
| 断连／输入法重启 | 无陈旧候选、无误选；正常系统选词可用，恢复后只接管有效上下文 |
| 富文本更新／保存失败 | 不丢字、不重复、不追加原始拼音；草稿保持正确 |
| 保存、关闭、重新打开 | 内容精确一致，无候选、编号或临时留白污染 |

稳定性不能仅用“距离中心误差小于几像素”作为通过条件。应在布局稳定后连续采样，验证同一场景的正文位置严格一致，并分别检查动画中和动画结束后的行为。

交付记录须注明平台、输入法、宿主与插件版本、附加模块、显示缩放、实测场景和已知限制。源码测试通过、模块已安装、模块实际加载、正式安装包验收是不同证据，必须分别说明。

## 10. 给其他平台实现者的摘要

> 在 Sumi 正文内实现与正文融为一体的输入法候选：继承实际字体、字号、颜色与行距，无独立背景、边框、阴影或 emoji 图标；组字去蓝底，当前候选用细下划线。聚焦时候选紧接输入显示行下一行向下展开；非聚焦时保持用户正文输入位置不动，仅候选固定底部并向上展开。两种模式最多四行、从正文左边界横排，超出可翻页。保证真实选词与保存正确、其他输入上下文不受影响、断连能回退。正文无可见滚动条边框但可正常滚动，全屏与长文输入不能抖动。

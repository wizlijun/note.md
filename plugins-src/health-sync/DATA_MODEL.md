# Health Sync 原始资料库结构

原始资料库由用户首次选择，位于 Vault 之外。当前设计只接受本版 SQLite 格式，不包含旧目录、旧 manifest、旧单账号或旧游标的兼容与迁移。Vault 只供后续 skills 保存最终分析报告，本插件默认展示当前数据情况。

## 文件与关系表

```text
<health-library>/
  .notemd-health-library
  health.sqlite
  write.lock
  attachments/<日期或_undated>/<内容摘要文件>
```

`health.sqlite` 是持久事实源，不是缓存。SQLite 的 `application_id` 标识本应用，`user_version` 标识数据库结构版本；每条原始记录另含 `schema_version`。不支持的结构明确拒绝，不猜测或静默升级。SQLite 自己的事务恢复是当前数据库的一致性保证，不是旧格式迁移。

| 表 | 内容 |
| --- | --- |
| `records` | 原始记录：`id, day, source, metric, category, account_id, payload` |
| `sources` | 来源级导入指纹与导出时间 |
| `accounts` | 按来源隔离的账号标识、名称及区域 |
| `coverage` | 来源、账号、集合、日期的采集状态、记录数与错误 |
| `attachments` | 文件路径、来源、账号、集合与 SHA-256 |
| `days` | 每日记录数与内容摘要 |
| `shards` | 日期、来源、指标、分类的逻辑分组统计；不对应分片文件 |
| `metadata` | 小型资料库元信息，不嵌入每日正文或完整记录索引 |

日期、来源、指标、分类、账号有检索索引。`records.id` 仅是数据库内部编号，不是跨次导入身份；原始对象身份与字段保留在记录中。凭据仍在 macOS 钥匙串，不进入 SQLite 或 Vault。资料库绑定及 API 游标在本机应用状态中，游标使用资料库身份和账号隔离。

## 公共记录与来源内容

公共记录包含 `schema_version, ingest_source, kind, day, metric, attributes, children, text`，可含 `text_segments` 和 `payload`。SQLite 的 `records.payload` 保存这条完整记录的 JSON，内部的 `payload` 字段保存厂商原始对象。

- Apple：一个 XML 顶层记录对应一行。原始属性存于 `attributes`，嵌套节点存于 `children`，混合文本顺序由 `text_segments` 保留。原始数值、单位、时间偏移、设备及来源应用不被聚合或覆盖。ECG、路线、CDA 等附件另存文件并登记摘要。
- Garmin：一个导出或 API 对象对应一行；账号、对象 ID、来源保存在公共属性中，原始对象完整保留。离线集合使用 `garmin.export_*`，API 集合使用各自指标名，避免彼此替换。对象中的心率等嵌套序列当前仍保留在 JSON 中，没有提前展开成每采样点一行。
- Oura：采用同样的账号和集合结构；离线集合使用 `oura.export_*`。CSV 保留原始字段字符串，JSON 保留嵌套值及未知字段。输入原件另存附件。实际导出包仍待用户提供验证。

归属日采用来源数据本身的日期，不随导入机器时区重算；无法可靠确定日期时为 `_undated`。日期不是数据全天完整的承诺。原始不同来源之间不做健康含义等价判断，不将步数等重复数据直接相加。

## 增量与一致性

Apple 重叠导出按完整记录的最大重复重数合并：原来有两条、新文件有一条相同记录，仍保留两条；缺席的历史记录继续保留。它只通过显式文件导入更新。

Garmin/Oura 按来源、账号、集合和原始对象 ID 识别记录；无稳定 ID 时按完整内容识别。离线分卷累积且保留缺席记录；API 仅替换完整成功的集合及请求日期窗口。覆盖 `observed` 只说明导出中观察到记录，不推进 API 游标，也不代表完整日期。

记录与统计、账号、覆盖、附件索引在同一 SQLite 事务内提交。附件以内容摘要持久化并验证原字节；未完成事务不会覆盖成功记录。数据库或身份标记缺失时停止，禁止静默重建空库。备份须在停止写入后包含完整资料库及附件。

## 扩展约束

1. 新来源和指标复用公共关系表，通过来源适配器接入，不为每个厂商复制一套数据库。
2. 原始对象未知字段必须保留；新增字段不要求立即修改表结构。字段缺失、null 和数值精度不能被随意归一化。
3. 账号、附件、覆盖与事实记录独立组织，新增记录类型不改变已有账号或文件归属。
4. 后续逐点时序、统一单位、聚合统计等如果有明确需求，可以增加从原始记录重建的派生表；派生数据不能替代原始记录，也不能反向改写厂商事实。
5. Agent 优先使用 `health-status`、`health-catalog`、`health-query` 的 JSON 接口检索。日/月/年分析报告另由后续 skills 生成，原始数据结构不嵌入报告正文。

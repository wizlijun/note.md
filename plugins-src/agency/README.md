# Agency 0.3.0

从已归档的 AI 互动中复盘：目标推进了什么、哪里发生返工、有没有形成新的能力或可复用方法。每项发现都保留原话依据；效能、乐观、想象作为片段详情中的辅助解释，不再作为主界面计数指标。

## 使用

1. 插件 → 回顾 → **打开 Agency…**。
2. 选择最近七天或日期输入框中的任意日期，自动扫描会话，查看纳入来源、覆盖范围、跨日提醒和排除原因。日期上的“未生成”表示尚无分析结果，不表示没有会话数据。
3. 选择已安装且可用的 Agent，生成单日观测，或切换“日期范围”批量生成（含首尾，最多31天，默认截至昨天的最近7天）。队列逐日处理，程序验证源文件哈希、引文、角色、覆盖及结果格式后才发布。
   队列显示逐日成功、复用、跳过或失败，点击日期查看结果。“完成当前后停止”保留当前分析，取消尚未开始的日期。普通单日失败继续处理，Agent失联或超时会停止后续任务。
4. 查看目标进展、协作负担和能力扩展，点击具体发现查看片段与编号引文；原文按钮会打开已验证的源文件，界面显示行号（宿主当前不提供精确行跳转）。
5. 不认同的片段可以排除并记录原因；排除后的片段不出现在三个主栏及小尝试中。来源、Agent 与规则版本相同时重新生成复用现有结果，保留校正。
6. 旧报告仍可查看目标状态和原话；点击重新生成才升级为新版复盘。旧批次和校正保留，不把旧结论直接包装成新发现。

本机本次更新已通过插件管理重新加载，无需重启整个应用；以后手工安装更新时，请等生成任务结束后重新加载插件。生成需要 Codex Agent 1.0.20、Claude Agent 1.0.33 或 DeepSeek Agent 1.1.19 及以上，并通过运行时能力检查。

## 判断边界

- 读取当前 Vault 的 `agent-sessions` Markdown，无需改动导出器；不修改源记录、既有 cron、USER/MEMORY 或待办。
- 日期按会话头部 Started/Ended 与目标日相交筛选；历史头部无时区或逐日消息时间，跨日会话不意味着全部行为都发生在目标日。
- 自动审批、已知自动任务、疑似派生会话、冲突文件和含疑似凭据的来源会排除。历史身份无法绝对确定，模型仍须核对，用户可进一步排除。
- 有输入预算和单来源限制，超限来源明确报告，不静默截断。本版不承诺分析了所有 AI 互动，也不显示不可靠的成功率、投入时间或 Agency 总分。
- “助手称完成”“用户明确验收”分别展示。工具导出中的 `ok` 不升级为独立验证。
- 能力扩展需要用户前后变化自述，或创建可复用技能/流程/产物的明确证据；普通委托和完成单次任务不直接算扩展。AI 报告创建产物不等于已证明用户学会。
- 单次报告、JSON、候选清单或账本不因可保存就算扩展；复用能力需明确沉淀要求或后续再次使用证据。同片段部分验收不能覆盖尚未完成的新要求。
- 未提取到负担或扩展表示证据不足，不代表不存在负担或没有提升。
- 每批最多一项有证据的可选小尝试，包含行动和下次可观察的检验标准，可以没有建议；不自动转成任务。
- 原生后端负责本地校验与保存；语义分析使用用户选择的 Agent provider 的 input-only 无工具隔离路径。只有明确声明支持 `agency-observe-v1`、完整结果及输入隔离的版本才能生成；旧版提示更新，不能退回普通 Agent 模式。
- 插件窗口和 CLI 共用逐日队列；CLI 启动独立后台进程，可供现有调度器调用。任务回执保留逐日进度，重跑范围自动复用已完成的有效结果。本版不自动新增 cron，不支持跨设备同时分析；单台主机生成，其他设备可浏览。
- 批量处理不会把跨日会话拆分为逐日消息，也不把多天片段数相加解释为独立互动数量。

## 数据

所有新增运行数据放在 Vault `.notemd/agency/`：

- `batches/` 保存观测批次与来源快照。
- `state.json` 是有效日期到批次的唯一提交指针；批次写入后再原子切换。
- `reviews/` 保存绑定批次的人工排除与备注，模型不能写人工审核状态。
- `job.json` 是最近运行回执（含范围和逐日结果），`run.lock` 在本机对整个队列防重入，`job.lock` 串行化进度和停止请求。

模板按需安装到 `.notemd/agent-tasks/agency-observe-v1/`。官方旧模板可精确匹配迁移；未知自定义内容保留并提示，不覆盖。模型返回完整终结 JSON，原生端校验并保存；引文或角色不匹配时最多自动修正一次，修正结果仍完整校验；其他错误不自动重试。失败保留上一个有效批次。改变源内容、Agent 或分析规则后产生新批次，旧批次及其校正仍保存，不把旧校正盲目套到新引文。

## 开发与核查

```sh
pnpm --filter agency-plugin test
pnpm --filter agency-plugin check
pnpm --filter agency-plugin build
cargo test --manifest-path plugins-src/agency/backend/Cargo.toml
scripts/dev-install-plugin.sh agency
```

CLI 后台分析（当前配置的 Vault）：

```sh
# 单日；默认使用 Codex
notemd agency run --date 2026-09-22

# 日期范围，含首尾，最多31天
notemd agency run --from 2026-09-17 --to 2026-09-22 --agent codex

# 查看最近队列的逐日进度；请求当前日期完成后停止
notemd agency status
notemd agency stop
```

`--agent` 支持 `codex`、`claude`、`deepseek`，必须已安装、启用且完成登录；不自动切换到其他 Agent。`run` 成功返回只表示后台队列已持有锁并保存任务，最终结果以 `status` 的 `state` 和 `items` 为准。总状态 `done` 表示全部日期已处理（可能包含无来源跳过），`partial` 表示部分失败，`failed` 表示没有成功日期且发生失败，`cancelled` 表示请求停止；单日是否生成看条目状态。命令退出或关闭窗口后 CLI 队列继续，重启系统不自动恢复，重新执行同一范围会复用有效结果。`status` 无任务时返回 null。

CLI 只保留最近队列回执，历史日期结果通过 `snapshot` 查看；已有任务运行时再次启动会报错，不会重置正在进行的队列。调度器应先查询 `status`，不要把 `run` 的退出码当作全部分析成功。

扫描和读取结果：

```sh
notemd agency scan --date 2026-09-22
notemd agency snapshot --date 2026-09-22
notemd agency status
```

不启动宿主的原生诊断（输出不含整份会话正文）：

```sh
plugins-src/agency/backend/target/debug/notemd-agency scan /path/to/vault 2026-09-22
```

# Sumi sync service

Private, single-user multi-device service. Deployment and acceptance evidence are recorded separately; uploading code does not certify authentication or end-to-end readiness. The repository's existing Wrangler **3.114.17** is reused; `npm ci` installs only pinned Yjs 13.6.33. Run `npm test` and `npm run check` after installing the existing `worker/` toolchain. `pretest` links its tools without installing another Wrangler. Local runtime compatibility date is pinned to 2024-12-30 because that is the latest date supported by the existing workerd. Tests use real workerd SQLite DO and R2; each test provisions separate random spaces rather than unsupported old-runtime per-test WAL stacking. The test script runs each test file in its own runtime because the pinned workerd cannot register multiple test-file runners together.

## Identity

Secrets: `SIGNING_KEY` (at least 32 random characters) and `PROVISION_KEY` (deployment administrator only). Neither belongs in an application bundle. All production access uses HTTPS/WSS. There is no anonymous page endpoint or public registration.

- `POST /admin/provision`, admin Bearer key, `{}` -> 201 `{spaceId,deviceId,deviceSecret,accessToken,expiresAt}`. Deployment tooling provisions the first device; transfer its credentials through secure local configuration, never Markdown or logs.
- `POST /admin/recover`, admin Bearer key, `{backupKey}` -> a new credential bundle and new space restored from verified R2 manifest. This never overwrites an existing space or revives its credentials; clients explicitly pair with the replacement space.
- `POST /v1/token`, no Bearer header, `{spaceId,deviceId,deviceSecret}` -> `{accessToken,expiresAt}`. Access expires after 900 seconds; `expiresAt` is Unix seconds. Device credential contains a 256-bit random secret and a space-bound HMAC routing proof; only its SHA-256 is stored server-side. Refresh/pair routing proofs are verified before selecting a DO, so arbitrary unauthenticated space IDs do not allocate new storage. Store the secret in host secure credential storage.
- `POST /v1/pair`, access Bearer token, `{}` -> `{spaceId,code,expiresAt}`. Invitation contains a 256-bit random secret and space-bound HMAC, one use, valid for 300 seconds; invitation `expiresAt` is Unix milliseconds.
- `POST /v1/pair/redeem`, no Bearer header, `{spaceId,code}` -> same credential bundle as provision. No management key in the pairing UI.
- `GET /v1/devices` -> `{devices:[{id,revoked}]}`; `DELETE /v1/devices/:id` revokes refresh, access, active sockets, and invitations issued by that device. Any paired device is trusted to manage its own personal space.

The service determines space from signed claims. Caller-controlled identity headers are replaced. Device revocation is checked at every HTTP request and WS message; signed access tokens alone do not bypass it. Authentication attempts and active device/invitation/socket counts are bounded.

## Pages and durable operations

All following requests use access Bearer tokens. IDs are UUIDs; `opId` must be stable across retries and unique for that device. Reusing an operation ID for a different payload is an error. JSON errors have `{error:code}`. State/generation conflicts are HTTP 409 and must retain local drafts, never overwrite them.

- `POST /v1/pages`: `{opId,pageId,localDate:"YYYY-MM-DD"|null,afterId?:UUID|null}` -> 201 `{page}`.
- `GET /v1/pages?cursor=0`: `{changes:[{cursor,page}],cursor,hasMore}`; fetch while `hasMore`. The append-only directory contains tombstones. An offline create's `afterId` must be submitted after that anchor's create. Ordering is anchored to `after_id`, with siblings ordered by page UUID, traversing tombstone anchors without displaying them.
- `GET /v1/pages/:id`: `{page}`.
- `DELETE /v1/pages/:id`: `{opId,generation}` -> `{page}`.
- `POST /v1/pages/:id/restore`: `{opId,generation}` -> `{page}`.
- `POST /v1/pages/:id/update`: `{opId,epoch,generation,update:base64,firstWriteDate?:"YYYY-MM-DD"}` -> `{type:"ack",opId,pageId,epoch,generation,version,localDate,sequence,validationPending}`. The acknowledgement means these exact opaque bytes and their operation identity are durable; unresolved causal dependencies may still require later validation.
- `POST /v1/pages/:id/sync`: `{epoch,stateVector:base64,cursor?:{version,offset},throughVersion?:number,generation?:number,quarantineRevision?:number}` -> `{page,stateVector:"AA==",format:"journal-v1",sha256,chunks:[base64...],cursor,hasMore,throughVersion,quarantineRevision}`. First response freezes a journal version; subsequent requests echo that version, generation, quarantine revision and cursor. Each response contains at most 1,024,000 packed bytes, split into 64 KB chunks. Decode each base64 chunk independently, join and verify that page's SHA-256. Concatenate the verified pages until `hasMore:false`, then decode the length-prefixed journal and merge its Yjs V1 records. A record may span HTTP pages. A generation/quarantine change requires restarting replay. The relay does not publish an authoritative CRDT state vector; the caller calculates its own after durable integration. The submitted vector is validated but version 1 currently replays the complete journal for correctness.

`page` contains `id,epoch,generation,deleted,local_date,sequence,after_id,version`. Initial epoch is 1, generation/version 0. New empty pages have `local_date:null,sequence:null` and no projected dated filename. The first update integrating nonempty text must carry `firstWriteDate`; the DO atomically assigns that date and daily sequence once. Competing first edits use the first server-accepted date; later edits never rename the file. Offline pages already written may supply their recorded first-write date at create. Deletion and explicit restore each increment generation, so pre-delete offline edits cannot silently arrive after restore. Deleted documents remain recoverable. Daily `sequence` allocation includes deleted pages and never reuses a number. Filename: `local_date + "-" + sequence.padStart(2,"0") + ".writing.md"`.

Wire is **Yjs/Yrs binary V1 update and V1 state vector**, UTF-16 body offsets. Roots are `body:Y.Text`, `page:Y.Map` (schema=1/page_id/epoch/root_line_id), `timing:Y.Map` of immutable compact V1 event tuples. The relay persists immutable raw updates in SQLite; it never materializes a complete `Y.Doc`, rewrites Markdown, or joins a whole page's history in memory. Replay encoding is repeated `u32 little-endian byte length` followed by the original update bytes. No record is dropped merely because its dependencies have not arrived. Clients merge the complete replay with Yrs before validating and applying it to a candidate document.

The bounded lazy wire validator indexes actor clocks, parent links, protected map fields and delete ranges. It validates explicit identities and immutable field replacements, including parent information resolved after a dependency arrives. A direct malformed/current operation rolls back. If a later valid dependency proves an earlier pending operation invalid, the relay quarantines that earlier operation, retains the valid dependency and broadcasts `resync_required`; replay excludes quarantined records. Already-connected clients can retain the invalid pending bytes in their CRDT, so they must stop merging that page and preserve local drafts until clean journal reconstruction plus local outbox replay is implemented. They must not attempt to remove pending content by overwriting Markdown. Full body/line/time semantics remain the client's candidate-validation responsibility.

The journal append, validation index, page version, directory allocation and durable idempotency response commit in one SQLite transaction. Output gates hold acknowledgements and broadcasts until durable completion. Operation IDs must remain stable across HTTP/WS fallback and retries.

Limits: 16 MB raw HTTP update, 24 MB JSON request, 256 KB raw WebSocket update, 400 KB WS message, 64 KB chunks, 500,000 structs per raw packet, 64 MB total raw journal per space, 1000 pages, 200000 remembered operations. Client replay allows 65 MB including journal framing. The one-million UTF-16 body limit and full logical validity are enforced by write-core; the relay also rejects any individual string exceeding that size. Limits fail explicitly without truncation. A 100,000-sequential-key real Yrs fixture (13,258,603 bytes) passes the localhost end-to-end HTTP and WS replay acceptance test. This is not a production memory or Internet-latency certification.

The native HTTP client negotiates Brotli/gzip content encoding and enforces response limits on decompressed bytes. Each new WebSocket obtains a fresh access token before its handshake so a long HTTP replay cannot leave it with a nearly expired credential. The native HTTP client budgets a large update's base64 upload at 64 KiB/s plus 25 seconds, capped at 360 seconds, and refreshes access credentials before an upload if they would expire within that budget. Each maximum-sized HTTP journal page receives a 67-second deadline using a 32 KiB/s download allowance; other requests retain a 25-second deadline. A truncated or timed-out read-only journal page is retried at most twice with the identical frozen cursor/version; partial bytes are discarded. Keep the same operation ID and exact payload when retrying a lost response; a timeout never means that the update was not committed. This initial-history allowance does not change the small incremental-edit path or its latency target.

## WebSocket

`GET /v1/ws` upgrade with access Bearer header. Tokens are never put in query strings. Native clients can set the Authorization header. Reconnect with a refreshed token after `4001 token_expired`.

1. Send `{type:"hello",protocol:1}`; receive hello with authorized space/device.
2. Send `{type:"subscribe",pageId,epoch,stateVector}`.
3. Reconnect replay starts with `sync_begin {transferId,page,stateVector:"AA==",format:"journal-v1",chunks:null,quarantineRevision}`. Receive ordered `journal_page {transferId,index,sha256,chunks}` messages (at most 192,000 packed bytes each), then `sync_end {transferId,pages}`. Verify every page's chunks/hash, index and final page count; merge only after completion. Interruption discards the incomplete transfer and restarts replay.
4. Send `{type:"update",pageId,opId,epoch,generation,update,firstWriteDate?}` for updates up to 256 KB. Larger edits use HTTP with identical operation identity. Ordinary live subscribers receive `{type:"update",pageId,epoch,generation,opId,deviceId,update,version}`. A large live increment uses the original non-journal `sync_begin/chunk/end` transfer with full-update SHA-256. Decode and apply the complete increment once. The sender may receive its own idempotent update.
5. `{type:"unsubscribe",pageId}` and `{type:"ping"}` are supported. Errors: `{type:"error",error}`. Lifecycle notifications use `{type:"page",page}`. Directory changes broadcast `{type:"directory",cursor,page}` to authenticated sockets; clients still replay the directory cursor on reconnect. `resync_required {page,reason,quarantineRevision}` explicitly blocks normal merging after quarantine; preserve local drafts.

Hibernation state (authorized claims, hello, subscriptions) is serialized on each socket; journal replay always reads SQLite, not an unpersisted document cache. Directory cursor remains the reconnect source of truth.

## Backup and operational boundaries

`POST /v1/backup` freezes a durable SQLite copy of the journal/directory at one revision, then uploads immutable 1,024,000-byte journal segments to R2 outside the input gate, followed by a schema-2 manifest. Each segment has its own SHA-256; the manifest contains ordered segment identities, record counts and the directory. `last_backup` changes only after every object succeeds. Automatic alarm starts after page creation or content updates, then daily. Failed uploads retain the frozen job and resume identical object keys after restart. Editing continues during R2 network waits. One pending job is allowed; overlap returns `{pending:true}`.

Recovery verifies the manifest, segment names/order/size/hash, record framing, wire identities and directory anchors before provisioning the replacement space. It holds at most one raw update plus a bounded R2 segment, never a full page document. Any mid-restore failure clears the unprovisioned journal and wire indexes; the same staging space can retry. Device secrets are not backed up. Production uses a 30-day R2 lifecycle rule. A deployed recovery drill remains an acceptance gate until its actual report passes.

First-device provisioning, live-network performance, and production recovery must each have explicit acceptance evidence. In particular, a successful code deployment and anonymous health response alone do not prove an operational authenticated service. Replacement-space recovery is covered by local workerd tests, including corrupt-object rejection. `tests/yjs-v1.json` is a Yjs-produced interoperability fixture; `scripts/interop.mjs` checks the Rust-generated fixture in `write-core/tests/fixtures/yrs-v1.json` in reverse/duplicate arrival order and regenerates it. A production deployment must run host/client fixture tests as well as service tests and verify all spec gates.

## Deployment and first connection

Use `python3 scripts/cloud-admin.py MODE` from this repository (the script resolves the root). It reuses the existing Account API Token from root `.env`, the account ID from `worker/wrangler.toml`, and only Wrangler 3.114.17. It never prints secret values. Modes are `preflight`, `prepare`, `bucket`, `deploy`, `secrets`, `retention`, `verify`, and `verify-source`, in that order. `quota` reads aggregate shared-account SQL use before capacity acceptance. `verify-source` downloads the deployed module and compares its SHA-256 with a fresh dry-run bundle. A failed network mutation must be checked by readback before retry. Do not rotate an existing service's owner keys when Keychain retrieval fails.

The Sumi-only owner bundle is generated locally, kept in macOS Keychain `net.notemd.sumi.admin.v1` / `cloudflare:sumi-sync`, and copied only into a mode-0700 temporary directory with mode-0600 files. `secrets` sends only the newly generated Sumi signing/provision keys to this dedicated Worker's secret store. The bootstrap administrator key never enters a host preference, Markdown, sidecar, plugin package, or invitation.

After authenticated deployment passes, `bootstrap` provisions one empty owner space and stores its bootstrap device credentials back in Keychain. Immediately before connecting the host, `invite` writes `owner-invitation.json` into the same private directory, with `baseUrl`, `spaceId`, `code`, and expiry. The invitation is single-use and expires in five minutes. Import it through the host's pairing settings; do not expose the administrator key. A bootstrap device must remain active until its invitation is redeemed because revoking a device also revokes its outstanding invitations. These commands do not send messages to other people.

`cloud-acceptance.mjs` uses a separate test space for actual network checks, a native-generated 100k-character bulk fixture, same-socket hibernation rehydration, two-device concurrent merge, frozen R2 backup/recovery into a fresh space, and device revocation. `--sequential-history` selects the real 100k-sequential-edit / 200k-struct fixture instead. That mode refuses to run without a current `packed-capacity-budget.json` matching every runtime source hash and the fixture hash, plus a fresh aggregate account-quota readback. Its conservative budget must leave at least half the shared Free daily row-write/read allowance. The authenticated diagnostics must confirm a fresh space uses `packed-v1` before capacity traffic begins.

New and still-empty spaces use the packed validator index described in [PACKED-INDEX.md](PACKED-INDEX.md). Existing populated legacy spaces retain their original validator and all durable journal data; the selected schema is frozen in SQLite. Backups store the wire journal rather than either index representation, so recovery into a new packed space rebuilds and validates the index. Bounded UUID buckets reject pathological dense inputs explicitly. Packing reduces initial-history import costs; it does not remove the account's daily quota. Both per-edit and initial-import costs are measured by the local quota regression.

For isolated capacity measurement, start the repository's Wrangler3 with `--local --ip 127.0.0.1 --port 18788`, test-only signing/provision keys and `--var LOCAL_SQL_METRICS:1`, then run `node scripts/packed-capacity-local.mjs`. The optional meter retains only row counts, never query text or values, and is not enabled in production. This script measures full service commit, duplicate, frozen backup and recovery under real workerd, and rejects evidence if runtime source changes during the run. No new Wrangler is installed.

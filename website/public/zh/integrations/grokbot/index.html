note.md + Grokbot

Grokbot 产出报告，你在 note.md 阅读、标记重点，把反馈留在原文旁边，供下一次任务继续使用。

通过文件协作

Grokbot 的官方名称是 Grok Bot，它可以处理 Markdown 文档。把产出保存到 note.md 知识库，报告仍是普通文件，你的批注也能供后续任务读取。

这套协作方式依靠文件访问，无需专用的 note.md 连接器。

设置知识库

  1. 在 Grok Bot 桌面应用中打开 Settings → Computer → Your computer → Execution on this computer，使用 Ask every time，逐次批准任务需要的本机命令。
  2. 告诉 Grokbot 知识库的完整路径，要求它先读根目录的 AGENTS.md，不要假定它会自动发现该文件。note.md 的文件约定可参考 llms-full.txt。
  3. 让它将报告保存为知识库内的 research/topic.md。
  4. 在 note.md 打开报告并添加批注。下一次任务先让 Grokbot 读取配对的 research/topic.note.md，再修订报告。

区分本机访问与云端工作

Grok Bot 的云端计算机与你的 Mac 或 Windows 电脑相互独立。云端 /workspace 下的路径不是本地知识库路径。本机命令执行需要单独授权，也可能受到团队策略限制。

无法访问本机时，可以附上选定的 Markdown 文件，再手动把返回的文档保存到知识库。附件只是文件交接，不会自动同步。详见官方的计算机与应用、本机权限及文件与结果说明。

让它读取你的批注

审阅报告后，可以这样发起下一次任务：

在我的知识库中，读取 AGENTS.md、research/topic.md 和 research/topic.note.md。回应批注里的问题，核查来源，并更新 research/topic.md。保留我的批注不变，简要说明修改了什么。

报告与反馈放在一起，下一次会话或另一个 agent 都能接着处理。

FAQ

需要安装 Grokbot 插件吗？

通过文件协作无需专用的 note.md 插件。Grokbot 需要获得相关本地文件的访问授权，也可以由你通过附件交接选定文件。

Grokbot 会自动遵循知识库规则吗？

请在任务开始时明确要求它读取 AGENTS.md，并审阅修改结果。.note.md 中的批注由你维护；这套流程让 Grokbot 读取批注、修改报告。
